# Правка контента и баланса

Этот скилл рассчитан в том числе на участника, который не пишет код. Задача —
чтобы правка данных была безопасной и её последствия были видны сразу, а не
через неделю по просевшему retention.

**Главное правило: контент — это данные, а не код.** Правится только
`packages/core-game/src/content/*` (или конфигурация в админке, если она уже
подключена — `docs/19-content-admin.md`). Файлы в
`packages/core-game/src/game/*` не трогаем: если нужного поведения нет, это
задача участника 1, а не правка данных.

## Шаг 1. Понять, что именно меняется

| Хочу | Это данные? | Куда |
|---|---|---|
| Новый враг из существующего паттерна поведения | да | `content/enemies.ts` |
| Враг с принципиально новым поведением | **нет** — нужен код | задача участнику 1 |
| Новый отрезок таймлайна спавна, изменение состава и темпа | да | `content/waves.ts` |
| Границы карты, параметры камеры | да | `content/maps.ts` |
| Целевые коридоры баланса | да | `content/balance-targets.ts` |
| Новое оружие на готовом поведении, числа уровней | да | `content/weapons.ts` |
| Оружие с новым способом атаки | **нет** — нужен код | задача участнику 1 |
| Новая пассивка на существующую характеристику, слоты, кривая опыта | да | `content/upgrades.ts` |
| Пассивка на характеристику, которой нет | **нет** — нужен код | задача участнику 1 |
| Цена SKU, награда за рекламу, кулдаун | да | экономика/конфиг |
| Новый уровень из существующих ассетов и паттернов | да | конфиг уровней |
| Уровень, требующий новой механики или новых ассетов | частично | ассеты — к напарнику, механика — к участнику 1 |

Если ответ «нужен код» — остановиться и сформулировать задачу, а не пытаться
обойти ограничение данными.

## Шаг 2. Внести правку

Формат врага:

```ts
// packages/core-game/src/content/enemies.ts
{ id: "new_enemy_id", hp: 10, speed: 60, damage: 4, xp: 2, pattern: "swarm" }
```

`xp` — ценность кристалла опыта за убийство врага.

`pattern` — строго один из уже реализованных в
`packages/core-game/src/game/patterns/`. Список паттернов и их параметров —
таблица в `CLAUDE.md`, «Как добавить нового врага»; придумывать новые
значения нельзя.

Параметры паттерна задаются в `params` и необязательны — незаданное берётся
из умолчаний. Параметр чужого паттерна TypeScript не пропустит. Делящемуся
врагу (`splitter`) обязателен `childEnemy` — существующий враг, который сам не
делится:

```ts
{ id: "slime", hp: 24, speed: 40, damage: 5, pattern: "splitter", params: { childEnemy: "swarm_rat" } }
```

Формат отрезка таймлайна спавна (волн с паузами в игре нет — поток):

```ts
// packages/core-game/src/content/waves.ts
{
  fromSec: 90,
  spawns: [{ enemy: "new_enemy_id", perSec: 0.5, burst: 4 }],
  events: [{ kind: "ring", enemy: "elite_ghoul", count: 1 }],
}
```

`enemy` — существующий `id` из `enemies.ts`, `fromSec` идёт по возрастанию,
`perSec` — врагов в секунду, `burst` — разовый выброс в начале отрезка.
`kind` события: `ring` (кольцом) или `flank` (рой с одной стороны). Дальше
последнего ручного отрезка таймлайн продолжается по `ENDLESS_CURVE` в том же
файле.

Формат оружия и пассивки — таблица в `CLAUDE.md`, «Как добавить оружие или
пассивку». Тексты оружия и пассивок задаются **ключами i18n**
(`nameKey`, `descriptionKey`), а не русскими строками.

Имена файлов фиксированы и не переименовываются.

## Шаг 3. Проверить данные

```bash
pnpm test
```

Тесты контента (`docs/17-testing-strategy.md` §3.1) проверяют:

- каждый `enemy` в волнах существует в `enemies.ts`;
- `pattern` каждого врага реализован в коде;
- параметры паттерна относятся к нему и лежат в границах, `childEnemy`
  существует и не делится;
- нет дублирующихся `id`;
- числа в разумных границах (`hp > 0`, `speed > 0`, урон не отрицательный);
- у каждого отрезка есть спавн или событие, `fromSec` растёт монотонно;
- **бюджет угрозы не убывает** — ни между отрезками, ни на переходе к кривой
  бесконечного режима; сообщение называет отрезок и оба числа;
- элиты не попадают в обычный поток и в пул кривой — только события;
- карта не уже полутора колец спавна, `viewAreaIdle` не больше `viewAreaMoving`.

Если тест упал — читать сообщение целиком, там написано, что именно не
сходится. Это дешёвая проверка на опечатки, она для того и нужна.

Правка кривой сложности или прокачки — ещё и распределение по десяткам seed:

```bash
pnpm balance:sim
```

Таблица ложится в `var/balance/`. В гейт перед PR она не входит и ничего не
утверждает: смотреть в неё стоит тогда, когда крутится баланс, а не на каждом
коммите.

## Шаг 4. Посмотреть, что стало с балансом

Правка данных **ломает golden-тесты — это ожидаемо и правильно**. Golden-тест
прогоняет фиксированные сценарии (пассивный игрок, агрессивный, билд на урон,
билд на выживание) и сравнивает точный результат: достигнутая волна, счёт,
время выживания.

Порядок действий:

1. Посмотреть, **насколько** разошлись числа.
2. Оценить, соответствует ли расхождение замыслу. «Хотел чуть усложнить
   середину, а средний забег стал короче на треть» — повод пересмотреть
   правку, а не обновлять эталон.
3. Обновить эталон в этом же PR.
4. В описании PR написать дельту человеческим языком: «после ускорения
   `swarm` средний забег короче на две волны, время до первой смерти новичка
   осталось в коридоре».

Смысл golden-тестов не в том, чтобы запретить изменения, а в том, чтобы
сделать их последствия видимыми в диффе. Без этого баланс уезжает малыми
шагами и заметить это можно только по метрикам через неделю после релиза.

Дополнительно проверить, что не сломаны свойства баланса
(`docs/17-testing-strategy.md` §3.3): кривая сложности не убывает, пассивный
игрок гарантированно умирает, ни один апгрейд не даёт бесконечного роста
параметра.

## Шаг 5. Цены и экономика — особый случай

- **Экономика по платформам считается раздельно.** Цена в Stars и цена в
  рублях — не конвертация по курсу, а два независимых решения
  (`docs/03-notes-and-risks.md`).
- **Цена — серверная величина.** Клиент её только показывает; при покупке
  сервер сверяет со своим значением. Правка цены «на клиенте» ни на что не
  влияет и не является правкой цены.
- **Никакого рандома в монетизации.** Только прямые покупки фиксированной
  стоимости — лутбоксы и гача исключены сознательно и по регуляторным
  причинам (`docs/03-notes-and-risks.md`, `docs/07-monetization-and-ads.md`).

## Шаг 6. Оформить

Коммит по формату `CLAUDE.md`, например:

```
feat(content): Добавить врага fast_swarm и волну на 90 секунде
```

Дальше — скилл `pre-pr`.

## Если админка уже подключена

После подключения редактора (`docs/19-content-admin.md`) часть правок делается
в нём, а не в файлах — но проверки остаются те же: схема, тесты контента,
прогон golden-сценариев на черновике конфигурации **до** публикации, и
публикация отдельной версией с возможностью отката. Порядок и рамки — в том
документе.
