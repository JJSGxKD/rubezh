# Платформенный адаптер

Адаптер — **тонкий слой между площадкой и игрой**. Всё, что не является
вызовом SDK площадки, находится не здесь.

## Контракт

Единый интерфейс `PlatformAdapter` в `packages/shared-types`:

- `init(): Promise<UserContext>` — контекст пользователя;
- `purchase(itemId): Promise<PurchaseResult>` — покупка средствами площадки;
- `share(payload): void` — шеринг результата забега;
- `haptic(type): void` — вибрация;
- `showAd?(): Promise<AdResult>` — **опционален**: на MAX rewarded-формата
  нет (`docs/01-tech-stack.md` §6), и вызывающий код обязан это пережить.

Менять контракт можно, но это изменение общего интерфейса: правится
`shared-types`, обновляются **все три** адаптера и документация в том же PR
(`docs/06-team-and-workflow.md` §4).

## Границы — жёсткие

- `core-game` **не импортирует** адаптеры и ничего не знает о платформе. Игра
  общается с площадкой только через `PlatformAdapter`.
- Адаптер **не импортирует** другой адаптер. Общее выносится в
  `shared-types` или в отдельный пакет.
- В адаптере **нет игровой логики**. Проверка простая: если появился расчёт
  награды, баланса или прогрессии — он здесь лишний.
- Заглушки `adapter-max` и `adapter-vk` из репозитория не удаляются, даже
  пока работа идёт только по Telegram. Они — то, что не даёт
  Telegram-специфике расползтись.

## Что делает адаптер, а что бэкенд

| Задача | Где |
|---|---|
| Получить `initData` / данные Bridge | адаптер |
| **Проверить подпись** этих данных | **бэкенд**, никогда не клиент |
| Открыть платёжный диалог площадки | адаптер |
| Создать инвойс, определить цену, зачислить покупку | **бэкенд** |
| Показать рекламный блок | адаптер |
| Выдать награду за просмотр | **бэкенд**, по подписанной одноразовой сессии |
| Определить платформу для таргетинга | клиент подсказывает заголовком, **решение принимает сервер** |

Общее правило: всё, что имеет денежный или наградной эффект, решается на
сервере. Клиент — источник заявлений, не фактов.

## Платёжная специфика по площадкам

- **Telegram**: цифровые товары продаются **только за Stars**. TON, Gram и
  USDT их не заменяют — это правило площадки, а не техническое ограничение
  (`docs/08-web-and-identity.md` §6).
- **MAX**: СБП / VK Pay, прямые рубли. Цена считается отдельно, а не
  конвертацией из Stars по курсу.
- **VK**: единственная площадка с нативной rewarded-рекламой из коробки.

## Обязательные тесты

Один контрактный набор прогоняется для **всех трёх** реализаций против
фейкового SDK (`docs/17-testing-strategy.md` §5):

- `init()` возвращает `UserContext` с заполненными обязательными полями;
- SDK недоступен (открыли не из мессенджера) → предсказуемая ошибка, а не
  падение и не белый экран;
- `purchase()` при отмене пользователем → `success: false` с причиной, а не
  исключение;
- `showAd()` отсутствует или вернул `{ shown: false }` — вызывающий код это
  переживает;
- `share()` и `haptic()` не бросают там, где их нет.

Это тот тест, который экономит неделю на портировании: когда `MaxAdapter`
проходит тот же набор, что `TelegramAdapter`, интеграция с игрой заведомо
работает.

## Ручная проверка

Автотесты не заменяют проверку в реальном клиенте. Перед релизом —
чек-лист `docs/17-testing-strategy.md` §8: Android, iOS и Desktop это три
разных WebView; жесты площадки не конфликтуют с управлением; сворачивание и
возврат ставят игру на паузу; реальная покупка на реальном аккаунте.

## Перенос из vpnsibcom

Инициализация TMA SDK и клиент API с молчаливой ре-авторизацией переносятся
из `vpnsibcom_web` — но по процедуре, а не копированием: скилл
`port-from-vpnsibcom`, инвентаризация в `docs/13-reuse-from-vpnsibcom.md` §11.
