## Шаг 2. Материал или плоское

Принцип v2: интерфейс — продолжение мира, но плоское остаётся там, где важна
скорость чтения.

- **Материал мира** (`relic` у `Modal` и `Panel`, `RibbonTitle`,
  `ItemMedallion`, `RarityGlow`, `AmbientSky`) — моменты награды и выбора:
  сундук, уровень, итоги, магазин, арсенал.
- **Плоское** (`cut`, обычные `Panel`, списки) — настройки, списки,
  гайдбук, админка целиком.
- Тон реликвии — по смыслу события, не для красоты: один тон — одно
  значение на весь экран.

## Шаг 3. Правила, которые проверяет ревью

Полный свод — `docs/27` §4. Чаще всего нарушают:

- **Значения — только из токенов.** Цвет, радиус, тень или длительность
  числом в компоненте — дефект. Не хватает значения — добавить токен.
- **Отступы от выреза и кнопок Telegram** — только `--app-inset-*`.
- **Анимируются только `transform` и `opacity`.** «Дыхание» свечения —
  прозрачностью отдельного слоя. Во время забега React перерисовывает
  только HUD, не чаще 10 раз в секунду.
- **«Меньше движения»** — только проявление, бесконечные анимации стоят.
  Новое заметное движение — решение по переключателю в том же PR («Живой
  фон», графика забега; `CLAUDE.md`, «Настройки не отстают»).
- **Контраст** — текст 4,5:1, крупный текст и значки 3:1. Состояние не
  передаётся только цветом.
- **Выключенная главная кнопка — нейтральная**, причина — подписью рядом.
- **Касание** — не меньше 44 px по высоте; меньше 24 px — провал.
  Маленький значок получает прозрачную зону (`hit-tall`).
- **Фокус** — кольцо видно, у пунктов меню и вкладок — внутрь.
- **Имя для диктора** — у каждой кнопки-значка `aria-label` из словаря.
- **Тексты — ключами i18n**, самый длинный текст словаря не ломает раскладку.
- **Больше трёх пунктов переключателя** — строкой вкладок, а не сеткой
  (Р145).
- **Новый значок или крупный компонент**, который первой загрузке не нужен, —
  отдельным модулем. Бюджет первой загрузки меряет `pnpm budget`.

- **У каждого экрана — все состояния** ([`states.md`](states.md) §1):
  загрузка, пусто, ошибка, нет сети, длинный текст, двойное нажатие.
- **Деньги и награды** — цена видна до нажатия, отказ так же заметен, как
  согласие (Р11, [`onboarding-and-ethics.md`](onboarding-and-ethics.md) §5).

## Шаг 4. Проверка

Матрица — `docs/27` §5.4 и `tasks/README.md`, «Приёмка»: **320, 390, 768,
1440, ландшафт 667×375 и 640×360**. Окна забега проверяются в витрине
(`screens/gallery.tsx`, режим диагностики), а не в настоящем забеге.

Замеры — скрипты `design/art/src/`. Им нужны dev-сервер оболочки
(`pnpm dev:telegram`), бэкенд и файл состояния игрока, прошедшего первый
забег (`STATE` — Playwright `storageState`). Playwright в облачной среде —
`/opt/node-tools`, локально — `PLAYWRIGHT_MODULE=…/playwright/index.mjs`.

| Что | Команда | Провал |
|---|---|---|
| Контраст по пикселям, с живым фоном | `STATE=state.json WIDTH=390 node design/art/src/contrast-audit.mjs`; `PREVIEWS=1` — ещё и окна витрины | код выхода 1 |
| Касание, имена для диктора, крупный шрифт 130/150 % | `STATE=state.json node design/art/src/a11y-audit.mjs`; `CHECKS=scale` — одна проверка | код выхода 1 |
| Боковая прокрутка админки на телефоне | `pnpm dev:admin`, затем `ADMIN_URL=http://127.0.0.1:5176 WIDTH=390 node design/art/src/admin-overflow.mjs` | раздел шире окна |

Каждый прогон делается на 320 и 390. Ссылка в тексте с пустым местом вокруг
проходит по исключению WCAG — скрипт её покажет, а решает человек.

**Аудит экрана** — не только замеры: разбор по эвристикам и
когнитивной нагрузке с отчётом по приоритетам P0–P3
([`critique.md`](critique.md)). HUD — по [`hud.md`](hud.md) §7, вердикт
«Не проверено» честнее «прошло», если не хватило входа.

## Шаг 5. Что сдать

- **Снимки до и после** на ширинах матрицы — в описание PR; кадры
  дизайнера — в галерею (`design/art/README.md`, «Кадры и промо — не в
  git»). В git — только макеты и `out/preview/ui-*`, на которые ссылается
  `mockups/ui-fixes.html`.
- **Документы:** строка компонента или экрана в `docs/27` (§4.6, §6), новый
  выключатель — в §7.1; у дизайнера — находка в `registry.md` со статусом.
- **Гейт** — `CLAUDE.md`, «Сборка и проверка перед PR»; вёрстку тесты не
  проверяют, логика раскладки — чистой функцией с тестом
  (`segmented-rules.ts`, `results-look.ts`).
- **Честный статус:** что не проверено (WebView Telegram, устройство,
  вырез), так и написать — как в `design/art/checklists.md`.

Дизайнер сдаёт материалы PR с меткой `release: none`, код экранов делают
задачи исполнителей (`design/art/backlog.md`).
