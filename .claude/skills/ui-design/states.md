# Состояния, отклик и крайние случаи

Справка скилла `ui-design`: что проверить у каждого экрана и окна, кроме
«нормального» вида. Основано на Impeccable (`harden`, `polish`), Web
Interface Guidelines (Vercel) и ux-designer-skill, переложено на React-оболочку
в Telegram. Лицензии — [`../THIRD_PARTY.md`](../THIRD_PARTY.md). Свод правил
проекта — `docs/27-design-system-and-app-shell.md`; при расхождении прав он.

## 1. Перечень состояний

Экран не готов, пока у него нет каждого применимого состояния.

| Состояние | Проверка |
|---|---|
| Обычное | одна доминанта, главное действие в нижней половине |
| Первая загрузка, подгрузка, обновление | скелет повторяет итоговую раскладку, ничего не прыгает |
| Пусто: впервые / игрок очистил / ничего не нашлось / нет доступа / не загрузилось | у каждого свой текст и следующее действие (`ux-writing.md` §4) |
| Один элемент, много элементов | нет «1 предметов»; список больше 50 строк виртуализирован |
| Длинный и короткий текст, эмодзи, не-латиница в имени | не вылезает: усечение, перенос или `line-clamp`; у детей flex — `min-w-0` |
| Большие числа (миллионы монет, место 12 345) | не ломают строку; `tabular-nums` там, где числа сравнивают |
| Нет сети, медленно, таймаут | понятный текст, «Повторить», ничего не потеряно |
| Ответ сервера 401 / 403 / 404 / 409 / 429 / 500 | у каждого свой ответ, не общее «Ошибка» (§3) |
| Выключено | причина подписью рядом, кнопка нейтральная (`docs/27` §4) |
| Двойное и тройное нажатие | второе действие не создаётся; проверка — нажать 10 раз подряд |
| Прерванный жест | второй палец, отпускание вне зоны — следующий жест работает |
| Свернули Mini App и вернулись | состояние на месте, забег на паузе |
| Крупный шрифт системы 130 и 150 %, 320 px, вырез | ничего не обрезано, нет боковой прокрутки, отступы — `--app-inset-*` |
| Успех | короткое подтверждение результата |

## 2. Отклик и ожидание

| Время | Как ощущается | Что показать |
|---|---|---|
| до 100 мс | мгновенно | видимый отклик нажатия обязателен |
| 100–300 мс | лёгкая задержка | смена состояния кнопки |
| 300 мс – 1 с | заметно | индикатор — **после** ~300 мс, чтобы не мигал |
| 1–5 с | ожидание | скелет области или индикатор с подписью «Сохраняем…» |
| 5–10 с | раздражение | прогресс и «Отмена» |
| больше 10 с | уход | фоновая работа и уведомление по готовности |

- Скелет — для содержимого, индикатор — для действия. «Индикатор на всё» и
  полноэкранный загрузчик — ошибка. Закрывать загрузкой только ту область,
  которая грузится.
- Скелет, мелькнувший на 50 мс, хуже его отсутствия: показывать только для
  загрузок дольше ~300 мс и держать минимальное время.
- Кнопка в загрузке: индикатор внутри, подпись и размер прежние, повторное
  нажатие заблокировано. Блокируется в момент старта запроса, не раньше.
- Процент прогресса — только настоящий.

## 3. Ошибки, повтор, офлайн

- Текст ошибки: что случилось → как исправить или что делать вместо. Код —
  не основной текст. Не обещать причину, которой мы не знаем. Ошибка не
  исчезает раньше, чем её прочтут.
- По ответам сервера: 401 — тихо обновить сессию и повторить, иначе на вход;
  403 — объяснить, почему недоступно и когда откроется; 404 — «не найдено» с
  выходом; 409 — назвать, что уже сделано («Награда уже забрана»); 429 —
  «Слишком часто, подождите N с»; 500 — общий текст и «Повторить».
- «Повторить» с видимым откликом во время повтора. Автоповтор — с индикацией.
- Повтор безопасен, потому что сервер идемпотентен (`docs/15` §4). Клиент
  всё равно блокирует второе нажатие.
- Офлайн: плашка связи видна, не прячется (`ConnectionBanner`). Данные из
  кеша не выдаются за свежие. Связь вернулась — обновить само.
- Сбой одного виджета не блокирует экран целиком.

**Оптимистичное обновление** — для переключателей, сортировки, отметок. **Не
для денег и наград:** покупка, списание звёзд и самоцветов, забор награды,
второй шанс — только после ответа сервера.

## 4. Длинный текст и раскладка

- Одна строка: `truncate`. Несколько: `line-clamp`. Перенос длинного слова:
  `overflow-wrap: break-word`.
- Ширина текстовых блоков — не фиксированная. Обрезанный пункт меню —
  сломанный пункт.
- Самый длинный текст словаря и имя игрока в 32 знака проверяются на 320 px.
  Переводы длиннее русского на 30–40 % — запас под MAX и VK и будущие языки.
- Картинки — с явными размерами или `aspect-ratio`: раскладка не прыгает.
- Выглядит нажимаемым — нажимается. Подпись и флажок — одна цель касания.
- `touch-action: manipulation` против приближения двойным касанием,
  `overscroll-behavior: contain` в листах и окнах. Масштаб не отключать.

## 5. Чек-лист перед сдачей (из Web Interface Guidelines)

- Фокус виден и не закрыт фиксированной панелью; окна держат и возвращают
  фокус. `outline: none` без замены — нельзя.
- Касание — не меньше 44 px на телефоне, не меньше 24 px везде; маленький
  значок получает прозрачную зону (`hit-tall`).
- Поле ввода — шрифт не меньше 16 px, иначе iOS приближает.
- Вставка из буфера в поле не блокируется; пробелы по краям обрезаются.
- Ошибка — у поля; при отправке фокус на первую ошибку.
- Подтверждение или «Отменить» у разрушительного действия.
- Тосты и встроенная проверка — `aria-live="polite"`.
- Статус не только цветом; у значка-кнопки — имя из словаря.
- Анимируются только `transform` и `opacity`, `transition: all` — нельзя
  (`motion.md`).
- Многоточие — символ `…`; число и единица — через неразрывный пробел.
- Нет тупиков: у каждого состояния есть следующий шаг.

## 6. Порядок полировки

1. Сломанные действия, потеря данных, вводящее в заблуждение состояние.
2. Недостающие состояния (§1).
3. Поток и иерархия, расхождение с соседними экранами.
4. Визуальные расхождения и движение.
5. Чистка: отладочный вывод, мёртвый код.

Не вылизывать один угол, оставляя остальное ниже планки. Причину чинить на
самом узком верном уровне: нет значения — токен; разовая реализация — общий
компонент; расхождение — привести к соседям.
