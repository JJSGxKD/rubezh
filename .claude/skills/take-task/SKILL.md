# Взять задачу и сделать её

Порядок работы целиком — `tasks/README.md`. **Прочитай его до начала работы.**
Здесь — короткий маршрут и то, что исполнители нарушают чаще всего.

## Маршрут

1. **Выбор.** `git fetch origin --prune`, затем свободная задача: `status: ready`,
   все `depends_on` — `done`, зоны не пересекаются с задачами в работе (ветки
   `task/*` на `origin`). Если подходят несколько — старший `priority`.
   `runner: human` исполнитель-ИИ не берёт. `runner: local` — только если есть
   живые Postgres, Redis, Docker или устройство.
2. **Захват.** Ветка `task/T-NNNN` от `origin/dev` и коммит, который ставит
   `status: in-progress` и `owner`. Затем `git push origin HEAD:refs/heads/task/T-NNNN`
   без `--force`. Отказ — задачу уже взяли, выбирай другую.
3. **Чтение.** Спецификация целиком, документы и код, на которые она ссылается.
   Скилл `pre-pr` пригодится в конце.
4. **Тесты до кода.** Первый коммит — кейсы из раздела «Тесты», они красные.
   Тест — договор: подгонять его под код нельзя.
5. **Код по «Шагам по порядку».** Коммиты дробные, формат — `CLAUDE.md`.
6. **Гейт.** `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`,
   `pnpm budget`, `pnpm docs:check`. Для экранов — снимки на 320, 390, 768 и
   1440 px против макета.
7. **Закрытие.** `status: done` в файле задачи — в этом же PR. PR в `dev`:
   - заголовок и метка — из спецификации;
   - описание — по скиллу `pre-pr`;
   - первая строка — `Задача: tasks/T-NNNN-<slug>.md`;
   - чек-лист критериев приёмки с отметками.

## Чего не делать

- **Не додумывать.** Неясно, два прочтения, нужен файл вне зон, спецификация
  спорит с кодом — черновик PR с разделом `## Вопросы` и стоп
  (`tasks/README.md`, «Если что-то неясно»).
- **Не выходить за зоны.** Можно трогать только `zones`, свои строки в `shared` и
  файл задачи. Попутный рефакторинг, переименование и «улучшение рядом» — причины
  вернуть PR.
- **Не вливать PR и не пушить в `dev` и `main`.** Вливают тимлиды.
- **Не трогать чужие ветки `task/*`** и не пушить с `--force`.
- **Опасного не делать.** Нельзя `prisma migrate reset`, `docker compose down -v`,
  копировать корневой `.env` с настоящими ключами, запускать бота с боевым
  токеном, менять настройки репозитория, секреты и переменные Actions.
- **Не менять пороги** `scripts/bundle-budget.mjs`, если спецификация этого не
  разрешает.

## Если задачу пришлось бросить

`git push origin --delete task/T-NNNN` и закрыть PR, если он был, с причиной в
комментарии. Задача снова свободна.
