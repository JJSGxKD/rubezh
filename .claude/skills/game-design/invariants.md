# Инварианты игры и поиск расхождения повтора

Справка скилла `game-design`: как превратить обещание дизайна в проверяемое
правило и как найти первый тик, где детерминированный забег разошёлся.
Основано на agentic-gamedev-skills (abagames, `implementing-gameplay-invariants`,
`localizing-game-state-divergence`). Лицензии —
[`../THIRD_PARTY.md`](../THIRD_PARTY.md). Детерминизм и golden —
`CLAUDE.md`, `docs/17-testing-strategy.md` §3; повтор забега —
`docs/28-diagnostics.md`.

## 1. Инвариант

Обещание дизайна → правило с областью и последствием:

| Обещание | Инвариант | Как игрок видит | Чем проверить |
|---|---|---|---|
| сундук с элиты один | одна выдача на источник | сундук на поле | забег с убийством элиты дважды по логу |
| опыт честный | опыт забега = сумма кристаллов | полоса опыта | сумма кристаллов в тесте |
| второй шанс один | продолжений не больше `CONTINUES_PER_RUN` | экран смерти | повтор с лишней командой — отказ |
| живых не больше потолка | число живых ≤ потолку отрезка | толпа | 400 врагов, проверка в шаге |
| кольцо одно | второе событие при активном пропускается | строй стражей | лог событий |
| сила в пределах | сумма множителей в `LOADOUT_BOUNDS` | характеристики | максимальная сборка |
| здоровье в границах | 0 ≤ hp ≤ max | полоска | шаг мира |
| детерминизм | то же зерно и ввод → тот же хэш мира | — | golden, повтор |

- Каждое правило — тестом, а не комментарием.
- Для вредной политики (стоять, ждать, бегать по кругу) заранее решить
  исход: умрёт, безопасно истечёт по времени или выживет без награды.
  Смерть не может быть единственной слабостью.
- **Невидимое правило:** инвариант верен, но не нарисован. Правило, которое
  меняет решение игрока, получает индикатор, заполняющийся до плохой
  ситуации: полоса потолка, оставшееся время кольца, заряды переброса.
- У объекта, дающего награду, — цикл жизни: появился → окно → взят →
  удалён; стабильный идентификатор для поиска двойного начисления.
- Числовая правка без недостающего инварианта — отказ: чинится не там.

## 2. Первый расхождённый тик

Задача — найти **первый** тик, где состояние нарушает правило, а не
рассуждать, где в коде ошибка. Результат — номер тика и два состояния, а не
патч.

1. **Оракул** — машинная проверка состояния — пишется до чтения трассы и не
   меняется по ходу.
2. **Трасса** — только при повторе, по записи на переход: номер, тик,
   событие, кто (игрок, система, восстановление из снимка), стабильный id
   объекта (не слот пула), что прочитано, что записано «до → после».
   Порядок внутри тика сохраняется, трасса не прореживается.
3. **Поиск:** хэши мира по контрольным точкам → бисекция по «совпадало до
   тика k» (оракул хэша монотонен) → линейный проход по трассе в найденном
   окне.
4. **Стоп-условия:** ни один оракул не упал, а итог неверен — трасса груба,
   добавить поле; упал на нулевом тике — неверен старт (снимок, контент);
   индекс «плавает» между прогонами — сначала починить недетерминизм.
5. **Первое нарушение ≠ первая причина:** пройти назад по полям, которые
   читает оракул, до самой ранней записи.
6. **Причинность:** убрать или изменить событие и повторить — если
   расхождение там же, событие было «прохожим».

Отчёт: зерно, сборка, хэш контента; оракул; первый тик и событие; состояние
до и после; самая ранняя запись; проверка причинности; что намеренно не
попало в трассу.

**У нас:** `pnpm replay` говорит «разошлось» без места. Режим «первый
расхождённый тик» для повтора и перепроверки забегов (T-0316–T-0320) —
кандидат в задачу.
