# T-0368. Граф связей игрока — вкладка «Связи» в карточке: граф на ПК, список на телефоне

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0368.json)](README.md#значки-статуса) [![T-0367](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0367.json&label=T-0367)](T-0367-player-graph-server.md)

## Зачем

Сервер отдаёт граф связей игрока (T-0367). После задачи в карточке игрока
есть вкладка «Связи».
- **На ПК** — граф: игрок в центре, вокруг друзья, пригласивший, партнёр и
  те, с кем он обменивался подарками, дальше — их связи. Щелчок по
  игроку перестраивает граф от него.
- **На телефоне** — те же связи списком по видам: граф на 390 px не читается.

## Решения

Решение владельца — Р182. Решения `claude-lead-1` от 01.11.2026:

- **Раскладка — `d3-force` 3.0.0** (точная версия, только этот модуль d3,
  без `d3` целиком). Рисунок — SVG в React, без canvas-библиотек: 200 узлов
  SVG держит. Модуль грузится лениво (`import()`) при открытии вкладки и в
  первую загрузку панели не попадает. Вес чанка — в PR, порог — 30 КБ gzip.
  Обоснование выбора — строкой в `docs/16-tech-stack-decisions.md`: почему
  не cytoscape и не vis-network — они в 10–20 раз тяжелее, а нужна одна
  раскладка.
- **Раскладка считается до показа:** 300 тиков симуляции синхронно, потом
  статичный рисунок. Узлы не плавают: панель — место работы (§4.6
  `direction-v2.md`, «движение — только как отклик»).
- **Вид узлов:**
  - игрок — круг с первой буквой имени;
  - центр крупнее и в обводке акцента;
  - заблокированный — тоном `danger`;
  - партнёр — квадрат.

  Подпись — имя под узлом, у узлов первого шага всегда, у второго — при
  наведении.
- **Вид связей** — цветом и линией, легенда над графом:
  - `friend` — сплошная нейтральная;
  - `invite` — сплошная со стрелкой;
  - `partner` — штрих;
  - `gift` — точки, толще при `count ≥ 5`;
  - вид из T-0369 — свой тон, если сервер его прислал.

  Цвета — токены панели, не новые литералы.
- **Действия.**
  - Щелчок по игроку — граф от него: адрес
    `#/players/<id>/graph`, «Назад» в браузере возвращает.
  - Двойной щелчок — карточка игрока.
  - Щелчок по партнёру — карточка партнёра.
  - Масштаб колесом и перетаскивание фона.
- **Обрезка.** Если `truncated: true` — над графом «Показаны 200 связей из
  большего числа — ближние все, дальние частично».
- **Телефон** (`useNarrow`) — список групп «Друзья», «Пригласил /
  приглашённые», «Партнёр», «Подарки»; строка — имя и дата, она ведёт в
  карточку. Только первый шаг: второй шаг списком не читается.
- **Логика — чистыми функциями** в `graph-layout.ts`: подготовка узлов и
  связей, группы для телефона, текст обрезки. Тест проверяет их, а не SVG.

## Сценарий и интерфейс

- **Открыл «Связи»** — «Загрузка…», затем граф. Легенда над ним, справа
  вверху число узлов.
- **Нет связей** — «Связей нет: друзей, приглашений, партнёра и подарков у
  игрока нет».
- **Ошибка** — `ErrorNotice` с «Повторить».
- **Щёлкнул друга** — граф перестроился от него, адрес сменился.
- **Телефон** — список групп, в каждой строки «Имя · дата».

## Тесты

Первым коммитом, `apps/admin/test/graph.test.ts`:

- схема разбирает ответ с узлами двух видов и связями четырёх видов;
- неизвестный вид связи (из будущей T-0369) схема пропускает, а
  подготовка рисует его тоном «прочее», а не падает;
- группы для телефона: только связи центра, по видам, сортировка по дате;
- текст обрезки — только при `truncated: true`.
