# T-0355. Панель — поиск игрока из поиска разделов «/»: «@ник» или число — строка «Игрок …» первой

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0355.json)](README.md#значки-статуса)

## Зачем

Дежурный разбирает жалобу из чата: «у @dym пропали самоцветы». Чтобы найти
игрока, сейчас нужно открыть раздел «Игроки», найти поле поиска и ввести ник
там. После задачи достаточно нажать «/» на любом экране и ввести `@dym`:
первой строкой в меню появится «Игрок @dym», и Enter откроет поиск с
результатом.

## Решения

Находка AD-04 аудита дизайнера (`design/art/direction-v2.md` §4.6).
Решения `claude-lead-1` от 01.11.2026:

- **Когда строка «Игрок …» появляется.** Только у кого есть `players.view`,
  и только если запрос похож на игрока:
  - начинается с `@`, а за ним хотя бы 2 символа;
  - или состоит из одних цифр, от 5 до 20 (Telegram ID; номер версии или
    дата — не игрок).

  Имя без `@` строку не даёт: «рассылки» — это раздел, а не игрок.
- **Что делает строка.** Первой в меню, над группами разделов: «Игрок
  @dym — найти» со значком `UserSearch`. Выбор — щелчок или Enter в поле
  поиска, пока строка первая — открывает раздел «Игроки» и запускает поиск
  с этим запросом. Тот же запрос встаёт в поле поиска раздела.
- **Поиск — тот же,** что в разделе: `runSearch` из `PlayerSearch.tsx`
  становится экспортом `searchPlayersFrom(query)`. Нового запроса к
  серверу нет.
- **Поле очищается** после перехода, лист меню на телефоне закрывается,
  как при выборе раздела.
- **Совпадение с разделом.** Если запрос похож на игрока и одновременно
  совпадает с разделом, первой остаётся строка игрока, разделы — под ней.

## Шаги по порядку

1. **Тесты первым коммитом.**
2. **`routes.ts`** — чистая функция `playerQuery(query: string): string | null`
   по правилам «Решений» (обрезает пробелы, возвращает запрос как есть).
3. **`PlayerSearch.tsx`** — экспорт `searchPlayersFrom(query)`: ставит
   `query` в хранилище и зовёт `runSearch`. Поле поиска показывает этот
   запрос: `draft` берёт начальное значение из хранилища, так уже сделано.
4. **`Shell.tsx`, `MenuColumn`**:
   - строка «Игрок …» над группами, если `playerQuery(query) !== null`
     и есть `players.view`;
   - Enter в поле поиска выбирает её;
   - переход — `navigate({ section: "players", id: null })`, затем
     `searchPlayersFrom`.

## Чего не трогаем

- Сервер поиска игроков и правила поиска (ID — точно, юзернейм — с начала).
- Вид меню разделов и поиск разделов.
- Палитру команд как отдельное окно: поиск остаётся полем в меню.

## Сценарий и интерфейс

- **ПК.** На экране «Сводка» нажал «/», ввёл `@dy`. Первой строкой — «Игрок
  @dy — найти», под ней разделов нет. Enter — открылся раздел «Игроки», в
  поле `@dy`, ниже результаты.
- **Телефон.** Открыл меню, ввёл `123456789`. Строка «Игрок 123456789 —
  найти», нажал — меню закрылось, открыт поиск.
- **Ввёл «рас»** — строки игрока нет, в меню раздел «Рассылки», как сейчас.
- **Нет права `players.view`** — строки игрока нет никогда.

## Тесты

Первым коммитом, `apps/admin/test/palette-player.test.ts`:

- `playerQuery("@dym")` → `"@dym"`; `playerQuery(" @dym ")` → `"@dym"`;
- `playerQuery("@d")` → `null` (меньше 2 символов после `@`);
- `playerQuery("123456789")` → `"123456789"`;
- `playerQuery("1234")` → `null`, `playerQuery("0.9.1")` → `null`;
- `playerQuery("рассылки")` → `null`, `playerQuery("")` → `null`.
