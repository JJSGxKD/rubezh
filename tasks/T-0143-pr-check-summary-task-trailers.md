# T-0143. Проверка PR — номер в сводке, путь задачи, сводка не в коде, трейлеры коммитов

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0143.json)](README.md#значки-статуса)

## Зачем

Тимлид руками правит одно и то же почти в каждом втором PR исполнителей
(`tasks/inbox.md`, 11.10):

- в заголовке сводки нет номера PR («В DEV ВЛИТ PR — …» или заглушка `#<номер>`);
- строка «Задача:» ведёт на несуществующий файл;
- сводка в блоке кода — бот отправил бы её как есть;
- трейлеры `Co-Authored-By` стоят сразу под заголовком коммита, и git склеивает
  их с заголовком.

Проверка `pr-check` уже перезапускается при правке описания (`edited` в
`pr-checks.yml`) — достаточно научить её этим правилам.

## Решения

Решение `claude-lead-1` от 14.10.2026. Новые проверки — ошибки, кроме служебных
PR (`isServicePr`):

1. **Сводка для команды** (`## Сводка для команды`, разбор — тот же
   `extractSection`, что у `team-summary.mjs`):
   - раздела нет — ошибка;
   - первая непустая строка содержит `#<номер этого PR>`; заглушки `#<номер>` и
     `#НОМЕР` — ошибка «впишите номер PR в заголовок сводки»;
   - раздел целиком в блоке кода (начинается с ```` ``` ````) — ошибка «сводка в
     блоке кода — бот отправит её как есть».
2. **Путь задачи** — только у веток `task/T-NNNN`: первая строка описания —
   `Задача: tasks/T-NNNN-….md`, файл есть в ветке PR и его id равен id ветки.
3. **Трейлеры коммитов** — у каждого коммита PR, где есть строка
   `Co-Authored-By:`, вторая строка сообщения пустая (`git log --format=%B base..head`
   — в джобе `fetch-depth: 0`, история есть). Ошибка называет коммит.

   трейлеры коммита — после пустой строки». В `docs/09` §8.1 — список
   проверок `pr-check`.

## Чего не трогаем

- Проверки заголовка, метки и «Для игроков».
- Служебные PR и бот сводок (`team-summary.mjs`) — только используем его разбор.

## Тесты

`scripts/test/pr-check.test.ts`:
- `checkSummary`: сводка с `#123` при номере 123 → `[]`; без номера →
  ошибка; `#<номер>` и `#НОМЕР` → ошибка с подсказкой; раздел в ```` ``` ```` →
  ошибка; раздела нет → ошибка.
- `checkTaskLine`: ветка `task/T-0042`, строка `Задача: tasks/T-0042-wipe.md`,
  файл есть → `[]`; файла нет → ошибка; id в строке другой → ошибка; ветка не
  `task/*` → `[]` без проверки.
- `checkTrailers`: «Заголовок\n\nТекст\n\nCo-Authored-By: …» → `[]`;
  «Заголовок\nCo-Authored-By: …» → ошибка с коротким sha; без трейлера → `[]`.

## Критерии приёмки

- [ ] PR без номера в сводке, с неверным путём задачи, со сводкой в коде или с
  трейлером под заголовком коммита получает красный `check` с понятной ошибкой.
- [ ] После правки описания проверка перезапускается и становится зелёной.
- [ ] Служебные PR не проверяются.
- [ ] Гейт (`CLAUDE.md`) зелёный.

## PR

- **Заголовок:** `chore(dev): Проверка PR — сводка, путь задачи, трейлеры`
- **Метка:** `release: none`
- **Для игроков:** нет
- **Сводка для команды:**

  ```
  📋 **СВОДКА: В DEV ВЛИТ PR #<номер> — ОФОРМЛЕНИЕ PR ПРОВЕРЯЕТ МАШИНА**

  Проверка PR теперь ловит то, что тимлид правил руками: сводку без номера PR или в блоке кода, неверный путь к задаче и трейлеры, приклеенные к заголовку коммита.
  ```
