# T-0454. Раздел «Участники» в панели — доли и их история

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0454.json)](README.md#значки-статуса) [![T-0452](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0452.json&label=T-0452)](T-0452-stakeholder-shares-server.md)

## Зачем

Сервер долей участников есть (T-0452), но назначить долю можно только
запросом. Владельцу нужен экран: кто участник, какая у него доля и с какого
месяца, что менялось и почему, и окно «Изменить долю» с проверкой суммы до
отправки. Финансы видят тот же экран без кнопки.

## Решения

- `docs/35-stage4-plan.md`, **Р217**; `docs/29-admin-panel.md` §6.6.
- Раздел «Участники» — в группе «Доход», после «Курсов»; право раздела —
  `revenue.split.view` (владелец и финансы). Участник проекта видит
  участников в своём кабинете (T-0455), отдельный раздел ему не нужен.
- Изменение доли — окно действия с подтверждением (`docs/29` §4,
  «Подтверждения»): доля, месяц, причина и строка последствий.

## Как сейчас

- Разделы — `apps/admin/src/routes.ts`, группа «Доход» (строка ~61), пример
  — `{ id: "fx", title: "Курсы", … permission: "analytics.revenue.view", icon: Coins }`;
  экран раздела — `screens/sections.tsx` (`fx: () => <FxScreen />`).
- Клиент API — `apps/admin/src/api/*.ts`, `api.request(path, { method, body, schema })`
  с Zod-схемой ответа (пример — `api/fx.ts`).
- Окно подтверждения — `ui/confirm-dialog.tsx`, `ConfirmDialog`.
- Сервер (T-0452): `GET /admin/stakeholders` → `StakeholdersView`,
  `PUT /admin/stakeholders/:accountId/share` `{ sharePercent, fromMonth, note }`;
  ошибки `stakeholder_month_past`, `stakeholder_role_required`,
  `stakeholder_shares_over` — с русскими текстами.

## Шаги по порядку

1. `api/stakeholders.ts`: схемы Zod ответа `StakeholdersView` (строго по
   T-0452), `loadStakeholders()`, `setShare(accountId, input)`.
2. `routes.ts`: раздел
   `{ id: "stakeholders", title: "Участники", hint: "Участники проекта и их доли: с какого месяца и что менялось", permission: "revenue.split.view", icon: <значок из lucide, например PieChart> }`
   в группе «Доход» после «Курсов»; `sections.tsx` — экран.
3. `screens/stakeholders/StakeholdersScreen.tsx`:
   - сверху — строка «Владелец — N %» (остаток) и «Участников — K»;
   - таблица (на телефоне — карточки): имя; доля сейчас и «с <месяц>»;
     будущая доля, если есть: «с <месяц> — M %»; метка «роли нет», если
     `hasRole: false`;
   - строка раскрывается историей: месяц, доля, причина, кто и когда;
   - кнопка «Изменить долю» у строки — только если у сессии есть
     `stakeholders.manage` (права сессии берутся так же, как в других
     разделах).
4. Окно «Изменить долю» (`ShareDialog.tsx`):
   - поля: «Доля, %» (число 0…100, два знака), «С месяца» (список: текущий и
     следующие 12 месяцев, названия месяцев по-русски «ноябрь 2026»),
     «Причина» (обязательна, 3…500 знаков);
   - под полями — расчёт до отправки: «Владельцу останется N %» на выбранный
     месяц (по данным экрана); если сумма выйдет больше 100 % — кнопка
     неактивна и подпись «Сумма долей дала бы N % — больше 100 %»;
   - строка последствий в подтверждении: «С <месяц> доля <имя> — N %.
     Прошлые месяцы не меняются.»; 0 % — «С <месяц> <имя> больше не получает
     долю.»;
   - ошибка сервера — текст из ответа под формой, окно не закрывается.
5. Пустое состояние: «Участников пока нет. Участник — аккаунт с ролью
   «Участник проекта»: выдать её можно в разделе «Роли».» и ссылка на «Роли»
   (если у сессии есть `roles.assign`).
6. `docs/29-admin-panel.md` §6.6 — сверить описание с экраном.

## Чего не трогаем

- Кабинет участника — T-0455.

## Сценарий и интерфейс

- Владелец открывает «Участники»: «Владелец — 70 %», строка «Иван — 30 % с
  ноября 2026», «Изменить долю» → 25 %, с декабря, причина → подтверждение →
  в строке «30 % с ноября 2026 · с декабря 2026 — 25 %».
- Финансы видят то же без кнопки.
