# T-0379. Бот MAX — связывает аккаунт по стартовому параметру и проверяет подписку на канал

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0379.json)](README.md#значки-статуса) [![T-0377](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0377.json&label=T-0377)](T-0377-external-account-link-base.md)

## Зачем

Задания «подпишитесь на канал в MAX» (Р188). Основа — связь аккаунтов, код и
проверка задания — сделана в T-0377. Здесь появляется бот MAX:
1. игрок Telegram открывает бота по ссылке с кодом;
2. бот связывает его MAX-id с игровым аккаунтом и присылает ссылку на канал;
3. сервер проверяет подписку через Bot API MAX.

## Решения

- **Р188** (`docs/35-stage4-plan.md`): бот MAX служит росту канала, игру не
  портирует. От владельца нужны:
  - бот MAX, с верификацией бизнес-аккаунта (`docs/03-notes-and-risks.md`);
  - ключ бота — в «Ключах интеграций».
- **Р53, Р84:**
  - токен внешнего сервиса — каталог ключей интеграций;
  - не секрет и меняется без релиза — каталог настроек.

Уточнения `claude-lead-1` (по Р188, без нового продуктового выбора):

- **Ссылка на бота** — `https://max.ru/<имя бота>?start=<код>`. Событие `bot_started`
  несёт `payload` (код) и `user.user_id` — MAX-id.
- **Приём событий — вебхук** (подписка `POST /subscriptions` Bot API MAX), по
  образцу вебхука Telegram: сначала очередь, потом ответ.
  - Защита — секрет подписки. MAX передаёт его в заголовке, сравнение за
    постоянное время.
  - Если в документации MAX на дату работы секрета у подписки нет —
    неугадываемый путь не считается защитой. Это вопрос тимлиду в PR, а не
    самостоятельное решение.
- **Проверка подписки** — участники канала через Bot API: бот администратор
  канала, запрос участников по `user_ids`. Пустой ответ — не подписан.
- **Подписка вебхука ставится сама** при старте, если есть ключ бота и публичный
  адрес API, — по образцу `setWebhook` Telegram. Она идемпотентна: та же подписка
  повторно не плодится.
- **Сверка с документацией MAX** (dev.max.ru) — первым шагом. Названия методов,
  полей, заголовка секрета и способа передачи ключа (заголовок `Authorization`
  или иное) берутся из неё. Расхождение с этой спецификацией в смысле, а не в
  именах — вопрос тимлиду.

## Шаги по порядку

1. **Сверка с документацией MAX** — в описание PR: таблица «что в спецификации →
   как в документации MAX, ссылка». Охватывает:
   - адрес API;
   - передачу ключа;
   - `POST /subscriptions` (поля, секрет);
   - событие `bot_started` (`payload`, `user.user_id`);
   - отправку сообщения с кнопкой-ссылкой;
   - участников канала.
2. **Тесты первым коммитом** (раздел «Тесты»).
3. **Ключи и настройки:**
   - **ключи интеграций**, сервис «MAX»:
     - `max.bot-token` — «Ключ бота MAX»;
       - подсказка: «Бот связывает аккаунт MAX игрока с игрой и проверяет
         подписку на канал. Бот должен быть администратором канала. Без ключа
         задания «подпишитесь на канал MAX» никому не видны.»;
       - `fromEnv: () => null`;
       - `check` — `GET /me` бота.
     - `max.webhook-secret` — генерируемый, 32–64 знака `[A-Za-z0-9]`.
       Сервер ставит его в подписку сам, `reveal` не нужен. Если каталог требует
       `generated.reveal`, показывать адрес вебхука без секрета.
   - **настройка** `max.bot-username` — имя бота для ссылки, без `@`.
4. **`platforms/max/max-bot-api.ts`** — клиент:
   - запросы через `outbound.forService("max.bot")` (имя — в `OUTBOUND_SERVICES`);
   - таймаут 5 с;
   - ответы разбираются Zod-схемами;
   - методы:
     - `me()`;
     - `subscribe(url, secret, updateTypes)`, `subscriptions()`;
     - `sendMessage(userId, text, linkButton?)`;
     - `isChannelMember(chatId, userId): boolean`;
   - ошибки:
     - сеть, 429, 5xx → `MembershipUnavailableError`;
     - нет канала, бот не админ, неверный ключ → `MembershipRejectedError`.
     Коды — из документации, в константе с комментарием.
5. **`platforms/max/max-webhook.controller.ts`** — `POST /api/v1/max/webhook`,
   `@Public()`:
   - нет ключа → 404 (`DisabledError`);
   - секрет из заголовка не совпал → 401 до разбора;
   - тело — Zod;
   - `bot_started` → в очередь Redis (свой ключ, повтор отсекается по id события
     или по паре «пользователь + payload + время» — по тому, что даёт MAX) → 200;
   - прочие типы → 200 без обработки;
   - Redis недоступен → 503.
6. **`platforms/max/max-updates.worker.ts`:**
   - `payload` — код, `user.user_id` — MAX-id;
   - пустой `payload` → «Чтобы связать аккаунт, открой задание в игре и нажми
     «Открыть бота MAX»»;
   - иначе `consume("max", payload, String(user_id))` → ответ по исходу. Тексты
     как у VK (T-0378, шаг 5), с заменами «VK» → «MAX» и «сообщество» → «канал»:
     - `linked` — «Готово! Аккаунт MAX связан с игрой. Подпишись на канал и
       вернись в игру — нажми «Проверить».» + кнопка-ссылка «Открыть канал»;
     - `already` — «Аккаунт уже связан. Подпишись на канал и нажми
       «Проверить» в игре.» + кнопка;
     - `taken` — «Этот аккаунт MAX уже связан с другим игроком. Связать его второй
       раз нельзя.»;
     - `expired` — «Ссылка устарела. Открой задание в игре и нажми «Открыть
       бота MAX» ещё раз.»
   - Ссылка на канал — `params.url` задания-канала MAX из каталога заданий. Если
     таких заданий несколько — кнопка на каждое, до трёх, в порядке каталога.
7. **`platforms/max/max-subscription.service.ts`:**
   - при старте и при смене ключа ставит подписку на
     `<публичный адрес API>/api/v1/max/webhook` с секретом и типом `bot_started`;
   - подписка на тот же адрес уже есть → ничего не делает;
   - ошибка — в лог, повтор при следующем старте;
   - публичный адрес — тот же, что для вебхука Telegram (`config.telegram.publicApiUrl`
     или общий, если есть).
8. **`platforms/max/max-channel-membership.ts`** (`ChannelMembership` для `max`) и
   **`max-link-starter.ts`** (`ExternalLinkStarter`: `https://max.ru/<имя>?start=<код>`,
   `null` без ключа или имени).
9. **`platforms/max/max.module.ts`:**
   - регистрация в `ChannelMemberships` и `ExternalLinkStarters`;
   - подключение в `app.module.ts`;
   - домен — только через порты.
10. **Документы** — раздел «Документы».

## Сценарий и интерфейс

Игрок в MAX нажимает «Начать» у бота по ссылке из задания. Бот отвечает текстом
из шага 6 и кнопкой-ссылкой на канал.

Панель:
- «Ключи интеграций», сервис «MAX»: ключ бота с проверкой, секрет вебхука;
- «Настройки»: `max.bot-username`.

## Тесты

Первым коммитом, до кода. Сеть — подмена `fetch`, Redis — живой.

- `backend/api/test/max-webhook.test.ts`:
  - **доступ:**
    - нет ключа → 404;
    - неверный секрет → 401, очередь пуста;
  - **очередь:**
    - `bot_started` → 200, событие в очереди;
    - повтор того же события → одно;
    - Redis недоступен → 503;
  - **воркер — ответы:**
    - код → `consume("max", payload, userId)`;
    - ответ «Готово!…» с кнопкой на канал;
    - `taken`, `expired`, пустой `payload` — свои тексты дословно;
  - **подписка вебхука:**
    - есть ключ и адрес → `subscribe` с секретом;
    - та же подписка уже есть → второго вызова нет.
- `backend/api/test/max-channel-membership.test.ts`:
  - участник в ответе → `true`, пусто → `false`;
  - бот не админ или нет канала → `MembershipRejectedError`;
  - 5xx и таймаут → `MembershipUnavailableError`;
  - ключ не попадает в лог.
- `backend/api/test/max-link-starter.test.ts`:
  - ключ и имя → `https://max.ru/<имя>?start=<код>`;
  - нет любого → `null`.
