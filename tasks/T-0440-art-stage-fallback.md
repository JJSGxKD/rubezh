# T-0440. Враги поздних ступеней — рисунок ближайшей ступени с тоном вместо фигуры

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0440.json)](README.md#значки-статуса)

## Зачем

С 8-й минуты забега враги вдруг рисуются геометрическими фигурами, как до
арта: у ступеней 3–5 нет кадров в атласах. Игрок видит «чужих» врагов там,
где должны быть те же, но матёрее. После задачи враг любой ступени рисуется
своим спрайтом, а поздняя ступень читается тёмным тоном.

## Решения

- `docs/35-stage4-plan.md`, **Р215**: кадр ближайшей нарисованной ступени не
  выше нужной; недостающая ступень — тоном: спрайт умножается на цвет
  «белый, смешанный с `mixColor` нужной ступени из `STAGE_LOOKS` на разницу
  `mix` нужной и нарисованной ступеней». Нарисованная ступень тона не
  получает.
- Дорисовка s3–s5 — отдельная задача дизайнера T-0441, после этой: как только
  кадры появятся, тон сам перестанет применяться.
- Элиты и боссы ступеней не получают — у них всегда `s0`, как сейчас.

## Как сейчас

- `content/stages.ts`: шесть ступеней — 0, 150, 330, 480, 660, 840 с.
- Атласы `design/art/out/atlas-core.json`, `atlas-late.json` (и пока не
  подключённый `atlas-r157.json`) содержат кадры `<id>/s0…s2/walk0…3`, ступеней
  3–5 нет ни у кого.
- `packages/core-game/src/game/render/art-atlas.ts`, `ArtMode.buildFrames`
  (строки ~229–236): для каждого типа и ступени ищет ровно
  `enemyFrameName(type.id, stage, k)`; не нашёл — в `frames` ложится `null`.
- `ArtMode.applyEnemy` (строки ~299–316): `null` — возвращает `false`, и
  `WorldRenderer` (строки ~391–396) ставит текстуру фигуры.
- `WorldRenderer.applyLook` (строки ~529–552): вид кэшируется по
  `enemySpriteLook` и `enemySpriteSize`; в обычном виде — `sprite.clearTint()`,
  заливки (`setTintFill`) — у попадания, телеграфа, заморозки и тона состояния.
- `looks.ts`: `STAGE_LOOKS` (строки ~113–124) — `mixColor` и `mix` ступеней;
  `mixChannels` (строки ~138–145) — не экспортирована.

## Шаги по порядку

1. `looks.ts`: экспортировать `mixChannels` (одно слово `export`, тело не
   менять).
2. `art-atlas.ts` — две чистые функции:
   - `export function artStageFor(stage: number, has: (stage: number) => boolean): number` —
     наибольшая ступень `s ≤ stage`, для которой `has(s)`; ни одной — `-1`;
   - `export function artStageTint(stage: number, drawn: number): number | null` —
     `null`, если `drawn < 0` или `drawn >= stage`; иначе
     `mixChannels(0xffffff, look.mixColor, Math.max(0, look.mix - drawnLook.mix))`,
     где `look = STAGE_LOOKS[min(stage, last)]`, `drawnLook = STAGE_LOOKS[min(drawn, last)]`.
3. `ArtMode.buildFrames`: для обычного врага ступень кадра —
   `artStageFor(stage, (s) => this.atlas.find(enemyFrameName(type.id, s, 0)) !== null)`;
   кадры шага берутся у этой ступени. Рядом с `frames` — массив
   `private stageTints: (number | null)[]` по индексу текстуры
   `тип × ступени + ступень`: `artStageTint(stage, drawn)`. У элиты и босса —
   как сейчас, `s0`, тон `null`.
4. `ArtMode.tintOf(slot: number): number | null` — тон текстуры, которую слот
   показывает сейчас (`shown[slot]`, индекс текстуры — `Math.floor(shown / ART_WALK_FRAMES)`);
   слот рисуется фигурой — `null`.
5. `WorldRenderer`:
   - новый кэш `enemySpriteTint: Int32Array` (−1 — без тона), сбрасывается там
     же, где `enemySpriteLook`;
   - в `applyLook` в ветке обычного вида: `tint = art ? this.art.tintOf(index) : null`;
     `null` — `clearTint()`, иначе `setTint(tint)`; ранний выход по кэшу
     сравнивает и тон — смена ступени у слота без смены вида обязана
     перекрасить спрайт.
   Заливки попадания, телеграфа, заморозки и состояния не трогать: они
   важнее тона и после себя возвращают обычный вид.

## Чего не трогаем

- Атласы и `design/art/**` — дорисовка в T-0441.
- `STAGE_LOOKS` и вид фигур (`stageColor`, `stageCore`) — режим без арта не
  меняется.
- Подключение пака `atlas-r157` — придёт с контентом Р157.

## Сценарий и интерфейс

Забег с артом (режим разработчика «Спрайты» или флаг арта): переход времени
на 9-ю и 12-ю минуту (`dev.time.jump`) — враги остаются спрайтами, на s3–s5
темнее, чем на s2. Снимок 390 px на 9-й и 15-й минуте — в PR, если есть
браузер; нет — ревью проверяет сам.

## Тесты

Первым коммитом, `packages/core-game/test/art-atlas.test.ts`:

- `artStageFor`: есть s0–s2 → для 5 даёт 2, для 1 — 1, для 0 — 0; есть только
  s0 → для 4 даёт 0; нет ничего → −1.
- `artStageTint`: `(2, 2)` и `(1, 2)` — `null`; `(3, 2)`, `(4, 2)`, `(5, 2)` —
  не `null`; сумма каналов строго убывает от 3 к 5 (позднее — темнее); каждый
  канал не ниже `0x80` (спрайт не уходит в чёрное пятно); `(4, -1)` — `null`.
- «у обычного врага на любой ступени контента есть кадр»: для каждого врага
  `ENEMIES` без `rank` и каждой ступени `0…STAGES.length − 1` —
  `artStageFor(stage, s => frames.has(enemyFrameName(id, s, 0))) >= 0` по
  кадрам `core` и `late` (как в блоке «атлас покрывает контент»). Это и есть
  проверка «нет фигур, когда есть рисунок s0».
- «рендер красит тон ступени»: по исходнику `WorldRenderer.ts` (как соседний
  тест про `releaseEnemy`) — `applyLook` зовёт `tintOf`, а в кэш вида входит
  тон.
