# T-0176. Лента живых событий — клиент: строка на главной под «Играть»

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0176.json)](README.md#значки-статуса) [![T-0174](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0174.json&label=T-0174)](T-0174-live-feed-backend.md)

## Зачем

Клиентская половина Р114 (`docs/35-stage4-plan.md`) поверх `GET /api/v1/feed`
из T-0174: под кнопкой «Играть» одна короткая строка — «кто-то только что…»,
которая сменяется сама. Игра выглядит живой, и всё в ней настоящее.

## Решения

Р114 (19.10.2026): строка **на главной под кнопкой «Играть»**, событие
сменяется раз в **5–8 секунд**; события настоящие, за последние сутки; имя
как в рейтинге; **событий нет — строки нет**; накрутки нет.

Уточнения `claude-lead2-1` по записанным правилам:

1. **Данные только с сервера** (T-0174): клиент ничего не придумывает и не
   достраивает. Событие старше 24 часов по `at` отбрасывается и на клиенте
   (устройство долго лежало с открытой главной).
2. **Нет входа, нет сети, ответ не разобрался — строки нет.** Пустой ответ —
   тоже. Ошибка не показывается игроку: лента — украшение, а не функция. Прежний
   ответ остаётся на экране, пока идёт новый; при ошибке нового — остаётся
   прежний, пока он не устарел по пункту 1.
3. **Незнакомый вид события** (сервер новее клиента) отбрасывается по одному,
   а не роняет ленту — как слайды главной (`home-api.ts`, `parsed`).
4. **Живая часть главной** (`home-live.ts`): компонент и словарь едут тем же
   чанком, что карусель и виджеты, — первая загрузка за ленту не платит
   (`docs/27` §3.4, `pnpm budget`). Тексты — в `i18n/ru-home.json`.
5. **Своего переключателя в настройках нет.** Строка спокойная, на экране одна,
   не мигает; тот же довод, что у движения виджетов главной (`docs/27` §7.1):
   отдельный выключатель не нужен. Решение записывается в §7.1.
6. **«Меньше движения»** (`prefers-reduced-motion`): события сменяются тем же
   темпом, но без перехода прозрачности — текст заменяется сразу.
7. **В низком ландшафте телефона** (`max-height: 480px`, как у карусели) ленты
   нет: под кнопкой «Играть» там не остаётся места.

Решение claude-lead-1 от 19.10.2026: выключателя ленты в настройках нет (пункт 5);
в низком ландшафте ленты нет (пункт 7).

## Шаги по порядку

1. **Тесты первым коммитом** (раздел «Тесты»).
2. **`state/feed-api.ts`** — по образцу `home-api.ts`:
   ```ts
   export const FEED_KINDS = ["long_run", "week_record", "boss", "chest"] as const;
   export interface FeedItem { id: string; kind: FeedKind; name: string; atMs: number; seconds: number | null }
   export const useFeed = create<{ items: FeedItem[]; refreshSec: number; askedAt: number }>(…)
   export function refreshFeed(now = Date.now(), api = createFeedApi()): Promise<void>
   ```
   - схема ответа `{ events: [{ id, kind, name, at, seconds }], refreshSec }`
     (`zod/mini`); `kind` читается строкой и отбрасывается по одному, если вид
     не из `FEED_KINDS`; `at` разбирается в миллисекунды, нечитаемая дата —
     событие отбрасывается; `name` — непустая строка, обрезается до 64 знаков;
   - `refreshSec` ограничивается 60…3600 (сервер новее или ошибся — клиент не
     начнёт опрашивать каждую секунду);
   - запрос один за раз (`inflight`); без входа (`capabilities.auth ===
     undefined`) запроса нет; офлайн (`useConnection`) — запроса нет;
   - неудача не меняет `items`.
3. **`screens/home-feed-rules.ts`** — чистые функции без React:
   - `freshItems(items, nowMs)` — отбросить старше `FEED_WINDOW_MS = 86_400_000`;
   - `nextHoldMs(random: () => number): number` — `5000 + Math.floor(random() *
     3001)` (5…8 секунд, обе границы достижимы); `random` приходит параметром
     — тест подставляет значения;
   - `nextIndex(items, currentId, count)` — следующий по кругу; если текущий
     пропал из обновлённого списка, начать с нуля; в списке одно событие —
     остаётся оно;
   - `feedTextOf(item): { key: string; params: Record<string, string | number> }`
     — ключ i18n по виду; параметры `name`, `minutes` (`Math.floor(seconds /
     60)`), `time` (`formatDuration(seconds)`).
4. **`screens/home-feed.tsx`** — `HomeFeed` (экспорт из `home-live.ts`):
   - берёт `items` из стора, при монтировании и затем каждые `refreshSec`
     вызывает `refreshFeed`, пока вкладка видна (`document.visibilityState`);
     скрытая вкладка таймеры не держит и при возврате обновляет ленту, если
     прошло больше `refreshSec`;
   - показывает одно событие; пока событий нет (после `freshItems` пусто) —
     `return null`, ни отступа, ни заглушки;
   - сменяет событие по таймеру `setTimeout(nextHoldMs(Math.random))`
     (вне симуляции — `Math.random` здесь допустим), останавливается при
     скрытой вкладке и при размонтировании; единственное событие не
     сменяется;
   - переход: только `opacity` (`transition-opacity` ~200 мс, токены движения
     из `tokens.css`), под `motion-reduce` — без перехода; ничего другого не
     анимируется (`docs/27` §3.3);
   - вид: одна строка по центру под кнопкой, `text-xs`, цвет приглушённого
     текста из токенов, `truncate` (имя длинное — обрезается многоточием, а не
     переносится и не двигает кнопку); отступ сверху — из токенов отступов.
     Никаких цветов и размеров мимо токенов. Строка — не кнопка и не ссылка;
   - доступность: `aria-live="off"` (смена текста раз в несколько секунд
     скринридеру не нужна), текст читается обычным чтением; имя выводится
     текстовым узлом, не разметкой.
5. **`home.tsx`** — `FeedSlot()` по образцу `CarouselSlot`: нет входа → `null`;

## Сценарий и интерфейс

Игрок открывает главную. Через мгновение под «Играть» появляется строка,
например «Игрок: 12 мин в одном забеге». Через 5–8 секунд она плавно (или
мгновенно — при «меньше движения») сменяется следующей, по кругу. Состояния:

- загрузка: ничего нет — строка появится с ответом, заглушки нет;
- пусто (событий за сутки нет): строки нет;
- ошибка: прежняя лента, если она свежая, иначе строки нет; игроку не
  сообщается;
- нет сети: строка не обновляется, остаётся свежее;
- гость без входа и низкий ландшафт: строки нет;
- ограничение аккаунта: на строку не влияет (сервер не отдаёт ограниченных
  игроков в чужие ленты, но видеть ленту им можно).

Макета нет (`design: null`): строка текстовая, визуал — из токенов; если
дизайнеру понадобится иная подача, это отдельная правка поверх.

## Тесты

Пишутся первым коммитом.

- `home-feed-rules.test.ts`:
  - `nextHoldMs`: `random` → 0 → 5000; → 0,999999 → 8000; → 0,5 → 6500;
    никогда меньше 5000 и больше 8000 на ста случайных значениях;
  - `freshItems`: событие ровно 24 ч назад остаётся, на миллисекунду старше —
    нет;
  - `nextIndex`: по кругу 0→1→2→0; текущего нет в списке → 0; одно событие →
    то же; пустой список → `-1`/`null` (как решит сигнатура, но без падения);
  - `feedTextOf`: `long_run` с `seconds: 725` → `minutes: 12`; `week_record`
    с `seconds: 725` → `time: "12:05"`; `boss`, `chest` → только `name`.
- `feed-api.test.ts` (подмена `apiRequest`, как в `home-api.test.ts`):
  - ответ с тремя событиями и одним неизвестного вида → три события;
  - событие с битой датой или пустым именем → отброшено, остальные целы;
  - `refreshSec: 5` → 60, `refreshSec: 999999` → 3600;
  - имя длиннее 64 знаков обрезается;
  - ошибка запроса при ненулевых `items` → `items` те же;
  - два вызова подряд → один запрос; без входа и офлайн → запроса нет;
  - ответ с неверной формой → `items` не меняются, не бросает.
- Рендер `HomeFeed`, если в репозитории есть приём рендера компонентов в
  тестах (`@testing-library/react` или аналог — выяснить по `package.json`
  пакета); если нет, поведение закрывается чистыми функциями выше, а в PR —
  скриншоты на 320, 390, 768 и 1440 px (портрет и низкий ландшафт): с
  событием, с длинным именем (обрезается), без событий (строки нет), с
  прерванным забегом (две кнопки в `footer`).
- В PR — проверка в браузере: смена события через 5–8 с; вкладка скрыта —
  таймеры стоят; `prefers-reduced-motion` — смена без перехода.

## Аналитика

`feed_event_viewed` — какие виды событий игроки успевают увидеть (событие
клиента, словарь `docs/22` §3.3, версия 1): `kind` — вид события, `position`
— место в ленте с нуля. Шлёт клиент, когда событие было на виду не меньше
секунды; не чаще раза на `id` за запуск и не больше 20 за запуск. Полей с именем
или идентификатором игрока нет. В Prometheus ничего не идёт.
