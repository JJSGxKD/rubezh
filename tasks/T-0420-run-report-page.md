# T-0420. Страница отчёта забега в «Разборе забегов» — «Честный», «Аннулировать», «Вернуть забег», «Ограничить игрока»

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0420.json)](README.md#значки-статуса) [![T-0419](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0419.json&label=T-0419)](T-0419-run-report-server.md)

## Зачем

Сейчас строка очереди разбора ведёт в карточку игрока, а решить что-то про
сам забег нельзя. После задачи строка открывает страницу отчёта забега: что
было в забеге, почему проверка его остановила, из чего сложились очки. На
странице действия (Р203):
- «Честный» снимает забег с очереди и возвращает его в текущие доски, если
  он на рейтинговой сложности, без читов и без ограничения;
- «Аннулировать…» убирает его из досок;
- «Вернуть забег…» отменяет аннулирование с причиной;
- «Ограничить игрока…» открывает то же окно, что в карточке игрока.

Сервер — T-0419.

## Решения

- **Р203** (`docs/35-stage4-plan.md`). Исполнитель его не пересматривает.
- **Решения владельца 10.11.2026** (Р203, T-0419): «Честный» возвращает
  годный забег в текущие доски; «Вернуть забег» — отмена аннулирования с
  обязательной причиной; закрытые сезоны не меняются. Панель **говорит
  заранее**, что сделает решение с рейтингом: окно показывает строку
  «Рейтинг» по `rating.returnable` из ответа, а не обещает возврат вслепую.
- **Адрес** — `#/review/<runId>`: раздел `review`, объект — забег, как
  `#/players/<id>` у игрока (`routes.ts`, `Route.id`). Экран раздела сам
  читает `useHashRoute()?.id`: есть — отчёт, нет — очередь.
  `sections.tsx` не меняется.
- **Строка очереди** открывает отчёт: `navigate({ section: "review", id: run.runId })`.
  Имя игрока в строке остаётся текстом; в карточку игрока ведёт ссылка на
  странице отчёта. «Ещё N в очереди» и `BoardMarkBadge` в строке остаются.
- **Права** — по сессии, как в шапке карточки игрока (`can(view, …)`):
  - «Честный», «Аннулировать…» и «Вернуть забег…» — `players.restrict`
    **и** разрешение состояния из ответа (`actions.honest`, `actions.annul`,
    `actions.restore`);
  - «Ограничить игрока…» — `players.restrict` или `players.ban`, окно
    `RestrictDialog` с теми же `canRestrict` и `canBan`;
  - без прав — отчёт без кнопок.
- **«Честный»** — `ConfirmDialog` без поля причины (причина на сервере
  необязательна, а лишнее поле замедляет разбор очереди).
- **«Аннулировать…»** — `ConfirmDialog` с причиной от 1 до 500 знаков
  (`reason`), `tone="danger"`.
- **«Вернуть забег…»** — `ConfirmDialog` с обязательной причиной от 1 до 500
  знаков: она уходит в журнал действий команды (решение владельца).
- **После решения** — страница показывает ответ сервера (отчёт с решением),
  тост и кнопку «← К очереди». Автоматического перехода нет: модератор
  видит, что решение записано.
- **Названия осей очков** — в панели (`run-report-view.ts`), сервер отдаёт
  только ключи `t`, `k`, `h`, `c`, `b`. Стиль — по ключу оси, имена — как в
  `STYLE_NAMES` сервера (`rating/score-rules.ts:20`).
- **Оружие и навыки** — id в `<code>`: словаря имён контента в панели нет.

## Сценарий и интерфейс

Модератор открывает «Разбор забегов», нажимает строку → `#/review/<runId>`.

Страница сверху вниз:

1. **Строка навигации**: `Button` «← К очереди» (`navigate({ section: "review", id: null })`)
   и ссылка «Карточка игрока» (`#/players/<accountId>`, обычная ссылка через
   `hrefOf`: открывается и в новой вкладке).
2. **`Panel` «Забег <первые 8 знаков runId>»** с подсказкой `HELP.review.report`,
   в `actions` — кнопки по правам:
   - «Честный» (`tone="primary"`), только при `actions.honest`;
   - «Аннулировать…» (`tone="danger"`), только при `actions.annul`;
   - «Вернуть забег…» (`tone="primary"`), только при `actions.restore`;
   - «Ограничить игрока…» (`tone="secondary"`).
   Внутри:
   - строка: имя игрока (или короткий id), значок вердикта, значок
     «В рейтинге» / «Не в рейтинге», при решении — `reviewText`;
   - **«Почему остановлен»** — список причин `reasonTitle(code)`; пусто —
     «Причин нет»;
   - **«Итог»** — `KeyValue`: «Сложность» (`difficultyTitle`), «Режим»
     (`endless` — «бесконечный», `prologue` — «пролог», иначе как есть),
     «Время» (`formatDuration`), «Уровень», «Убийств», «Исход» («погиб» /
     «сдался» / «—»), «Причина смерти» (код или «—»), «Начат» (по часам
     сервера; `null` — «старт не дошёл»), «Закончен», «Вторых шансов» (число
     и секунды через запятую), «Читы разработчика» («да» / «нет»), «Рубеж»
     («страж пал на N с» / «страж пришёл, не пал» / «не дошёл»), «Отпечаток
     контента» (`<code>`), «Рейтинг» (`ratingText`);
   - **«Очки»** — нет `score` — «Очков нет: пролог, обучение или сбой
     подсчёта». Иначе `KeyValue`: «Очки» и «Ожидалось» (`expectedPoints` или
     «—»), «Стиль» (`STYLE_TITLES`), «Полоса силы» (`band`); таблица осей
     (ось → `axisText`), строки — «Сила на старте» (`scoreInput.power` или
     «—»), «Оценка сборки» (`scoreInput.buildScore` или «—»), «Охота» —
     таблица журнала (ранг «элита» / «босс», ценность, жил N с) или «—»;
   - **«Ход боя»** — оружие таблицей (`id`, уровень, урон или «—»), навыки
     (`id` и уровень), «Получено урона», «Собрано опыта», «Отрезок
     таймлайна», «Боссов / элит / сундуков / кристаллов», пятёрка врагов.
     `details === null` — «Подробностей нет: сборка до листа забега».
3. **Окно «Честный»** — `ConfirmDialog`: заголовок «Забег честный?»,
   `subject` «<имя> · <runId 8>», `changes` — `honestChanges`; кнопка
   «Честный». Успех — тост `decisionToast`, страница — по ответу.
4. **Окно «Аннулировать»** — `ConfirmDialog`: заголовок «Аннулировать
   забег», `subject` как выше, `changes` — `annulChanges`, `reason`
   `{ min: 1, max: 500, label: "Причина", hint: "Останется в журнале действий" }`,
   кнопка «Аннулировать», `tone="danger"`. Успех — тост «Забег
   аннулирован», страница — по ответу.
5. **Окно «Вернуть забег»** — `ConfirmDialog`: заголовок «Вернуть забег?»,
   `subject` как выше, `changes` — `restoreChanges`, `reason`
   `{ min: 1, max: 500, label: "Причина", hint: "Останется в журнале действий" }`,
   кнопка «Вернуть забег». Успех — тост `decisionToast`, страница — по
   ответу.
6. **Окно «Ограничить игрока»** — `RestrictDialog` с `playerName`,
   `accountId` из отчёта, каталогом и действующими ограничениями, как в
   карточке; `onDone` перечитывает действующие ограничения.

Состояния:
- **загрузка** — `Loading`;
- **забега нет** (`404`) — `Notice` «Забег не найден» и «← К очереди»;
- **ошибка / нет сети** — `ErrorNotice` с «Повторить»;
- **отказ решения** (`409`) — текст сервера в окне, страница перечитывает
  отчёт после закрытия окна;
- **каталог ограничений не загрузился** — кнопки «Ограничить игрока…» нет;
- **без `players.restrict` и `players.ban`** — отчёт без кнопок.

Ширины: 320, 390, 768, 1440 px, ландшафт 667×375 и 640×360 — `KeyValue` и
таблицы переносятся, кнопки в шапке панели переносятся строкой, ничего не
вылезает за край. Снимки отчёта (подозрительный без решения; аннулированный с кнопкой «Вернуть забег…»)
на 390 и 1440 px — в PR, если у потока есть браузер; нет — так и написать.
