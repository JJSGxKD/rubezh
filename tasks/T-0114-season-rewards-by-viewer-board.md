# T-0114. Сезон и награды за места по доске зрителя, призы только внутриигровые

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0114.json)](README.md#значки-статуса) [![T-0110](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0110.json&label=T-0110)](archive/T-0110-weekly-season-server.md) [![T-0113](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0113.json&label=T-0113)](T-0113-boards-by-viewer.md)

## Зачем

Недельный сезон (T-0110) считает одну таблицу на всех. После T-0113 у рейтинга
две доски, и места с наградами должны следовать за ними: обычные игроки
получают награды по общей таблице так, будто аккаунтов с ограничением
«Отдельная доска» нет, а эти аккаунты — по полной и только внутриигровое.

## Решения

Р104, T-0110 («Решения»), решение владельца от 13.10.2026. Исполнитель их не
пересматривает.

- **Две таблицы на сложность.** Общая — рейтинговые аккаунты без ограничения;
  полная — все рейтинговые. Аккаунт попадает в таблицу своей доски и берёт
  место в ней. Принадлежность определяется **в момент закрытия сезона** тем же
  правилом, что живая таблица (`boardOf`): снятое до закрытия ограничение
  возвращает аккаунт в общую.
- **Общая считается без них**: места плотные, `board_size` и порог `MIN_BOARD`
  (T-0110) — по самой таблице. Девять обычных игроков при трёх с ограничением —
  таблица из девяти: награды за место нет, а у тех трёх (полная из двенадцати) —
  есть.
- **Награды те же по виду и размеру**: монеты и престиж по таблице T-0110, без
  отдельных наград, косметики и бейджей этой доски — иначе экран выдаёт
  различие. Порог — тот же и по собственному времени аккаунта.
- **Призы только внутриигровые**: `coins` и `prestige` и ничего больше. Ни
  звёзд, ни TON, ни подарков площадки, ни выводимых начислений, ни реферальных
  и партнёрских выплат. Это проверяется тестом, а не только словами.
- **Ограничение рейтинга сильнее** (T-0110): под видом `leaderboard` или
  блокировкой целиком награды нет, как и было.
- **События T-0110 не меняются**: никакого поля «доска» в `season_closed` и
  `season_reward_claimed`; метка в аналитике — T-0115 и только измерением при
  выборке.
- **Таблица друзей — как обычно**: друзья видны всем друзьям, с их временем
  недели, независимо от доски.

- **Вкладка «Друзья» в сезоне** (находка ревью #327, 14.10.2026): у зрителя со
  скрытым ограничением поле `me` сейчас берётся из общей таблицы недели
  (`seasons-view.service.ts`), и место не совпадает со списком друзей. Считать
  `me` по той же таблице, что отдаётся в ответе.

## Шаги по порядку

1. **Тесты** (раздел «Тесты») — первым коммитом.
2. **Миграция.** `season_result.board varchar(8) not null default 'common'`
   (`'common' | 'full'`); `docs/21-diagrams.md` (ER) в этом же PR. Команда
   `migrate dev --create-only` — один раз, проверить, что папка одна.
3. **Правила.** `season-rules.ts`: `type SeasonBoard = Board`; чистая функция
   `standings(entries, separate: ReadonlySet<string>)` → `{ common, full }`
   (общая — без `separate`, плотные места, ничья по `first_at`); награда
   вычисляется по месту и размеру **таблицы аккаунта**, функции награды
   остаются прежними. Константа `SEASON_REWARD_KEYS = ["coins", "prestige"] as
   const` и тип награды `Pick<…, typeof …>` — награда, в которой есть что-то
   ещё, не собирается.
4. **Живая таблица.** `season-board.store.ts`: вторая проекция
   `seasons:<seasonKey>:full:<сложность>`, общая — прежний ключ. Запись по
   `rating.boardsFor`, чтение по `rating.boardOf` (`scope=all`); `scope=friends`
   не фильтруется. Слушатели ограничения (имена уникальны): наложение вида —
   убрать аккаунт из общей таблицы текущей недели; снятие — пересчитать недельную
   проекцию аккаунта из базы (метод, который T-0110 уже вызывает из `setRanked`).
   `seasons:rebuild` строит обе таблицы.
5. **Закрытие.** `seasons-close.service.ts`: в SQL два ранжирования —
   общее по аккаунтам без действующего вида (`NOT EXISTS (… ACTIVE_RESTRICTION
   … kind = 'separate_board')`) и полное по всем; строка результата берётся из
   общего для первых и из полного для вторых, `board_size` — размер своего
   ранжирования, в `season_result.board` — доска. Остальное (`ON CONFLICT DO
   NOTHING`, одна награда на аккаунт и сезон, исключение аккаунтов под
   ограничением рейтинга) — как в T-0110. Таймауты не менять.
6. **Выдача.** `POST …/claim` не меняется; перед начислением
   `assertInGameReward(reward)` — монеты через кошелёк, больше ничего: ни записей
   в учёт выплат, ни реферальных и партнёрских начислений.
7. **Другие награды за место.** Поиск по `place`, `rank`, `leaderboard` в
   `modules/tasks`, `modules/progress`, `modules/wallet`, `modules/badges` и
   `modules/achievements` (если есть к моменту работы): любая выдача за место
   читает доску аккаунта (`boardOf`). На момент спецификации других нет; если
   найдены, перечислить в PR.
8. **Документы** (раздел «Документы»).

## Сценарий и интерфейс

Экранов нет; экран сезона (T-0111) показывает то, что отдаёт сервер.

- Зритель без ограничения: таблица недели без аккаунтов с ограничением, своё
  место и награда — по ней.
- Зритель с ограничением: полная таблица, место и награда — по ней; выглядит
  так же, без пометок.
- Пусто, нет сети, ошибка — как в T-0110/T-0111.

## Тесты

Первым коммитом. Чистые — `seasons/season-rules.test.ts`, живые —
`seasons.integration.test.ts` на Postgres и Redis.

- `standings`: трое обычных и двое с ограничением (времена вперемешку) →
  общая из троих с местами 1–3, полная из пяти; ничья решена по `first_at`;
  пустое множество `separate` → общая равна полной.
- Закрытие (Postgres): девять обычных и три с ограничением → у обычных
  `board_size = 9`, награды за место нет (меньше `MIN_BOARD`), у трёх —
  `board_size = 12`, `board = 'full'`, награда за место есть; обычный игрок,
  которого аккаунт с ограничением обогнал бы, получает место «как будто его
  нет»; повторное закрытие ничего не вставляет; снятие ограничения до закрытия
  возвращает аккаунт в общую.
- Награда за порог: у аккаунта с ограничением такая же, как у обычного с тем же
  временем.
- Только внутриигровое: у `season_reward` и у начисления после `claim` ровно
  `coins` и `prestige`; в кошельке одна запись с причиной `season_reward` в
  мягкой валюте; нет записей в учёте выплат, реферальных и партнёрских
  начислений.
- Живая таблица: наложение убирает аккаунт из общей, полная его держит; снятие
  возвращает недельное время из базы; `scope=friends` содержит друга с
  ограничением; JSON `GET …/board` у двух зрителей одной формы.
- Аккаунт под `leaderboard` или блокировкой целиком награды не получает ни на
  какой доске.
- События: `season_closed` и `season_reward_claimed` без полей про доску
  (тест схем и `scripts/test/event-dictionary.test.ts` зелёные).
