# T-0363. Кампания и источник у прямых ссылок и ссылок с метками — список игроков, воронка, ежедневный отчёт

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0363.json)](../README.md#значки-статуса)

## Зачем

Игрок может прийти тремя путями:
- по ссылке через переходник — касание `click`;
- по прямой ссылке кампании `l-<код>` — касание `link`, Р95;
- по ссылке с метками, источник которой завёлся сам, — касание `tagged`,
  Р116.

Отчёты знают кампанию только у первого пути:
- список игроков в панели — колонка и фильтр «Кампания» видят только `click`;
- воронка видит `click` и `link`, но не `tagged`;
- ежедневный отчёт в чат команды не знает видов `link` и `tagged` и
  считает таких игроков источником «неизвестно».

После задачи кампания и источник одинаково видны у всех трёх путей.

## Решения

Входящие 13.10 (вопросы 2 и 3 PR #288) и 21.10 (после T-0179, #432).
Решения `claude-lead-1` от 01.11.2026:

- **Откуда кампания:**
  - `click` — `link.campaign` через `link_click`, как сейчас;
  - `link` — `link.campaign` по `link.code = first_start_ref`;
  - `tagged` — `link.campaign` по `link.auto_key = first_start_ref`, как уже
    делает `links.repository.ts:226`.
- **Как назвать в отчётах.** Все три пути — переход по нашей ссылке. В
  ежедневном отчёте они складываются в один источник «по ссылке»
  (`click`), как уже делает воронка для `link` (`funnel-report.ts:68`).
  Делить «переходник / прямая / метки» в чате незачем: разрез — в разделе
  «Ссылки».
- **Фильтр «Кампания»** в списке игроков ищет по всем трём путям.
- **Один источник правды.** Выражение «кампания по касанию» пишется один раз
  — SQL-фрагмент в `funnel-report.ts` или общем модуле атрибуции — и
  используется в трёх местах. Три копии условий — дефект ревью.

## Как сейчас

- `player-list.repository.ts:102–103` — кампания только для `click`;
  `:123–126` — фильтр так же.
- `funnel-report.ts:68–90` — `click` и `link`, `tagged` нет.
- `daily-stats.repository.ts:49` — `SOURCES` без `link` и `tagged`;
  `:102` — неизвестный вид → `unknown`.
- `links.repository.ts:226` — образец соединения `tagged` по `auto_key`.

## Шаги по порядку

1. Тесты первым коммитом.
2. Общий SQL-фрагмент «кампания и источник по первому касанию».
3. Список игроков — колонка и фильтр.
4. Воронка — `tagged`.
5. Ежедневный отчёт — `link` и `tagged` считаются `click`.

## Чего не трогаем

- Постбэки и конверсии сетям (`ad-conversions`): там важен клик сети, у
  прямой ссылки и ссылки с метками клика нет.
- Раздел «Ссылки» и его счётчики.

## Тесты

Интеграционные, на живом Postgres (`docs/17-testing-strategy.md` §4.2):

- `player-list.integration.test.ts`:
  - игроки с касаниями `click`, `link` и `tagged` по ссылкам одной кампании
    — у всех трёх колонка «Кампания» заполнена;
  - фильтр по кампании находит всех троих.
- `funnel.integration.test.ts`: игрок `tagged` попадает в строку своей
  кампании.
- `daily-stats.integration.test.ts`: игроки `link` и `tagged` считаются
  источником «по ссылке», а не «неизвестно».
