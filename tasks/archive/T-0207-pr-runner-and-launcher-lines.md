# T-0207. Строки «Поток» и «Запустил» в описании PR задачи — проверяет pr-check

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0207.json)](../README.md#значки-статуса) [![T-0204](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0204.json&label=T-0204)](T-0204-tasks-archive-folder.md)

## Зачем

Все PR открываются с одного аккаунта GitHub, поэтому по автору PR не
понять, чья это работа. Строка `Поток: …` в описании уже есть по правилам,
но её никто не проверяет, а человека, который запустил поток, не пишут
вовсе. После задачи у каждого PR ветки `task/T-NNNN` есть обе строки, и
`pr-check` не пропускает PR без них. По ним «Вклад» на доске (T-0208)
считает работу и по потокам, и по людям.

## Решения

Решение владельца от 24.10.2026 (разбор входящих, вопрос В4): вклад
считается по кодовому имени потока **и** по человеку, который его запустил.

Решения `claude-lead-1` от 24.10.2026:

- **Две строки в описании PR задачи**, каждая с начала строки:
  - `Поток: claude-N / <модель> / <уровень>` — `N` — номер аккаунта
    (цифры), модель — из `EXECUTORS`, уровень — из `EFFORTS`
    (`scripts/tasks/task-file.mjs`);
  - `Запустил: владелец` или `Запустил: помощник <ник>` — ник от 2 до 32
    символов: буквы, цифры, `_` и `-`. Юзернейм Telegram и настоящее имя
    сюда не пишутся: репозиторий публичный.
- **Проверяются только PR веток `task/T-NNNN`** — как строка `Задача:`.
  PR тимлидов подписываются первой строкой `**claude-…:**`, как сейчас.
- **Доработка — строки нового потока.** Поток, который продолжил PR
  командой `pnpm task resume`, заменяет обе строки своими: задача
  засчитывается тому, кто её закончил, как и поле `owner`.
- **Ошибки `pr-check`** — по одной на строку:
  «поток: в описании нет строки «Поток: claude-N / <модель> / <уровень>»»,
  «поток: «<как написано>» — модель или уровень не из списка»,
  «запустил: в описании нет строки «Запустил: владелец» или «Запустил:
  помощник <ник>»».

## Как сейчас

## Шаги по порядку

1. **`pr-check.mjs`.** `export function checkRunnerLines(body,
   headRefName)` → список ошибок; ветка не `task/T-NNNN` — пусто. Модели и
   уровни — импорт `EXECUTORS` и `EFFORTS` из
   `../tasks/task-file.mjs`. Вызов в `main` рядом с `checkTaskLine`.
2. **`tasks/README.md`:**
   - «Как взять задачу», шаг 10 — вместо строки про поток: «предпоследней и
     последней строками перед подписью агента — `Поток: claude-3 /
     sonnet-5.5 / medium` и `Запустил: владелец` (или `Запустил: помощник
     <ник>`); без них `pr-check` красный»;
   - «Автопоток», «Промт потока» — первая строка промта: «Ты — исполнитель
     проекта «Рубеж», поток claude-N / sonnet-5.5 / medium, запустил:
     владелец.» и в тексте — «в описании PR — строки Поток и Запустил»;
   - «Доработка» — «замени строки `Поток:` и `Запустил:` в описании PR
     своими».
3. **Скилл `take-task`**, «Закрытие» — обе строки; **скилл `pre-pr`** —
   там, где перечислены строки описания PR задачи, — обе строки; **`AGENTS.md`**
   — то же одной строкой.

## Чего не трогаем

- PR тимлидов, дизайнера и служебные PR между `dev` и `main`.
- Подсчёт вклада — задача T-0208.
- Уже влитые PR: строки задним числом не дописываются.

## Тесты

Первым коммитом, `scripts/test/pr-check.test.ts`:

- ветка `task/T-0001`, обе строки верные (`Поток: claude-3 / sonnet-5.5 /
  medium`, `Запустил: владелец`) → ошибок нет;
- `Запустил: помощник ivan_2` → ошибок нет; `Запустил: помощник @ivan` →
  ошибка; `Запустил: помощник` без ника → ошибка;
- нет строки `Поток:` → ошибка «поток: в описании нет строки…»;
- `Поток: claude-3 / gpt-5 / medium` → ошибка «модель или уровень не из
  списка»; `Поток: claude-x / sonnet-5.5 / medium` → ошибка;
- строка `Поток:` не с начала строки (внутри абзаца) → как отсутствие;
- ветка `lead/specs` без строк → ошибок нет.
