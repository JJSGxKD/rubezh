# T-0478. Метрики конвейера — с первого ревью, круги доработки, провалы поезда по причинам

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0478.json)](../README.md#значки-статуса) [![T-0477](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0477.json&label=T-0477)](T-0477-lead-conveyor-in-repo.md)

## Зачем

Конвейер тимлида вливает десятки PR в день, но не видно, где теряется
время: сколько PR проходят ревью с первого раза, сколько кругов доработки
у остальных и почему падают пачки поезда — конфликт в общем документе,
красный CI, флейк. Задача (Р224, F) считает это из данных GitHub и лога
поезда — чтобы чинить спецификации, скиллы и общие файлы по цифрам.

## Решения

- `docs/35-stage4-plan.md`, **Р224** (F).
- Метрики за период (`--since`, по умолчанию сутки):
  - **с первого ревью** — доля PR задач, влитых без метки «доработка» и
    без комментария доработки **claude-lead-…:**;
  - **круги доработки** — медиана и максимум на PR;
  - **время до мерджа** — медиана от открытия PR;
  - **провалы поезда** — по причинам из `.lead/train-failed.txt`:
    конфликт (с разбивкой по файлам — топ-5), красный свой CI, красная
    пачка, сеть;
  - **пачки** — сколько, средний размер, доля зелёных.
- Вывод — Markdown для чата команды; отправляет человек.
