# T-0075. Награда дня сама обновляется на смене суток по Москве

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0075.json)](../README.md#значки-статуса)

## Зачем

Игрок забрал награду дня вечером и оставил экран открытым. В полночь по Москве
отсчёт на кнопке прыгает с «Следующая — через 1 мин» на «через 1 д», а кнопка
остаётся неактивной, хотя новая награда уже доступна: экран получил награду один
раз при открытии и больше не спрашивает. Приёмка PR #245 (T-0007), 13.10. После
задачи экран сам перечитывает награду на смене суток, и «Забрать» оживает без
перезахода.

## Решения

- **Перечитываем один раз на каждые сутки** — таймером на момент смены суток,
  а не проверкой на каждом тике часов. Так же сделано на главной
  (`useMidnightRefresh` в `screens/home-widgets.tsx`): граница суток — по
  Москве (`msUntilReset(…, "daily")`, `screens/meta/schedule.ts`) плюс запас
  5 секунд, чтобы разница часов телефона и сервера не вернула вчерашний ответ.
- **Таймер считается от момента, когда награда была получена**, а не от
  момента запуска эффекта: если ответ пришёл за секунду до полуночи, а эффект
  отработал уже после, таймер по `Date.now()` пропустил бы эту полночь и
  показал вчерашнее ещё сутки.
- **Перечитывание тихое**: экран не уходит в «Загружаем награду…» и не
  перерисовывает дни, пока ответ не пришёл. Не вышло — как при обычной
  ошибке загрузки: «Не удалось загрузить награду — проверьте связь» с
  «Повторить» (ключ `daily.failed`, новых текстов нет). Оставлять вчерашнюю
  неделю нельзя: она врёт про «через 1 д».
- Часы и отсчёт на кнопке (`useClock`, T-0007) не меняются.

## Шаги по порядку

1. **Тесты первым коммитом** (раздел «Тесты»): новый файл
   `packages/app-shell/test/daily-reload.test.ts`. Он падает — модуля ещё нет.
2. **Новый файл `packages/app-shell/src/screens/meta/daily-reload.ts`:**

   ```ts
   import { msUntilReset } from "./schedule";

   /**
    * Когда перечитать награду дня после смены суток по Москве
    * (tasks/T-0075). Запас — как на главной (`home-widgets.tsx`,
    * `MIDNIGHT_SLACK_MS`): часы телефона могут обгонять сервер, и ответ в
    * первую секунду полуночи ещё вчерашний.
    */
   export const DAILY_RELOAD_SLACK_MS = 5_000;

   /**
    * Через сколько миллисекунд перечитать награду, полученную в `loadedAtMs`.
    * Считается от момента получения, а не от `nowMs`: смена суток, которая
    * успела наступить между ответом и запуском таймера, не теряется — тогда
    * ответ 0, то есть сразу.
    */
   export function dailyReloadDelayMs(loadedAtMs: number, nowMs: number): number {
     const target = loadedAtMs + msUntilReset(loadedAtMs, "daily") + DAILY_RELOAD_SLACK_MS;
     return Math.max(0, target - nowMs);
   }
   ```
3. **`daily.tsx`, импорт:** `import { dailyReloadDelayMs } from "./daily-reload";`
   рядом с `./schedule`.
4. **`daily.tsx`, тип (строка 26):** в состояние `ready` добавить момент
   получения:

   ```ts
   type Loaded = { status: "loading" } | { status: "failed" } | { status: "ready"; view: DailyView; loadedAt: number };
   ```
5. **`daily.tsx`, `load` (строки 36-40):** параметр «тихо», по умолчанию нет:

   ```ts
   const load = async (silent = false): Promise<void> => {
     if (!silent) setState({ status: "loading" });
     const response = await api.view();
     setState(response.ok ? { status: "ready", view: response.data, loadedAt: Date.now() } : { status: "failed" });
   };
   ```

   Остальные вызовы `load()` (первый в эффекте и «Повторить» у `ErrorState`)
   остаются без аргументов.
6. **`daily.tsx`, `claim` (строка 56):**
   `setState({ status: "ready", view, loadedAt: Date.now() });`
7. **`daily.tsx`, новый эффект** — сразу после существующего
   `useEffect(…, [])` (строка 44), до `claim`:

   ```ts
   const loadedAt = state.status === "ready" ? state.loadedAt : null;
   // Сутки сменились — награда новая. Перечитываем один раз; ответ ставит
   // новый `loadedAt`, и эффект заводит таймер на следующие сутки.
   useEffect(() => {
     if (loadedAt === null) return;
     const timer = setTimeout(() => void load(true), dailyReloadDelayMs(loadedAt, Date.now()));
     return () => clearTimeout(timer);
   }, [loadedAt]);
   ```

## Сценарий и интерфейс

Экран «Награда дня» открыт в 23:58 по Москве, награда сегодняшнего дня забрана.

- До полуночи как сейчас: «Следующая — через 2 мин», отсчёт тикает.
- В 00:00:05 по Москве экран без «Загружаем…» перечитывает награду. Приходит
  новый день: «Забрать» активна, сегодняшняя ячейка подсвечена.
- Не вышло перечитать (нет связи): вместо недели «Не удалось загрузить награду
  — проверьте связь» и «Повторить», как при обычной ошибке загрузки. Общая
  плашка «Нет связи» (T-0015) при этом стоит над ними — это принято
  (`tasks/inbox.md`, пункт про две ошибки разом).
- Экран закрыт — таймер снят, запроса нет.

Состояния «загрузка», «пусто» и «ограничение аккаунта» не меняются.

## Тесты

Первым коммитом. `packages/app-shell/test/daily-reload.test.ts`, времена — через
`Date.parse("…Z")`. Полночь по Москве — 21:00 UTC (`meta-schedule.test.ts`).

- «до полуночи ждём остаток суток и запас»: награда получена в
  `2026-09-14T12:00:00Z`, сейчас то же время → `32_405_000`
  (9 ч до полуночи по Москве и 5 с запаса).
- «таймер заводится позже ответа — задержка короче»: получена в
  `2026-09-14T20:59:00Z`, сейчас `2026-09-14T20:59:30Z` → `35_000`.
- «смена суток уже прошла — сразу»: получена в `2026-09-14T20:59:00Z`, сейчас
  `2026-09-14T21:10:00Z` → `0` (не отрицательное число).
- «ответ после полуночи — следующая смена через сутки»: получена и сейчас в
  `2026-09-14T21:00:05Z` → `86_400_000`.
- «ровно в полночь следующая смена через сутки с запасом»: получена и сейчас в
  `2026-09-14T21:00:00Z` → `86_405_000`.
- «запас — константа»: `DAILY_RELOAD_SLACK_MS` равен `5_000`.

оболочки нет.
