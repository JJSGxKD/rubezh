# T-0142. Бюджет экранов — порог на самый большой экран, сумма — предупреждением

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0142.json)](../README.md#значки-статуса)

## Зачем

Порог «Экранов по требованию» — сумма всех ленивых чанков. Она растёт с каждой
новой фичей по определению, и порог приходится поднимать каждой пачкой: #292,
#253, #330 (`tasks/inbox.md`, 14.10). Такой порог не ловит главного — один
раздутый экран, который игрок ждёт при открытии. И мешает: исполнители
упираются в него, хотя ничего не раздули.

## Решения

Решение `claude-lead-1` от 14.10.2026:

- **Проваливает гейт** самый большой ленивый чанк экрана: «Самый большой
  экран» — порог на один чанк из группы «Экраны по требованию». Порог —
  замер на `dev` плюс 15%, округлённый вверх до 0,5 КБ, с комментарием, какой
  чанк самый большой.
- **Сумма остаётся строкой отчёта, но предупреждением.** Строка «Экраны по
  требованию, всего» с прежним числом печатается с пометкой «следим» и гейт не
  проваливает. Расти ей можно, смотреть — нужно.
- Первая загрузка, интерфейс забега, движок, звук, реклама, шрифты и CSS — как
  сейчас.

## Как сейчас

- `scripts/bundle-budget.mjs`: группы `{ name, limitKb, matches }`
  (строки 131–317), «Экраны по требованию» — `limitKb: 145` (строка 282);
  `main` (строка 355) печатает строки и выходит с кодом 1 при `kb > limitKb`
  (строки 379–398).
- Тестов скрипта бюджета нет.

## Шаги по порядку

1. **Тесты первым коммитом.** Вынести расчёт строк отчёта в чистую функцию
   (`budgetRows(files, groups)` → строки `{ name, kb, limitKb, kind: "fail" | "watch" }`)
   и покрыть её тестом. Новый `scripts/test/bundle-budget.test.ts`: сумма
   чанков группы, самый большой чанк, превышение «fail» → код 1, превышение
   «watch» → только пометка.
2. **Группа «Самый большой экран»** — `kind: "fail"`, мера — максимум по чанкам
   группы экранов. Порог — по замеру (`pnpm build`, затем `pnpm budget`), +15%,
   округлить вверх до 0,5 КБ. В комментарии — имя самого большого чанка и замер.
3. **«Экраны по требованию»** — `kind: "watch"`, подпись «всего», порог
   прежний (145) как ориентир.
4. **Вывод:** у строк «watch» вместо «ПРЕВЫШЕН» — «следим», код выхода от них не
   зависит.
5. **Документы:** `docs/27` §3.4 — абзац о новом пороге и о том, что сумма
   стала предупреждением; таблица бюджета — новая строка. `CLAUDE.md`,
   «Сборка и проверка перед PR»: фразу о бюджете не менять, если она остаётся
   верной; иначе поправить одной строкой.
