# T-0351. Задел — брать задачу до мерджа зависимостей, ветка поверх их веток, метка «задел», доводка первой в очереди

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0351.json)](../README.md#значки-статуса) [![T-0349](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0349.json&label=T-0349)](T-0349-self-merge-command.md)

## Зачем

Задачу можно взять, только когда все её зависимости `done` в `dev`, то есть
влиты. Пока зависимость ждёт ревью, задачи за ней стоят, и облачные потоки
простаивают (Р177: на 28.10.2026 свободных задач `any` не было вовсе, восемь
задач ждали только PR, уже отправленных на ревью). Владелец решил (Р178):
следующую задачу можно начинать **заделом** — поверх веток зависимостей, —
а довести, когда они влиты.

## Решения

Решение владельца **Р178** (`docs/35-stage4-plan.md`, 28.10.2026), детали —
`claude-lead-1`:

1. **Когда можно взять заделом:** задача `ready`, у каждой её незакрытой
   (`status` не `done`) зависимости есть открытый PR со статусом «на ревью»,
   «ждёт владельца» или «доработка», и сама эта зависимость **не задел**
   (одна ступень). Зоны — как у обычного захвата (Р171).
2. **Ветка задела:** от `origin/dev`, затем `git merge --no-edit` каждой ветки
   незакрытой зависимости `origin/task/T-XXXX` по порядку `depends_on`.
   Конфликт между ветками зависимостей — захват отменяется: «ветки
   зависимостей конфликтуют друг с другом — возьми другую задачу».
3. **Метка статуса «задел»** — пятая в `STATUS_LABELS` (Р172). PR задела —
   всегда черновик. Задел **не держит зон** — как «на ревью».
4. **Доводка:** когда все зависимости задела `done` в `dev`, задел встаёт в
   `pnpm task next` сразу после доработки, раньше свободных задач. Берёт его
   любой поток той же модели и уровня: `pnpm task resume T-NNNN` вливает
   свежий `origin/dev` в ветку и меняет «задел» на «в работе». Поток
   доделывает, проходит гейт, снимает черновик и ставит «на ревью».
5. **Влить задел до зависимостей нельзя:** `claim-check` в CI красный, если
   у PR незакрытые зависимости и он не черновик или без метки «задел»;
   `pnpm task merge` (T-0349) отказывает, если хоть одна зависимость в `dev`
   не `done`.
6. **Зоны задела в CI:** `diff-check` вычитает из диффа задела файлы, которые
   меняют PR его незакрытых зависимостей (`git diff --name-only origin/dev...origin/task/T-XXXX`):
   их проверяет PR самой зависимости.
7. **Зависимость закрыли без мерджа** (PR закрыт, задача `cancelled`) — задел
   на доске в «Ждут» с причиной «зависимость T-XXXX закрыта без мерджа»;
   решает тимлид.

## Критерии приёмки

- [ ] Задачу с зависимостями на ревью можно взять `--ahead`, ветка содержит ветки зависимостей.
- [ ] Задел — черновик с меткой «задел», зон не держит, на доске своя колонка.
- [ ] Созревший задел — первым после доработки в `pnpm task next`, `resume` вливает `dev`.
- [ ] Влить или снять с черновика задел с невлитыми зависимостями нельзя — CI и `pnpm task merge` отказывают.
- [ ] `diff-check` задела не ругается на файлы зависимостей.

  Задачу, чьи зависимости уже на ревью, можно взять заделом: `pnpm task claim T-NNNN --ahead` строит ветку поверх веток зависимостей, черновик PR получает метку «задел» и зон не держит (Р178).   ```
