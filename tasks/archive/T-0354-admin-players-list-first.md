# T-0354. Панель «Игроки» — список новых сразу, фильтры свёрнуты в строку с чипами активных

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0354.json)](../README.md#значки-статуса)

## Зачем

Сейчас раздел «Игроки» открывается пустым списком: чтобы увидеть хоть
кого-то, нужно нажать «Показать». Над списком при этом раскрыты 13 фильтров,
и на телефоне они занимают два экрана. После задачи список новых игроков
загружается сразу. Фильтры свёрнуты в одну строку, а активные фильтры видны
чипами, и каждый снимается крестиком.

## Решения

Находка AD-03 аудита дизайнера (`design/art/direction-v2.md` §4.6).
Решения `claude-lead-1` от 01.11.2026:

- **Список сразу.** При первом открытии раздела загружается список с
  `EMPTY_FILTERS` (новые сверху), одной страницей того же размера, что
  сейчас (`limit` в `listQuery` не меняется). Вернулись из карточки игрока —
  список и фильтры прежние, повторной загрузки нет: хранилище `useList` уже
  переживает переход.
- **Фильтры свёрнуты.** Над списком — строка «Фильтры» (кнопка с числом
  активных: «Фильтры · 2») и чипы активных фильтров. Кнопка раскрывает ту же
  форму, что сейчас, без изменения полей и проверок (`filtersProblem`).
  «Показать» загружает и сворачивает форму. Состояние «раскрыто» — локальное,
  при входе в раздел форма свёрнута.
- **Чипы.** Чип — «Подпись: значение ×», например «Платящий: да ×»,
  «Уровень: 3–10 ×», «Регистрация: 01.10–15.10 ×», «Кампания: spring ×».
  Порядок и направление сортировки чипами не показываются: это не фильтр.
  Крестик снимает фильтр и сразу загружает список заново. «Сбросить» у
  чипов есть, только когда чипов два и больше: снимает все.
- **Пары полей — одним чипом:** уровень от–до, регистрация с–по, «заходил»
  с–по. Задано одно поле — «Уровень: от 3», «Регистрация: по 15.10».
- **Подписи — одним источником.** Подписи полей формы и чипов берутся из
  одной таблицы в `list-filters.ts`, чтобы они не разошлись. Названия видов
  ограничений — из справочника, как сейчас (`kindTitle`).

## Шаги по порядку

1. **Тесты первым коммитом** — раздел «Тесты».
2. **`list-filters.ts`** (новый, чистые функции, без React):
   - `filterChips(filters, kindTitle): FilterChip[]`, где
     `FilterChip = { key: string; label: string; clear: (filters) => PlayerListFilters }`;
   - таблица подписей полей, общая с формой.
3. **`PlayerList.tsx`**:
   - загрузка при монтировании, если `listed.status === "idle"`;
   - строка «Фильтры · N» с чипами;
   - форма — под кнопкой, свёрнута по умолчанию;
   - подсказку состояния `idle` убрать: экран в нём больше не бывает дольше
     первого кадра.
4. Подписи полей формы — из таблицы `list-filters.ts`.

## Чего не трогаем

- Поиск по имени и ID (`PlayerSearch.tsx`), карточку игрока.
- Сервер и запрос списка: `listQuery`, размер страницы.
- Общий компонент чипов для других разделов — заведём, когда понадобится
  второму разделу.

## Сценарий и интерфейс

- **Открыл раздел** — «Загрузка…», затем список новых игроков. Над ним —
  кнопка «Фильтры» без числа, чипов нет.
- **Нажал «Фильтры»** — под строкой раскрывается форма. Заполнил её,
  нажал «Показать» — форма свернулась, появились чипы, кнопка показывает
  «Фильтры · 3».
- **Нажал × на чипе** — чип пропал, список перезагрузился.
- **Ошибка загрузки** — `ErrorNotice` с «Повторить», как сейчас.
- **Пусто под фильтры** — «Под фильтры никто не подходит», чипы видны:
  сразу понятно, что снять.
- **Телефон, 390 px** — чипы переносятся строками, боковой прокрутки нет
  (`node design/art/src/admin-overflow.mjs`).

## Тесты

Первым коммитом, `apps/admin/test/player-list-chips.test.ts`:

- `EMPTY_FILTERS` → чипов нет;
- `payer: "yes"` → один чип «Платящий: да»; его `clear` даёт `payer: ""`;
- `levelMin: "3"`, `levelMax: "10"` → один чип «Уровень: 3–10»; `clear`
  очищает оба поля;
- только `registeredTo: "2026-10-15"` → «Регистрация: по 15.10»;
- `restricted: "chat"` с `kindTitle` → подпись из справочника;
  `restricted: "any"` → «Ограничения: есть»;
- `sort` и `order` не дают чипов;
- подписи чипов совпадают с подписями полей формы (одна таблица).
