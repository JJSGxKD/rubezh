# T-0474. pnpm verify — отчёт проверки для PR, который пишет скрипт, а не агент

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0474.json)](../README.md#значки-статуса)

## Зачем

В описании PR исполнитель отмечает «[x] Гейт и docs:check зелёные». Ревью
13.11.2026 трижды нашло, что это неправда: гейт красный, а галочка стоит
(#738, #748, #755). Ревьюер тратит круг на то, что мог бы проверить скрипт.
Задача даёт `pnpm verify` (Р224, B): скрипт сам прогоняет нужные проверки
по затронутым пакетам и печатает отчёт, который вставляется в PR как есть.

## Решения

- `docs/35-stage4-plan.md`, **Р224** (B).
- Отчёт пишет **скрипт**; агент его не правит. В отчёте — голова коммита,
  на которой он снят: если после отчёта были коммиты, он устарел, и
  ревьюер это видит.
- Проверки — **только затронутые пакеты** (по диффу с `origin/dev`): весь
  `pnpm test` на общей машине с шестью агентами слишком долог; полный
  прогон остаётся за CI.
- Интеграционные тесты с базой — по флагу `--db` и только при
  `TEST_DATABASE_URL` на `rubezh_test` (иначе строка «не запускались —
  проверит CI»).

## Как сейчас

- Гейт — `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`,
  `pnpm budget` (`CLAUDE.md`, «Сборка и проверка перед PR»); зоны —
  `node scripts/tasks/task.mjs diff-check --base origin/dev`;
  `pnpm docs:check`.
- Скилл `pre-pr` описывает гейт словами.

## Шаги по порядку

1. `scripts/verify/verify.mjs`:
   - затронутые пакеты — по `git diff --name-only origin/dev...HEAD`
     (пакет — ближайший `package.json`); корневые конфиги задевают всё;
   - шаги: `pnpm typecheck` из корня (один на всё, тесты входят), eslint
     затронутых файлов, `vitest run` по затронутым пакетам, `pnpm build` и
     `pnpm budget`, если затронута оболочка или панель, `diff-check` зон,
     `pnpm docs:check`; каждый шаг — с таймаутом и временем;
   - итог — Markdown-блок:

     ```
     ## Проверено (pnpm verify)

     Голова: 7ff1fbe8 · 13.11.2026 14:02 UTC · Windows

     | Шаг | Итог | Время |
     |---|---|---|
     | typecheck | ✅ | 1 м 12 с |
     | lint (14 файлов) | ✅ | 9 с |
     | тесты core-game, app-shell | ❌ 2 упали | 2 м 40 с |
     | build + budget | ⏭ не затронуты | — |
     | зоны задачи | ✅ | 2 с |
     | docs:check | ✅ | 4 с |
     | интеграция с базой | ⏭ не запускались — проверит CI | — |

     Упало: packages/core-game/test/art-atlas.test.ts > …
     ```

   - код выхода — 0, только если всё ✅ или ⏭;
   - `--write <файл>` — сохранить блок; без флага — в stdout.
2. `package.json`: `"verify": "node scripts/verify/verify.mjs"`.
3. Скиллы: `pre-pr` и `take-task` — вместо «прогони гейт и отметь» —
   «`pnpm verify`, блок — в описание PR как есть; при красном — чинить, а
   не отмечать»; `review-pr` — «нет блока `## Проверено` или его голова не
   совпадает с головой PR — первое замечание, дальше не читать».
4. `tasks/README.md` и `CLAUDE.md` («Сборка и проверка перед PR») — строка
   про `pnpm verify`.

## Чего не трогаем

- CI и его шаги — проверка в CI остаётся полной.
- Сам гейт: команды те же, меняется только то, кто пишет отчёт.

## Сценарий и интерфейс

- Исполнитель перед PR: `pnpm verify --write verify.md` → вставляет блок в
  описание. Ревьюер видит ❌ и голову коммита — возвращает без чтения
  диффа.

## Тесты

Первым коммитом `scripts/test/verify.test.ts`: определение затронутых
пакетов по списку файлов (файл пакета, корневой конфиг, документ);
сборка отчёта из результатов шагов (✅, ❌ с первыми упавшими тестами, ⏭);
код выхода; голова и время в шапке.
