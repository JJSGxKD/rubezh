# T-0371. Брошенный захват — ветка без работы дольше суток не держит зоны, задачу можно перехватить

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0371.json)](../README.md#значки-статуса)

## Зачем

Поток берёт задачу (`pnpm task claim`), упирается в лимит аккаунта или
пропадает — и ветка `task/T-NNNN` с одним коммитом захвата висит днями. Пока она
есть, задача считается занятой, а её зоны держат все задачи, которые с ней
пересекаются: на 06.11.2026 захват T-0070 трёхдневной давности без единой правки
блокировал срочную T-0181. Удалить чужую ветку из облачной сессии нельзя. После
задачи такой захват сам перестаёт держать зоны и задачу можно перехватить
обычной командой.

## Решения

Решение владельца от 06.11.2026: «захват задачи больше определённого времени без
внесённых изменений значит, что взявший ушёл в лимиты или ещё что, — задачу
можно перехватывать, чтобы не блокировать потоки». Числа и правила — решения
`claude-lead-1` от того же дня, исполнитель их не пересматривает.

1. **Брошенный захват** — все четыре условия сразу:
   - на `origin` есть ветка `task/T-NNNN`;
   - открытого PR из этой ветки нет;
   - дифф ветки против базы (`git diff --name-only <база>...origin/task/T-NNNN`)
     меняет **только** файл самой задачи (`tasks/T-NNNN-*.md`) — то есть
     в ветке только захват;
   - последний коммит ветки (`%cI`) старше **24 часов**: константа
     `ABANDONED_CLAIM_HOURS = 24` в `claim.mjs`, с комментарием «почему»
     (лимит аккаунта сбрасывается за 5 часов, сутки — запас на ночь и выходной
     человека).

   Любой другой коммит в ветке (код, тест, документ) или открытый PR любого
   вида — захват живой, как сейчас. Время захвата неизвестно (`git` не
   ответил) — захват живой.
2. **Чистая функция** `isAbandonedClaim({ changedFiles, lastCommitAt, hasOpenPr,
   taskFileName, now })` в `claim.mjs` — правило решения 1 без обращений к git;
   её проверяют тесты.
3. **Сбор данных** — в `git-io.mjs`, `loadRegistryState`: для каждого id из
   `taken` — изменённые файлы и время последнего коммита ветки; в состоянии —
   `abandoned: Set<string>` id брошенных захватов. Два вызова `git` на ветку,
   веток — десятки: отдельного кэша не нужно.
4. **Брошенный захват не держит зоны:** `checkClaim` пропускает такие задачи
   так же, как PR на ревью (`waitsForReview`). Сообщение для живых захватов не
   меняется.
5. **Доска и подсказки.** `classify` (`board.mjs`) показывает брошенную задачу
   свободной, с пометкой: в `pnpm task next` строка задачи кончается
   «брошенный захват <owner из ветки>, <сколько часов назад>»; `pnpm task
   streams` считает её свободной. Колонки доски — по тому же правилу.
6. **Перехват** — обычной командой `pnpm task claim T-NNNN --owner "…"`. Если
   ветка задачи есть и захват брошен, команда не отказывает, а:
   1. `git fetch origin task/T-NNNN`, локальная ветка `task/T-NNNN` от
      `origin/task/T-NNNN`;
   2. `git merge --no-edit origin/dev`;
   3. в файле задачи `owner` — новый, `status: in-progress`;
   4. коммит `chore(tasks): Перехватить T-NNNN — захват брошен` (в теле —
      прежний `owner` и время его коммита);
   5. `git push origin HEAD:refs/heads/task/T-NNNN` **без `--force`**: ветка
      только растёт, а если прежний владелец успел запушить работу, push
      отклонится, и команда скажет «захват ожил — выбери другую задачу».

   Живой захват — отказ, как сейчас.
7. **`claim-check` в CI** принимает PR перехваченной задачи: время захвата —
   коммит «Перехватить …», если он есть (`claimedAt` ищет оба заголовка).
8. **Не удаляем чужие ветки.** Ни команда, ни CI ветку прежнего владельца не
   удаляют: перехват — это коммит сверху, история захвата остаётся.

## Как сейчас

- `scripts/tasks/claim.mjs`: `checkClaim` — зоны держат задачи с веткой или
  открытым PR, кроме PR на ревью (`waitsForReview`); `claimTime`.
- `scripts/tasks/git-io.mjs`: `takenIds` (ветки `task/*` на origin),
  `claimedAt(id)` (время коммита «Взять T-NNNN в работу»), `loadRegistryState`.
- `scripts/tasks/board.mjs`: `classify(tasks, taken, prs, repoFiles, epicOrder)`.
- `scripts/tasks/task.mjs`: `runClaim`, `runNext`, `runStreams`, `runRelease`.
- Тесты — `scripts/test/tasks-claim.test.ts`, `tasks-board.test.ts`.

## Шаги по порядку

1. Тесты первым коммитом (раздел «Тесты»).
2. `claim.mjs` — `ABANDONED_CLAIM_HOURS`, `isAbandonedClaim`, пропуск в
   `checkClaim`.
3. `git-io.mjs` — сбор `abandoned` в `loadRegistryState`, `claimedAt` с
   перехватом.
4. `board.mjs` — свободная колонка и пометка.
5. `task.mjs` — перехват в `runClaim`, пометка в `next`.
6. `tasks/README.md`, раздел «Как взять задачу»: подпункт «Брошенный захват» —
   правило решения 1, что делает перехват, и что прежнему владельцу,
   вернувшемуся к задаче, писать тимлиду, а не пушить поверх. Скилл `take-task`
   — одна строка о том же.

## Тесты

`scripts/test/tasks-claim.test.ts`:

- `isAbandonedClaim`: только файл задачи, 25 ч, без PR — `true`; 23 ч — `false`;
  файл задачи и ещё один файл — `false`; открытый PR — `false`; время
  неизвестно — `false`; файл задачи из архива (`tasks/archive/…`) считается
  файлом задачи;
- `checkClaim`: задача A пересекается зонами с B; захват B брошен — A можно
  брать; захват B живой (свежий или с работой) — прежняя ошибка «зоны
  пересекаются».

`scripts/test/tasks-board.test.ts`: брошенная задача — в свободных, с пометкой;
живая — в работе.

Перехват (`runClaim`) — функцией, которой передан `git` (как устроены прочие
тесты команд): ветка есть и захват брошен — merge, коммит «Перехватить …»,
push без `--force`; push отклонён — сообщение «захват ожил».
