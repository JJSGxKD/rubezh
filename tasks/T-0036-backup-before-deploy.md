# T-0036. Свежий бэкап базы перед каждым выкатом

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0036.json)](README.md#значки-статуса)

## Зачем

Новая версия API применяет миграции при старте контейнера (`entrypoint`:
`prisma migrate deploy`). Перед этим `deploy.sh` не делает бэкап. Ближайший
дамп — ночной в 03:17, а миграция, испортившая данные, днём съест всё, что
игроки сделали с ночи. `docs/09-ci-cd.md` §10 требует «перед миграцией прода —
свежий бэкап», в скрипте этого шага нет. Пункт аудита.

## Решения

- **Перед подъёмом новой версии API — всегда дамп**, даже если новых миграций
  нет. Выкаты прода редкие: только стабильные релизы из `main`. База на тесте
  маленькая, дамп занимает секунды. Узнавать, есть ли новые миграции, — лишняя
  сложность.
- **Дамп не сделался — выкат останавливается до миграций.** API остаётся на
  прежней версии, как при нехватке места (`ensure_space`).
- **Аварийный обход** — `./deploy.sh <версия> --no-backup`. Только руками, с
  предупреждением в логе выката. Workflow выката флаг не передаёт.
- **Дамп перед выкатом — только на диск сервера,** владельцу в бота не
  отправляется: ночной дамп уходит и так. Хранятся последние 3 таких дампа,
  отдельно от 14 ночных.
- Тот же `backup.sh`, режимом `--before-deploy <версия>`: шифрование ключом
  владельца (`age -R backup-recipient.pub`) и формат — как у ночного.

## Как сейчас

- `infra/prod/deploy.sh`:
  - `VERSION="${1:?…}"` — версия первым аргументом;
  - `ensure_space` (строки 124–131) останавливает выкат до миграций, если
    места меньше `MIN_FREE_MB`;
  - выкат API — строки 133–162: `prune_api_images`, `ensure_space`,
    `docker compose pull api`, ещё раз `ensure_space`,
    `set_env_value API_TAG "$VERSION"`, затем
    `docker compose up -d --wait --wait-timeout 180 … api`.
    Не поднялся — возврат на прежний тег.
- `infra/prod/backup.sh`:
  - ночной дамп: `pg_dump --format=custom` в контейнере Postgres →
    `age -R backup-recipient.pub` → `${OUT}/rubezh-<stamp>.dump.age`;
  - отправка владельцу в бота, если влезает в лимит;
  - `report` в чат администраторов;
  - локально последние `KEEP_LOCAL=14`;
  - ошибка → `trap on_error ERR` и отчёт «❌ Бэкап базы не сделан».
- Тестов на shell-скрипты нет. Есть тест по тексту инфраструктуры —
  `scripts/test/image-pins.test.ts`. Образец чтения файла — там же.

## Шаги по порядку

1. Тест первым коммитом (раздел «Тесты»).
2. **`backup.sh` — режим перед выкатом:**
   - разбор аргументов в начале: `--before-deploy <версия>` →
     `mode=before-deploy`, `release=<версия>`. Без аргументов — `mode=nightly`,
     поведение прежнее. Неизвестный аргумент — ошибка и выход 2;
   - в режиме `before-deploy`:
     - файл — `${OUT}/rubezh-pre-<stamp>-<версия>.dump.age`. В версии
       допустимы только `[0-9A-Za-z.+-]`, иначе ошибка;
     - дамп и шифрование — те же команды, что у ночного;
     - отправки владельцу и отчёта в чат нет; `trap on_error` — тоже нет.
       Об ошибке скажет выкат: код выхода не 0;
     - файл пустой (`[ ! -s "$file" ]`) — ошибка;
     - ротация: оставить 3 последних `rubezh-pre-*.dump.age`;
     - в конце — строка в stdout: `бэкап перед выкатом: <файл>, <размер>`;
   - ротация ночных (`ls -1t "${OUT}"/rubezh-*.dump.age`) не должна захватывать
     `rubezh-pre-*`. Шаблон ночных — `rubezh-2*.dump.age`: штамп начинается с
     года. Иначе дампы перед выкатом вытеснят ночные.
3. **`deploy.sh`:**
   - разбор: `VERSION="${1:?…}"`, второй аргумент — только `--no-backup`,
     иначе ошибка;
   - сразу после второго `ensure_space`, **до** `set_env_value API_TAG`:

     ```bash
     if [ "$skip_backup" = yes ]; then
       log "⚠️ выкат без бэкапа (--no-backup) — только для аварий"
     elif ! "${APP}/backup.sh" --before-deploy "$VERSION"; then
       log "бэкап перед выкатом не сделан — выкат остановлен до миграций, API остаётся на ${previous:-прежней версии}"
       exit 1
     fi
     ensure_space
     ```

     Повторный `ensure_space` нужен: дамп занял место;
   - комментарий над блоком — почему дамп именно здесь: миграции
     применяются при старте нового контейнера, следующей строкой.
4. **Документы** — раздел «Документы».

## Чего не трогаем

- Ночной бэкап, его отправку и отчёт: поведение без аргументов — прежнее.
- PITR и `backup-watch.sh`.
- `deploy.yml`: он зовёт `deploy.sh <версия>` без флагов.
- Откат на прежний тег.

## Тесты

Первым коммитом, новый `scripts/test/deploy-script.test.ts`. Тест читает
`infra/prod/deploy.sh` и `infra/prod/backup.sh` текстом, переводы строк
приводит к LF:

- в `deploy.sh` вызов `backup.sh --before-deploy "$VERSION"` стоит **раньше**
  строки `set_env_value API_TAG "$VERSION"` и раньше
  `docker compose up -d --wait`;
- после вызова бэкапа в `deploy.sh` есть `ensure_space`;
- в `deploy.sh` есть обработка `--no-backup` и строка лога с «без бэкапа»;
- в `backup.sh` есть режим `--before-deploy` и имя `rubezh-pre-`;
- ротация ночных дампов в `backup.sh` не захватывает `rubezh-pre-*`: в
  шаблоне ротации ночных нет `rubezh-*.dump.age` целиком — есть
  `rubezh-2*.dump.age`;
- оба файла начинаются с `#!/usr/bin/env bash` и содержат `set -euo pipefail`.

Если в CI доступен `bash` (раннер Ubuntu) — ещё кейс `bash -n` для обоих
файлов, пропускаемый на Windows (`it.skipIf(process.platform === "win32")`).

Живую проверку на сервере делают тимлиды при ближайшем выкате: в логе выката —
строка «бэкап перед выкатом: …», файл на месте.

## Критерии приёмки

- [ ] `--no-backup` пропускает дамп с предупреждением.
- [ ] Ночной бэкап работает как раньше, его ротация не трогает дампы перед
  выкатом, и наоборот.
