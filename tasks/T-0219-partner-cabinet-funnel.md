# T-0219. Кабинет партнёра — воронка по своим ссылкам и кодам, без ID и малых групп

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0219.json)](README.md#значки-статуса) [![T-0218](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0218.json&label=T-0218)](T-0218-partner-cabinet-links-promo.md)

## Зачем

Партнёру важно знать, какая из его площадок приводит игроков, которые
играют и возвращаются. T-0068 строит такую воронку для команды в карточке
партнёра. После этой задачи та же воронка — во вкладке «Воронка» кабинета:
переходы, запуск, первый забег, возврат на 1-й и 7-й день, покупка — по
дням и по ссылкам, без имён и ID игроков и без разрезов, по которым можно
узнать конкретного человека.

## Решения

Решение владельца от 24.10.2026 — `docs/35-stage4-plan.md` Р136: воронка
по своим источникам — переходы, запуск, первый забег, возврат на 1-й и 7-й
день, платящие — по дням и ссылкам, без имён и ID игроков.

Решения `claude-lead-1` от 24.10.2026:

- **Данные — отчёт T-0068**: тот же разбор по привязкам партнёра
  (`partner_binding`), те же вехи `FUNNEL_STEPS`, тот же выбор периода
  «7 · 30 · 90 · свой». Партнёр — только из `PartnerCabinet.partnerOf`:
  фильтр навязывает сервер (`docs/29-admin-panel.md` §5.4).
- **Переходы** — число кликов по ссылкам партнёра за период
  (`link_click`), строкой над воронкой: это счётчик ссылок, а не игроков.
- **Порог группы** — разрез (ссылка, код, площадка, день), в котором
  меньше N игроков на первой вехе, показывается строкой «меньше N игроков —
  не показываем», без чисел. N — ключ `partners.cabinet.minGroup`
  (умолчание 10). Итог «Все игроки партнёра» показывается всегда, если в
  нём не меньше N; меньше — «Пока меньше N игроков: воронка появится, когда
  их станет больше».
- **По дням** — таблица «день → вход, 1-й забег, вернулся D1, вернулся D7,
  покупка» за выбранный период, по дате привязки; дни с группой меньше N —
  одной строкой «мало игроков».
- **Что не уходит партнёру**: суммы покупок и выручка — только число
  платящих; ID, имена, площадки отдельных игроков.

1. **Настройка** `partners.cabinet.minGroup` (10) в каталоге.
2. **Сервер** — `PartnerCabinet.funnel(actor, query)`: отчёт T-0068 по

   уходят в ответ вовсе.
3. **Панель** — вкладка «Воронка» в кабинете: переходы, полосы `FunnelChart`,
   разрезы по ссылкам и кодам, таблица по дням, строки «мало игроков».
4. **Документы:** `docs/23` §4.4 — что видит партнёр и порог группы;
   `docs/30` — ключ настройки.

## Сценарий и интерфейс

Партнёр открывает «Воронка»: сверху «Переходов за 30 дней: 1 240», ниже —
полосы вех и разрезы по ссылкам: «канал · Игровой угол — 312 вошли, 141
сыграли, 58 вернулись на 7-й день». Ссылка с пятью игроками — строкой
«меньше 10 игроков — не показываем». Состояния: загрузка, пусто («Пока
никто не пришёл по вашим ссылкам»), мало игроков, ошибка с повтором.

## Тесты

Первым коммитом.

- `partner-cabinet.test.ts` — порог: разрезы с 9 и 10 игроками при N = 10 →
  первый скрыт, второй с числами; итог меньше N → только строка о пороге.
- `partner-cabinet.integration.test.ts`:
  - игроки двух партнёров — кабинет первого видит только своих;
  - переходы считаются по `link_click` ссылок партнёра за период;
  - в ответе нет `accountId`, имён и сумм;
  - владелец в режиме `?partnerId=` видит ту же воронку.
- Снимки вкладки (с данными и «мало игроков») — в PR.
