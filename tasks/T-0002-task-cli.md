# T-0002. Команда pnpm task — доска, захват и проверка зон

## Зачем

Реестр задач (`tasks/README.md`) сейчас ведётся руками: занятые задачи ищут по
веткам, пересечение зон сверяют глазами, захват делают тремя командами git. Чем
больше исполнителей, тем дороже ошибка: два агента в одной зоне или PR, который
«заодно» поправил чужие файлы. Команда `pnpm task` делает всё это одной
командой, а CI отклоняет PR задачи, если дифф вышел за её зоны.

## Решения

- **Без новых зависимостей.** Скрипты на чистом Node, как `scripts/release/*.mjs`.
  Логика — чистые функции, покрытые тестами. CLI — тонкая обвязка над `git` и
  `gh`, тестами не покрывается (`scripts/release/pr-check.mjs` — образец).
- **Шапка задачи — строгое подмножество YAML.** Есть только:
  - пары `ключ: значение`;
  - пустое значение;
  - `null`;
  - строчный список `[a, b]`;
  - список строками `  - элемент` под ключом.

  Кавычек, многострочных значений и вложенных объектов нет. Разбирает свой
  парсер, YAML-библиотека не нужна. Любая другая конструкция — ошибка с номером
  строки.
- **Источник правды о задачах — файлы в `origin/dev`,** а не рабочая копия:
  доска одинакова, на какой бы ветке ни стоял исполнитель. Читать через
  `git show origin/dev:tasks/<файл>` и `git ls-tree origin/dev tasks/`.
- **Занята ли задача, решает ветка** `task/T-NNNN` на `origin`
  (`git ls-remote --heads origin "task/*"`). Открытые PR — из
  `gh pr list --state open --json number,headRefName,isDraft`. Если `gh` нет или
  он не авторизован, колонка «На ревью» сливается с «В работе», и команда об этом
  предупреждает.
- **Захват** работает как в `tasks/README.md`, шаг 3:
  - ветка от `origin/dev`;
  - коммит захвата меняет `status` и `owner` в файле задачи;
  - `git push origin HEAD:refs/heads/task/T-NNNN` без `--force`.

  Отказ push означает, что задачу уже взяли.
- **Проверка зон в CI** — новым шагом существующего джоба `check` в
  `.github/workflows/pr-checks.yml`, а не новым джобом: `check` обязателен в
  ruleset ветки `main` (комментарий в самом файле объясняет почему). Шаг
  срабатывает только для веток `task/T-NNNN`, у остальных PR — пропуск с
  сообщением.

## Как сейчас

- `scripts/release/pr-check.mjs` — образец: чистые функции и CLI внизу файла с
  `pathToFileURL(process.argv[1])`.
- Тесты скриптов лежат в `scripts/test/*.test.ts`. Импорт из `.mjs` идёт с
  `// @ts-expect-error` и причиной в той же строке — образец
  `scripts/test/docs-check.test.ts`.
- `scripts/test/docs-check.test.ts` первым кейсом прогоняет проверку на
  настоящем репозитории. Так же нужно сделать для реестра задач.
- `tasks/epics.md` — таблица, эпик узнаётся по `**E<число>.` в первой колонке.

## Шаги по порядку

1. **Тесты — первым коммитом** (раздел «Тесты»).
2. `scripts/tasks/task-file.mjs` — разбор и проверка одной задачи:
   - `parseFrontmatter(text)` → `{ data, body }` или ошибка с номером строки;
   - `validateTask(fileName, data)` → список ошибок вида
     `T-0003-x.md: поле priority — ожидается P0, P1, P2 или P3, а не P5`.

   Правила:
   - имя файла — `T-\d{4}-[a-z0-9-]+\.md`, и `id` совпадает с его началом;
   - все поля из `tasks/README.md` («Поля задачи») на месте, лишних нет;
   - перечисления: `priority` P0–P3; `status` draft | ready | in-progress | done | cancelled;
     `size` S | M; `runner` any | local | human; `release` none | patch | minor;
   - `zones` не пустой у `ready` и `in-progress`;
   - путь в `zones` и `shared` относительный, без `..`, без `\` и без ведущего `/`;
   - у `in-progress` `owner` не пустой.
3. `scripts/tasks/registry.mjs` — проверка реестра целиком,
   `checkRegistry(files, epicsMarkdown)`:
   - уникальные `id`;
   - `epic` есть в `epics.md`;
   - каждый `depends_on` ссылается на существующую задачу;
   - циклов в `depends_on` нет (ошибка называет цикл: `T-0003 → T-0004 → T-0003`).

   Пропускаются `README.md`, `epics.md` и `_template.md`.
4. `scripts/tasks/zones.mjs`:
   - `globToRegExp(pattern)` — шаблоны:
     - `*` — любые символы, кроме `/`;
     - `**` — любые вложенные каталоги, `**/` совпадает и с нулём каталогов;
     - `?` — один символ, кроме `/`;
     - остальные символы — буквально;
   - `matches(path, patterns)`;
   - `zonesOverlap(a, b, repoFiles)` — пересекаются, если хоть один путь из
     `repoFiles` или из буквальных (без `*` и `?`) зон `a` и `b` совпадает с
     зоной `a` и с зоной `b` одновременно. Буквальные пути учитываются, чтобы
     ловить два новых файла с одним именем;
   - `outOfZone(changed, task)` — изменённые файлы вне `zones`, `shared` и
     самого файла задачи.
5. `scripts/tasks/board.mjs`, `classify(tasks, taken, prs, repoFiles, epicOrder)`.
   Каждая задача попадает ровно в одну колонку:

   | Колонка | Условие |
   |---|---|
   | «Готово» | `done` |
   | «Отменено» | `cancelled`, по умолчанию скрыто |
   | «Черновики» | `draft` |
   | «На ревью» | есть ветка и открытый PR не в черновике |
   | «В работе» | есть ветка, PR нет или он в черновике |
   | «Заблокировано» | `ready`, ветки нет, но не все зависимости `done` или зоны пересекаются с задачей «В работе» или «На ревью»; причина — в строке |
   | «Свободно» | `ready`, ветки нет, зависимости `done`, пересечений нет |

   Внутри колонки — по `priority`, затем по порядку эпика в `epics.md`, затем по `id`.
6. `scripts/tasks/task.mjs` — CLI, вывод на русском:
   - `check` — `checkRegistry` по рабочей копии `tasks/`; ошибки → код выхода 1;
   - `board` — колонки с задачами: `id`, `title`, `priority`, `size`, `runner`, у
     занятых — `owner`, у заблокированных — причина;
   - `next [--runner any|local]` — «Свободно» с подходящим `runner`
     (по умолчанию `any`; `local` включает `any`; `human` не показывается
     никогда). Первая строка — лучшая задача;
   - `claim T-NNNN --owner "<аккаунт / модель>"`:
     - отказ, если рабочая копия грязная или задача не «Свободно» (с причиной);
     - иначе `git fetch origin --prune` → `git switch -c task/T-NNNN origin/dev`
       → правка `status` и `owner` в файле задачи → коммит
       `chore(tasks): Взять T-NNNN в работу` → `git push origin HEAD:refs/heads/task/T-NNNN`;
     - push отклонён → вернуться на прежнюю ветку, удалить локальную
       `task/T-NNNN`, сообщить «задачу уже взяли», код выхода 1;
   - `release T-NNNN --yes` — `git push origin --delete task/T-NNNN`; без `--yes` —
     только подсказка, что будет сделано;
   - `diff-check [--base <ref>]`:
     - задача берётся из `GITHUB_HEAD_REF`, иначе из `git branch --show-current`;
     - ветка не `task/T-NNNN` → «не ветка задачи — пропуск», код выхода 0;
     - иначе изменённые файлы — `git diff --name-only <base>...HEAD` (по
       умолчанию `origin/dev`), задача читается из файла на текущей ветке;
       файлы вне зон → список и код выхода 1.
7. `package.json` (корень): скрипт `"task": "node scripts/tasks/task.mjs"`.
8. `.github/workflows/pr-checks.yml`, в джоб `check` последним шагом:

   ```yaml
   - if: ${{ !cancelled() && startsWith(github.head_ref, 'task/T-') }}
     run: |
       git fetch origin "${{ github.base_ref }}"
       node scripts/tasks/task.mjs diff-check --base "origin/${{ github.base_ref }}"
     env:
       GITHUB_HEAD_REF: ${{ github.head_ref }}
   ```

   Новых actions не добавлять. Над шагом — комментарий, зачем он (по-русски,
   «почему», а не «что»).
9. `tasks/README.md`, раздел «Как взять задачу»:
   - шаги 1–3 заменить на `pnpm task next` и
     `pnpm task claim T-NNNN --owner "…"`; ручной захват оставить коротким
     абзацем «если команды нет»;
   - в раздел «Приёмка» добавить, что зоны проверяет CI (`diff-check`).
10. `.claude/skills/take-task/SKILL.md`: шаги выбора и захвата — через `pnpm task`.
11. `docs/09-ci-cd.md`, раздел о `pr-checks.yml` (§8.1, «Проверка PR»): одна-две
    фразы о шаге проверки зон.

## Чего не трогаем

- `scripts/release/*` и остальные шаги `pr-checks.yml`.
- `scripts/docs-check.mjs`: файлы `tasks/` он не сканирует, и так остаётся.
  Доработка `docs:check` — задача эпика E8.
- Ruleset репозитория и обязательные проверки — без изменений.

## Тесты

Первым коммитом. Импорт из `.mjs` — с
`// @ts-expect-error — утилита на чистом JS, типов у неё нет` в той же строке,
как в `docs-check.test.ts`.

1. `scripts/test/tasks-file.test.ts`:
   - разбирает шапку со строчным списком, списком строками, пустым значением и
     `null`;
   - отступ табуляцией, кавычки и строка без `:` → ошибка с номером строки;
   - нет поля, лишнее поле, неверное перечисление, `id` не совпадает с именем
     файла, `..` в зоне, `in-progress` без `owner` → по ошибке на каждый случай,
     текст называет файл и поле.
2. `scripts/test/tasks-registry.test.ts`:
   - **на настоящем репозитории** `checkRegistry` по `tasks/` и `tasks/epics.md`
     возвращает пустой список;
   - на наборе в памяти: повтор `id`, неизвестный эпик, несуществующая
     зависимость, цикл из двух и трёх задач — ошибка называет цикл.
3. `scripts/test/tasks-zones.test.ts`:
   - `a/**` совпадает с `a/b/c.ts` и с `a/c.ts`;
   - `a/*.ts` не совпадает с `a/b/c.ts`;
   - `**/x.ts` совпадает с `x.ts` и с `d/e/x.ts`;
   - `a.b/c` не совпадает с `aXb/c`: точка буквальна;
   - зоны `backend/api/src/modules/shop/**` и
     `backend/api/src/modules/shop/shop.service.ts` пересекаются;
     `…/shop/**` и `…/wallet/**` — нет;
   - две задачи с одним и тем же новым файлом (его нет в `repoFiles`) —
     пересекаются;
   - `outOfZone`: файл в `zones`, строка в `shared` и сам файл задачи — не
     нарушение; файл в другом модуле — нарушение.
4. `scripts/test/tasks-board.test.ts` — фикстура из 7 задач, по одной на каждую
   колонку. Каждая попадает в свою, у заблокированных правильная причина
   (зависимость или пересечение зон с конкретной задачей). Порядок внутри
   «Свободно» — по приоритету, затем по эпику, затем по `id`.

## Критерии приёмки

- [ ] `pnpm task check` на текущем реестре — без ошибок; `pnpm test` включает проверку реестра.
- [ ] `pnpm task board` и `pnpm task next` работают из любой ветки и показывают реестр из `origin/dev`.
- [ ] `pnpm task claim` захватывает свободную задачу. Второй захват той же задачи из другого клона получает отказ «задачу уже взяли». Проверено руками на тестовом репозитории (`git init --bare` + два клона); как именно — в описании PR.
- [ ] Шаг `diff-check` в `pr-checks.yml` падает, если PR ветки `task/T-NNNN` меняет файл вне зон, и не мешает остальным PR.
- [ ] Новых зависимостей и новых actions нет.
- [ ] Гейт (`CLAUDE.md`) и `pnpm docs:check` зелёные.

## PR

- **Заголовок:** `feat(dev): Команда pnpm task — доска, захват и проверка зон`
- **Метка:** `release: patch` (область `dev` до игрока не доходит, `docs/09-ci-cd.md` §8.1)
- **Для игроков:** нет
- **Сводка для команды:** у реестра задач появилась команда `pnpm task`. Она
  показывает доску, предлагает следующую задачу и захватывает её одной командой.
  CI теперь не пропустит PR задачи, который меняет файлы вне её зон.
