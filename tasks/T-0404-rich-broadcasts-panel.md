# T-0404. Оформленные рассылки — редактор и предпросмотр в панели

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0404.json)](README.md#значки-статуса) [![T-0403](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0403.json&label=T-0403)](T-0403-rich-broadcasts-server.md)

## Зачем

После T-0403 сервер умеет оформленные рассылки, но в панели их не
написать. После задачи в форме рассылки:
- переключатель «Простой текст / Оформленный»;
- поле для ограниченного Markdown с подсказкой разметки и счётчиком знаков;
- предпросмотр блоками — заголовки, списки, таблицы, раскрывающиеся блоки,
  как их разобрал сервер;
- ошибки разбора с номером строки.

На экране рассылки видно, прошёл ли тест себе этой редакции: без него
оформленную рассылку не запустить (Р199, WP52 № 12).

## Решения

- **Р199** (`docs/35-stage4-plan.md`, WP52, сценарий «Новости и «Что
  нового»»). Правила оформленной рассылки — T-0403 и `docs/29-admin-panel.md`
  §7.2:
  - что понимает разметка;
  - пределы;
  - запуск только после теста себе той же редакции.
- **Решения тимлида:**
  - **Предпросмотр строит сервер** (`POST admin/broadcasts/preview`, T-0403),
    а панель только рисует его блоки. Свой разбор в панели однажды разошёлся
    бы с тем, что уйдёт игрокам;
  - предпросмотр — по кнопке «Предпросмотр» и при переключении формата, а
    не на каждую букву: маршрут под лимитом `admin:mutate` (60 в минуту);
  - предпросмотр — честное приближение, а не снимок Telegram. Подпись под
    ним: «Так примерно покажет Telegram. Точно — «Тест себе»».

## Шаги по порядку

1. **Тесты первым коммитом** — раздел «Тесты».
2. **`api/broadcasts.ts`:**
   - `broadcastSchema` += `format: z.enum(["plain", "rich"]).default("plain")`;
     `broadcastViewSchema` += `tested: z.boolean().default(false)`. Умолчания —
     чтобы старая фикстура `ROW` и старый сервер разбирались;
   - `BroadcastInput` += `format: "plain" | "rich"`; `bodyOf` передаёт его;
   - `richDocSchema` — Zod-схема `RichDocument` T-0394, рекурсивная
     (`z.lazy`):
     - блоки `heading`, `paragraph`, `list`, `table`, `details`, `quote`,
       `buttons`, `divider`, `footer`;
     - части текста — строка, массив, `bold`, `italic`, `link`, `dateTime`;
     - незнакомый вид блока — ошибка разбора ответа, а не молчание;
   - `previewBroadcast(api, text)` →
     `ApiResult<{ doc: RichDoc; plain: string; problems: string[] }>`;
   - `broadcastProblem` у `rich` — текст до 4 096 знаков исходника; разбор
     проверяет сервер. Счётчик простого текста берёт длину `plain` из
     последнего предпросмотра.
3. **`screens/broadcasts/RichPreview.tsx`** — `RichPreview({ doc })`,
   отрисовка блоков без `dangerouslySetInnerHTML`:
   - `heading` → `h3`/`h4`/`h5`;
   - `paragraph` → `p` с `whitespace-pre-wrap`;
   - `list` → `ul`/`ol`;
   - `table` → `table` в обёртке `overflow-x-auto` (на 320 px таблица
     прокручивается внутри, страница — нет);
   - `details` → `details`/`summary`;
   - `quote` → `blockquote`;
   - `divider` → `hr`;
   - `buttons` → плашки как у кнопки рассылки;
   - `bold`/`italic` → `strong`/`em`;
   - `link` → `a` с `rel="noreferrer"` и `target="_blank"`, только
     `https://`;
   - `dateTime` → его `fallback`.

   Цвета и отступы — классы токенов панели, как у карточки рассылки.
4. **`BroadcastForm.tsx`:**
   - над полем текста — `Select` «Формат»: «Простой текст» и «Оформленный
     (Markdown)»;
   - подсказка поля:
     - у простого — как сейчас;
     - у оформленного — «Markdown: # заголовок, **жирный**, _курсив_,
       [ссылка](https://…), - список, > цитата, таблица | a | b |,
       <details><summary>…</summary>…</details>; ${N} из 4096»;
   - у оформленного под полем:
     - кнопка «Предпросмотр» → `previewBroadcast`;
     - есть `problems` — `Notice` со списком, первые пять;
     - иначе — `RichPreview` и строка «Простой текст: ${plain.length} из
       4000 — его получат MAX, VK и старые клиенты»;
     - подпись «Так примерно покажет Telegram. Точно — «Тест себе»»;
   - смена формата на оформленный — предпросмотр сразу; смена текста
     делает прежний предпросмотр бледным (`opacity-60`) с пометкой «текст
     изменился — обновите»;
   - ошибка сохранения с сервера — в прежнем `Notice`.
5. **`BroadcastsScreen.tsx`** — карточка рассылки:
   - строка `KeyValue` «Формат» — «простой текст» или «оформленный»;
   - у оформленной вместо `whitespace-pre-wrap` текста — `RichPreview`
     документа: экран рассылки сам зовёт `previewBroadcast(text)` при
     открытии; ошибка — исходник как сейчас и `Notice`;
   - у оформленного черновика строка «Тест себе этой редакции» — `Badge`
     «пройден» (`success`) или «не пройден» (`warning`);
   - «Запустить…» у оформленного черновика без теста — `disabled` с
     `blockedBy` «Сначала «Тест себе» этой редакции»;
   - после «Тест себе» просмотр перечитывается: отметка видна сразу.
6. **`ui/help.ts`**, раздел `broadcasts` — ключ `format`: «Оформленный
   текст Telegram покажет заголовками, списками и таблицами; MAX, VK и
   старые клиенты получат тот же текст без разметки. Запуск — только после
   «Тест себе» этой же редакции».

## Сценарий и интерфейс

Маркетолог в панели, раздел «Рассылки»:

1. «Новая рассылка» → «Формат: Оформленный (Markdown)» → пишет текст →
   «Предпросмотр» — видит заголовок, список и таблицу блоками и «Простой
   текст: 812 из 4000».
2. Ошибка в разметке → «строка 7: незакрытый **» в `Notice`, предпросмотра
   нет, сохранить можно только исправив (сервер вернёт ту же ошибку).
3. Сохранил → карточка рассылки: «Формат — оформленный», «Тест себе этой
   редакции — не пройден», «Запустить…» неактивна с подсказкой.
4. «Тест себе» → сообщение в его чате с ботом → «пройден» → «Запустить…»
   доступна.
5. «Изменить» текст → отметка снова «не пройден».

Состояния:
- предпросмотр загружается — `Loading` на месте блока;
- ошибка сети — `ErrorNotice` с «Повторить»;
- нет права `broadcast.edit` — раздел не виден, как сейчас;
- простая рассылка — экран как сейчас.

**Снимки** — при приёмке их делает тимлид (`pnpm screens` или браузер) на
320, 390, 768 и 1440 px:
- форма с оформленным предпросмотром;
- форма с ошибками разбора;
- карточка черновика без теста и с тестом.

Боковой прокрутки страницы нет, таблица предпросмотра прокручивается внутри.
