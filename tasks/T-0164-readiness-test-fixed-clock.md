# T-0164. Тесты «61-й запрос — 429» не падают на смене минуты

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0164.json)](README.md#значки-статуса)

## Зачем

Два теста шлют 61 запрос с настоящими часами. Если серия пересекает границу
минуты, счётчик лимита начинается заново, и 61-й запрос получает 200 вместо
429. Так упал `gate` в PR #296 (05:45:00). Тест ломается раз в несколько сотен
запусков и сбивает приёмку чужих задач.

## Решения

`claude-lead-1`, 19.10.2026: время в тесте фиксируется, проверку не ослабляем
(не «до 62 запросов», не «любой из 429/200»). Подставные часы — тем же способом,
что в `backend/api/test/events.test.ts:153–171`.

## Как сейчас

- `backend/api/src/modules/ingest/rate-limiter.ts:41–43` — `consume(rule, key,
  cost, nowMs = Date.now())`: окно — `Math.floor(nowMs / 1000 / windowSec)`,
  то есть календарная минута. Контроллеры `nowMs` не передают, поэтому из
  теста время подменяется только через часы процесса.
- `backend/api/test/readiness.test.ts:87–94` — «на 61-й запрос с одного адреса
  за минуту отвечает 429»: 60 запросов `GET /health/ready` и 61-й.
- `backend/api/test/client-scripts.test.ts:107–113` — «61-й запрос с одного
  адреса за минуту — 429»: тот же приём на `/api/v1/client/scripts`. Дефект
  тот же, пункт входящих называл только первый тест.
- `backend/api/test/events.test.ts:153–171` — образец:
  `vi.useFakeTimers({ toFake: ["Date"] })` и `vi.setSystemTime(Date.UTC(…))`.
  Подменяется только `Date`, настоящие таймеры остаются — они нужны Fastify и
  пробе готовности (тайм-аут Redis в `readiness.test.ts:61–68`).

## Шаги по порядку

1. `readiness.test.ts`: в тесте «на 61-й запрос…» до `appWith(…)` вызвать
   `vi.useFakeTimers({ toFake: ["Date"] })` и
   `vi.setSystemTime(Date.UTC(2026, 9, 13, 10, 0, 30))` (середина минуты).
   Комментарий над вызовом, по-русски, почему: окно лимита — календарная
   минута, серия на её границе началась бы заново.
2. В `afterEach` того же файла добавить `vi.useRealTimers()` — вызов безопасен и
   без подмены. Импорт `vi` из `vitest`.
3. То же в `client-scripts.test.ts` для теста «61-й запрос…»: часы в середине
   минуты, `vi.useRealTimers()` в `afterEach` (если в файле уже есть свой
   `afterEach` — дописать в него).
4. Числа и ожидания (60 раз 200, 61-й — 429) не менять.

## Чего не трогаем

- `rate-limiter.ts` и контроллеры: `nowMs` в них не пробрасываем.
- Другие тесты с лимитами (`ads.test.ts`, `media.test.ts`, `online.http.test.ts`,
  `promo-codes.test.ts`): у них другие окна и счётчики, их проверяет тимлид
  отдельно.
- `events.test.ts`: там время уже зафиксировано.

## Тесты

Правка и есть тест. Проверка, что она работает:

- `readiness.test.ts` и `client-scripts.test.ts` проходят целиком;
- файл `readiness.test.ts` прогнан 20 раз подряд
  (`pnpm --filter backend-api exec vitest run test/readiness.test.ts --repeat 20`), все 20 — зелёные;
- тест «отвечает 503, когда Redis молчит дольше секунды» по-прежнему
  зелёный: настоящие таймеры не подменены.
