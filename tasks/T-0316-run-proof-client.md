# T-0316. Запись для проверки у каждого забега — лог ввода, выборы и контрольные суммы сквозь продолжение из снимка; отправка на сервер очередью

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0316.json)](README.md#значки-статуса) [![T-0317](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0317.json&label=T-0317)](T-0317-run-proof-server.md)

## Зачем

Перепроверка забегов (WP5): сервер повторяет забег и сверяет исход. Нужна
запись. Сейчас полная запись диагностики пишется только у тех, кто включил
«Помощь в тестировании», и тяжела: кадры, события, производительность.

Есть и вторая проблема: забег, продолженный из снимка после перезагрузки,
вообще не повторить (`replayBlocker: "resumed"`) — лог начинается с середины.

После задачи у **каждого** забега есть лёгкая «запись для проверки»: всё,
что задаёт исход, и ничего лишнего. Она живёт в снимке прерванного забега и
продолжается после него. Клиент отправляет её на сервер очередью после
записи забега (T-0317).

## Решения

Решения владельца — `docs/35-stage4-plan.md` WP5:
- награды и верх рейтинга получают только забеги, которые сервер повторил;
- запись — та же, что у диагностики, со снимком снаряжения и бустов (Р17) и
  хэшем контента (Р16).

Решения `claude-lead-1` от 25.10.2026:

- **`RunProof`** — подмножество `RunRecording`, `schema: "run-proof-v1"`.

  Заголовок:
  - `runId`, `seed`, `mapId`, `difficultyId`, `mode`, `startingWeaponId`;
  - `contentHash`, `unitScale`;
  - `loadout` — снимок снаряжения, бусты, класс устройства (`RunLoadout`).

  Ход:
  - `input` — лог ввода `rle-v1`;
  - `choices` — выборы улучшений, сундуков и инструментов карточек с тиками;
  - `continues` — тики вторых шансов;
  - `checkpoints` — контрольная сумма мира раз в 60 с.

  Итог:
  - `result` — тики, время, уровень, убийства, причина смерти, контрольная
    сумма.

  Кадров, событий, производительности и GPU — нет: это полная запись
  диагностики, она остаётся по переключателю.
- **Пишется всегда** — тем же `run-recorder.ts`, режимом «только проверка»:
  - стоимость — лог ввода (до ~36 КБ на десять минут в худшем случае, `docs/28` §3.4);
  - забег разработчика (`dev`) — `replayBlocker: "dev"`, как сейчас.
- **Сквозь продолжение** — снимок прерванного забега (`run/snapshot.ts`)
  хранит запись для проверки на момент снимка. Продолжение дописывает её
  дальше, а не начинает новую.
  - `replayBlocker: "resumed"` больше не ставится.
  - Повтор (`replay.ts`) идёт от зерна по всей записи и сверяет
    контрольную сумму в тике снимка.
  - Снимок прошлой сборки без записи — `resumed`, как раньше.
- **Размер** — запись сжимается (`CompressionStream("gzip")`, есть в
  браузерах Telegram), кодируется base64; потолок — 64 КБ после сжатия.
  Больше — `replayBlocker: "proof_overflow"`, запись не отправляется.
- **Отправка** — `state/run-proof-queue.ts`:
  - после того как забег записан сервером (ответ с `runId`) —
    `PUT /api/v1/runs/:runId/proof` (T-0317);
  - очередь в `localStorage` с повтором при сети, до 3 записей в очереди,
    старее 3 суток — выбрасываются;
  - ошибки хранилища — `try/catch`.

  Игрок ничего не ждёт: забег уже записан.
- **Детерминизм** — запись для проверки не влияет на мир: забег с ней и без
  неё побитно одинаков.

## Как сейчас

- **Полная запись** — `core-game/src/game/diagnostics/run-recorder.ts`
  (`RunRecording`, `run-api.ts:413`); лог ввода — `input-log.ts`; повтор —
  `replay.ts` (вердикты `match`, `mismatch`, `not_replayable`…).

  `run/snapshot.ts`.

## Тесты

Первым коммитом.

- `run-proof.test.ts`:
  - забег без продолжения → запись → `replay` даёт `match`;
  - снимок на 3-й минуте → продолжение → запись покрывает весь забег,
    `replay` — `match`, без `resumed`;
  - подмена одного выбора в записи → `mismatch` с тиком;
  - забег с записью и без — побитно одинаков;
  - запись больше 64 КБ после сжатия → `proof_overflow`.
- `run-proof-queue.test.ts`:
  - отправка после ответа сервера;
  - нет сети — в очереди, отправка позже;
  - четвёртая запись вытесняет старую;
  - старше 3 суток — выброшена;
  - хранилище бросает — забег всё равно записан.
