# T-0390. Снятие застрявшего захвата тимлидом — попытка задачи и ветка task/T-NNNN-N

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0390.json)](README.md#значки-статуса)

## Зачем

7 ноября 2026 аккаунт исполнителя заблокировали на GitHub (claude-10). Его PR
скрылись, а ветка `task/T-0119` с настоящей работой осталась. Она держит зоны:
срочная T-0388 не взялась, потому что пересекается с T-0119 по
`balance-targets.ts` и тестам баланса. Правило брошенного захвата (T-0371) такую
ветку не ловит — в ней есть работа. Снять захват сейчас можно одним способом:
владелец удаляет ветку в интерфейсе GitHub. Скрытый PR к тому же не даёт открыть
новый PR из той же ветки.

После задачи тимлид снимает застрявший захват одной командой. Задача получает
новую попытку и новую ветку `task/T-NNNN-2`, старая ветка ничего не держит, и
удалять её не нужно.

## Решения

Р195 (`docs/35-stage4-plan.md`, 07.11.2026), решение владельца. Числа и правила
ниже — решения `claude-lead-1`, исполнитель их не пересматривает.

1. **Попытка задачи** — необязательное поле шапки `attempt`.
   - Нет поля — попытка 1. Поле есть — целое число от 2; `attempt: 1`, ноль,
     дробь, текст — ошибка проверки: «attempt: попытка 1 пишется без поля»
     или «ожидается целое число от 2».
   - Строка `attempt: N` — **последняя в шапке**, после `batch`. Так она не
     соседствует со строками `status` и `owner`, и слияние ветки прежней
     попытки с `dev` реже конфликтует в шапке. `pnpm task fix` порядок не ломает.
2. **Ветка текущей попытки** — единственная действующая ветка задачи:
   - попытка 1 — `task/T-NNNN`, как сейчас;
   - попытка N ≥ 2 — `task/T-NNNN-N` (`task/T-0119-2`).

   `task/T-0119-1` — не ветка задачи: суффикс бывает только у попыток от 2.
3. **Один модуль имён** — `scripts/tasks/branch.mjs`, без обращений к git:
   - `TASK_BRANCH_RE = /^task\/(T-\d{4})(?:-([2-9]|[1-9]\d+))?$/`;
   - `parseTaskBranch(ref)` → `{ id, attempt }` или `null` (принимает и
     `refs/heads/…`, и голое имя);
   - `taskBranch(id, attempt = 1)` → имя ветки;
   - `attemptOf(task)` → число из поля или 1;
   - `currentBranchOf(task)` → `taskBranch(task.id, attemptOf(task))`.

   Все места, где имя ветки задачи сейчас собирается строкой `` `task/${id}` ``
   или разбирается своей регуляркой, берут его отсюда (раздел «Как сейчас»).
   Своих регулярок `task\/(T-\d{4})` в `scripts/tasks` и `scripts/release` не
   остаётся.
4. **Ветка прежней попытки ничего не держит.** Если номер попытки в ветке
   меньше `attempt` задачи на базе (`origin/dev`), то эта ветка:
   - не делает задачу занятой — не входит в `taken`;
   - не держит зоны соседей;
   - не считается брошенным захватом и не перехватывается;
   - её открытый PR не считается PR задачи — ни на доске, ни в `merge`, ни в
     зависимостях задела.

   Ветка с попыткой **больше** текущей (`task/T-0119-3` при `attempt: 2`) —
   не ветка задачи: тоже ничего не держит. Если её PR приходит в CI,
   `claim-check` отказывает (п. 7).
5. **`pnpm task restart T-NNNN --reason "…"`** — команда тимлида.
   - **Где.** Только в рабочей ветке тимлида, не `task/*`. Рабочая копия
     чистая. Задача на базе в статусе `ready` или `in-progress`. Причина
     непустая. Ветка текущей попытки есть на `origin`.
   - **Отказы, каждый с причиной:**
     - ветки нет — «снимать нечего, задача свободна»;
     - `done`, `cancelled`, `draft` — «попытки бывают только у задач в
       работе».
   - **Что делает:**
     1. в файле задачи `attempt` + 1 (поле появляется последней строкой
        шапки), `status: ready`, `owner:` пустой;
     2. коммит `chore(tasks): Снять захват T-NNNN — попытка N`, в теле:
        причина, прежняя ветка, прежний `owner` из ветки (`readBranchFile`) и
        время её последнего коммита;
     3. **без push.** Снятие вступает в силу с влитием в `dev` PR тимлида, как
        любая правка реестра;
     4. печатает: «после влития задачу берут веткой task/T-NNNN-N: `pnpm task
        claim T-NNNN --owner "…"`; продолжить работу прежней попытки — `--from
        task/T-NNNN`. Открытый PR прежней ветки закрой с комментарием».

   Чужую ветку команда не удаляет и в неё не пушит.
6. **`pnpm task claim` и попытки.**
   - Ветку создаёт по попытке задачи на базе. Брошенный захват (T-0371),
     перехват и задел работают с веткой текущей попытки.
   - Новый флаг **`--from <ветка>`** — только ветка прежней попытки этой же
     задачи (`parseTaskBranch` даёт тот же id и меньшую попытку), и она есть на
     `origin`. Иначе отказ: «--from берёт только ветку прежней попытки
     T-NNNN».
   - Порядок с `--from`:
     1. ветка от `origin/dev`;
     2. `git fetch` и `git merge --no-edit origin/<ветка>`;
     3. конфликт **только** в файле самой задачи разрешается версией с базы —
        `git checkout <база> -- tasks/<файл>`, и слияние коммитится;
     4. конфликт в любом другом файле — `git merge --abort`, локальная ветка
        убирается, отказ со списком файлов;
     5. дальше коммит захвата, как обычно.
   - `--from` с `--ahead` — отказ.
7. **CI и проверки.**
   - **`claim-check`** принимает ветку текущей попытки. На ветку прежней или
     несуществующей попытки отказывает: «ветка task/T-0119 — попытка 1, а у
     T-0119 действует попытка 2: захват снят тимлидом (Р195). Продолжай веткой
     task/T-0119-2: pnpm task claim T-0119 --from task/T-0119».
   - **`diff-check`** на ветке задачи: ни у одного файла `tasks/T-*.md` поле
     `attempt` в ветке не отличается от базы. Иначе ошибка: «ветка задачи
     меняет попытку T-NNNN: снимает захват только тимлид (pnpm task restart)».
     Так поток не может сам открыть себе попытку.
   - **`pr-check`** и **`pr-status-label`** узнают ветку задачи через
     `parseTaskBranch`: PR из `task/T-0119-2` получает метки статуса и проверки
     так же, как из `task/T-0119`.
   - **`.github/workflows/*` не меняются**: условие
     `startsWith(head_ref, 'task/T-')` уже пропускает ветки с суффиксом.
8. **Остальные команды и страница:**
   - `resume`, `release` (удалить свою ветку), `merge` (самостоятельный мердж,
     поиск PR по ветке), `holds`, `next`, `streams`, `status-json` работают с
     веткой текущей попытки;
   - **вклад и автор задачи** на странице доски (`board-page.mjs`,
     `contribution.mjs`) считаются по влитым PR из ветки **любой** попытки этой
     задачи — `parseTaskBranch(pr.headRefName)?.id === task.id`;
   - **подсказка в `pnpm task next`:** у задачи с `attempt ≥ 2`, если ветка
     прежней попытки есть на `origin` и в ней есть работа кроме захвата, строка
     кончается «попытка N, работа прежней попытки — task/T-NNNN (--from)».
9. **Не удаляем и не переписываем чужие ветки.** Ни одна команда и проверка
   не делает `push --delete` чужой ветки и `--force`. Ветки прежних попыток
   остаются как история.

- **`tasks-claim.test.ts`:**
  - **`checkClaim`.** Задачи A и B пересекаются зонами, B — `attempt: 2`:
    - на `origin` только `task/B` (попытка 1) с работой — A брать можно;
    - есть `task/B-2` — прежняя ошибка «зоны пересекаются»;
    - есть `task/B-3` — A брать можно.
  - **Брошенный захват.** Считается только по ветке текущей попытки.
  - **`restart`** (функцией с `git` параметром):
    - поднимает попытку 1 → 2 и 2 → 3, поле — последней строкой шапки;
    - ставит `status: ready` и пустой `owner`;
    - коммит с заголовком и телом п. 5, без push;
    - отказы: ветки текущей попытки нет; задача `done`, `cancelled` или
      `draft`; пустая причина; рабочая ветка `task/*`.
  - **`claim --from`:**
    - конфликт только в файле задачи — берётся версия базы, захват проходит;
    - конфликт в другом файле — `merge --abort`, отказ со списком;
    - `--from` чужой задачи или текущей попытки — отказ;
    - `--from` с `--ahead` — отказ.
  - **`claim-check`:**
    - ветка текущей попытки — проходит;
    - прежней или будущей — отказ с текстом п. 7.
  - **`diff-check`:** ветка задачи меняет `attempt` любой задачи — ошибка.
- **`tasks-board.test.ts`:**
  - задача с `attempt: 2` и только старой веткой — свободна, с подсказкой
    `--from`, если в старой ветке есть работа;
  - с веткой `-2` — в работе;
  - PR из старой ветки не делает задачу «на ревью».
- **`tasks-merge.test.ts`:** самостоятельный мердж находит PR ветки

- **`tasks-board-page.test.ts` и `tasks-contribution.test.ts`:** влитой PR

- **`pr-check.test.ts` и `pr-status-label.test.ts`:** ветка
  `task/T-0119-2` — ветка задачи, `task/T-0119-1` — нет.

## Критерии приёмки

- [ ] `pnpm task restart T-NNNN --reason "…"` поднимает попытку коммитом без
      push. После влития в `dev` ветка прежней попытки не держит зоны и не
      делает задачу занятой.
- [ ] Задачу с попыткой N берут веткой `task/T-NNNN-N`, с нуля или `--from`
      ветки прежней попытки. CI (`claim-check`, `diff-check`, `pr-check`,
      метки статуса) принимает такую ветку.
- [ ] PR из ветки прежней попытки не проходит `claim-check`. Ветка задачи не
      может поменять `attempt`.
- [ ] Для задач без `attempt` всё работает как раньше: нынешние тесты
      зелёные.
- [ ] Ни одна команда не удаляет чужую ветку и не пушит с `--force`.
- [ ] Гейт (`CLAUDE.md`), `pnpm docs:check` и `pnpm task check` зелёные.

## PR

- **Заголовок:** `chore(tasks): Снимать застрявший захват новой попыткой`
- **Метка:** `release: none`
- **Для игроков:** нет
- **Сводка для команды:**

  ```

  Если поток пропал или его аккаунт заблокировали, а ветка задачи с работой держит соседние задачи, тимлид снимает захват командой pnpm task restart.   ```
  ```
