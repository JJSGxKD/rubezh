# T-0156. Панель — сводка заблокированных адресов клиента

## Зачем

T-0155 собирает на сервере сводку адресов, которые политика клиента
заблокировала. Без экрана её не видно, и список разрешённого снова
дополняется по скриншотам. Эта задача показывает сводку в панели.

## Решения

Р108 (`docs/35-stage4-plan.md`, 19.10.2026): панель показывает сводку, и
список дополняется по ней, а не по скриншотам.

Решение claude-lead-1 от 19.10.2026: право чтения сводки — `diagnostics.view`,
хранилище на сервере — Redis, кнопки сброса нет (сводка устаревает за 30
суток).

Уточнения `claude-lead2-1`:

- **Раздел «Блокировки клиента»** в группе «Эксплуатация», id `csp`, право
  `diagnostics.view` — то же, что проверяет маршрут сервера (T-0155).
- **Только чтение.** Кнопки «сбросить» нет (решение claude-lead-1 от
  19.10.2026): сводка устаревает сама через 30 суток.
- Макета нет (`design: null`): экран из готовых деталей панели — `Panel`,
  `DataTable`, `Notice`, `Badge`, `Button`, `Field`, `Input`, `Select`.

## Как сейчас

- Ответ сервера (T-0155): `GET /api/v1/admin/csp-reports` →
  `{ data: { entries: [{ directive, host, count, lastAt }], overflow,
  maxEntries } }`. `lastAt` — ISO-строка, записи идут свежими сверху.
  `directive` — одно из имён директив политики или `other`; `host` — имя
  хоста, либо слово `inline`, `eval`, `data`, `blob`, либо `other`.
- `apps/admin/src/api/diagnostics.ts:1–40` — образец слоя запросов:
  Zod-схема ответа и `api.request(path, { schema })`.
- `apps/admin/src/screens/diagnostics/DiagnosticsScreen.tsx:1–60` — образец
  экрана-списка: `useApi`, `Loading`, `ErrorNotice` с «Повторить», `Panel` с
  кнопкой «Обновить» и пояснением `help={HELP.diagnostics.reports}`.
- `apps/admin/src/routes.ts:75–80` — группа «Эксплуатация»: строка
  раздела `{ id, title, hint, permission, icon }`; подсказка не длиннее 80
  знаков (проверяет `test/routes.test.ts`).
- `apps/admin/src/screens/sections.tsx:30–52` — `SECTION_SCREENS`: id раздела
  → экран. Тест `routes.test.ts:76–80` сверяет, что у каждого раздела есть
  экран и наоборот.
- `apps/admin/src/ui/help.ts:209–211` — пояснения «?»: `HELP.diagnostics`.
  `test/help.test.ts` требует, чтобы каждое пояснение стояло на экране и было
  не длиннее 400 знаков.
- `apps/admin/src/ui/kit.tsx:234` — `DataTable` сам превращается в карточки
  на узком экране.
- `apps/admin/src/format.ts:11` — `formatDateTime`.

## Шаги по порядку

1. **Тесты первым коммитом** (раздел «Тесты»).
2. `src/api/csp-reports.ts`:
   - Zod-схема `cspSummarySchema` по ответу сервера;
   - `fetchCspSummary(api)` → `api.request("/csp-reports", { schema })`;
   - `directiveGroup(directive: string): string` — человеческое имя:
     `script-src*` → «скрипты», `style-src*` → «стили», `font-src` →
     «шрифты», `img-src` → «картинки», `media-src` → «ролики»,
     `frame-src`, `child-src` → «фреймы», `connect-src` → «запросы»,
     `worker-src` → «воркеры», `other` → «другое»; незнакомое — само имя;
   - `hostTitle(host: string): string`: `inline` → «встроенный код»,
     `eval` → «eval», `data` → «data:-адрес», `blob` → «blob:-адрес»,
     `other` → «другое», остальное — хост как есть;
   - `sortEntries(entries, order: "fresh" | "count")`: «свежие» — по `lastAt`
     по убыванию, «частые» — по `count` по убыванию, при равенстве — по
     `lastAt`. Функция чистая, массив не мутирует.
3. `src/screens/csp-reports/CspReportsScreen.tsx`:
   - `useApi(() => fetchCspSummary(api), [])`;
   - `Panel` с заголовком «Заблокированные адреса клиента», пояснением
     `HELP.csp.summary`, кнопкой «Обновить»;
   - над таблицей — `Select` порядка («Сначала свежие» / «Сначала частые») и
     `Input` «Хост содержит» (подстрока без учёта регистра по `host`);
   - таблица `DataTable`, колонки: «Что заблокировано» (`directiveGroup` и
     рядом имя директивы моноширинным мелким текстом), «Хост» (`hostTitle`;
     для настоящего хоста — моноширинно), «Раз» (`count`, вправо),
     «Последний раз» (`formatDateTime(lastAt)`);
   - если `overflow > 0` — `Notice tone="warning"`: «Сводка заполнена
     (`maxEntries` хостов): ещё `overflow` отчётов не поместились. Новые хосты
     появятся, когда старые устареют.» Числа вставляются как есть.
4. Состояния экрана:
   - загрузка — `Loading`;
   - ошибка (в том числе нет сети и нет права) — `ErrorNotice` с «Повторить»;
     текст ошибки берётся из ответа, свой не придумывается;
   - пусто — «Заблокированных адресов пока нет. Либо блокировать нечего, либо
     клиент с отчётами ещё не выкачен.»;
   - фильтр ничего не нашёл — «По фильтру ничего нет»;
   - ограничения аккаунта нет: раздел виден только с правом, экран его не
     перепроверяет.
5. `src/routes.ts`: в группу «Эксплуатация» после «Диагностики» —
   `{ id: "csp", title: "Блокировки клиента", hint: "Какие адреса политика
   источников клиента заблокировала и сколько раз", permission:
   "diagnostics.view", icon: … }`. Значок — из `lucide-react`, которого ещё
   нет в этом файле; подойдёт `ShieldX` или `Ban`, берётся тот, что есть в
   установленной версии.
6. `src/screens/sections.tsx`: `csp: () => <CspReportsScreen />`.
7. `src/ui/help.ts`: `csp: { summary: "…" }` — до 400 знаков, смысл: «Адреса,
   которые браузер игрока не загрузил из-за политики источников. Показаны
   только директива, хост и число; страницы и игроки не сохраняются. Нужное
   дополняется в список разрешённого отдельной правкой политики.»
8. `docs/29-admin-panel.md`: строка в таблице модулей рядом с «Диагностикой»
   (строка 70): «Блокировки клиента — владелец, админ — сводка адресов,
   заблокированных политикой источников (`35-stage4-plan.md` Р108)».

## Сценарий и интерфейс

Человек открывает «Эксплуатация → Блокировки клиента». Видит таблицу, самые
свежие сверху. Хочет понять, что чаще всего ломается, — меняет порядок на
«Сначала частые». Ищет сеть — вводит часть имени хоста. Нажимает «Обновить» —
сводка запрашивается заново. Состояния — шаг 4. На телефоне `DataTable`
показывает карточки сам; снимки проверяются на 320, 390, 768 и 1440 px.

## Тесты

Пишутся первым коммитом, до кода. Файл — `apps/admin/test/csp-reports.test.ts`
(образец — `test/diagnostics.test.ts`, `fakeFetch` и `json` из
`test/helpers.ts`).

- `fetchCspSummary` обращается к `/api/v1/admin/csp-reports` и разбирает
  ответ; запись с лишним полем не ломает разбор, а ответ без `entries`
  отвергается схемой;
- `directiveGroup`: `script-src-elem` → «скрипты», `font-src` → «шрифты»,
  `other` → «другое», незнакомое имя возвращается как есть;
- `hostTitle`: `inline` → «встроенный код», `other` → «другое»,
  `fonts.gstatic.com` без изменений;
- `sortEntries`: «свежие» ставит запись с большей `lastAt` выше, «частые» —
  с большим `count`, при равных `count` выше свежая; исходный массив не
  меняется;
- меню: раздел `csp` есть в группе «Эксплуатация», право —
  `diagnostics.view`, подсказка не длиннее 80 знаков;
- существующие `routes.test.ts` и `help.test.ts` проходят без правок самих
  тестов.
