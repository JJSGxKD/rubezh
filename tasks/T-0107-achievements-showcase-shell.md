# T-0107. Витрина достижений: категории, редкость, любимые и престиж в профиле и рейтинге

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0107.json)](README.md#значки-статуса) [![T-0106](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0106.json&label=T-0106)](T-0106-achievements-prestige-server.md)

## Зачем

Сервер (T-0106) отдаёт 49 достижений с категориями, лестницами, редкостью и престижем, а вкладка «Достижения» всё ещё плоский список заданий. После задачи игрок видит витрину: достижения по категориям, у лестницы одну карточку с текущей ступенью, у каждого «есть у N% игроков», скрытые с подсказкой, три любимых в профиле и очки престижа рядом с именем в рейтинге. Цель, которой гордятся и которую показывают, без влияния на баланс (`docs/39-retention-mechanics.md` К1, Р102).

## Решения

- **Витрина — содержимое вкладки «Достижения» на экране заданий,** не новый маршрут: вкладка и знак с числом наград на ней уже есть. `tasks.tsx` в этой вкладке рисует `<Achievements />` вместо списка заданий; знак вкладки по-прежнему считается по `GET /tasks` (готовые к забору).
- **Данные — `GET /api/v1/achievements`** (T-0106): `{ prestige, favorites, rarity: { population, shown, computedAt }, items }`. Забор награды — существующий `POST /tasks/:id/claim` (`state/tasks-api.ts`), после него витрина и знаки перечитываются.
- **Лестница — одна карточка.** Строки с общим `ladder` склеиваются, показывается *текущая* ступень: первая готовая к забору, иначе первая невыполненная, иначе последняя. На карточке «Ступень 2 из 4» и ряд точек по ступеням (закрашенные — выполненные). Название, цель, награда, престиж и редкость — у текущей ступени.
- **Редкость показывается, только если сервер отдал `percent`** (не `null`): «Есть у 12,3% игроков» и словесная ступень. Границы ступеней (старт, геймдизайнер калибрует): от 40% — «Обычное», от 15% — «Необычное», от 5% — «Редкое», ниже — «Очень редкое». Нет процента — строки редкости нет вовсе, пустого места тоже.
- **Скрытое:** пока не открыто, карточка «Скрытое достижение» с подсказкой `hint` и значком замка; ни прогресса, ни награды, ни редкости (сервер их и не отдаёт). Открытое — как обычное.
- **Любимые — до трёх, только открытые.** Звёздочка на карточке открытого достижения; `PUT /api/v1/achievements/favorites` с полным списком (порядок = слоты); оптимистично не рисуем: ждём ответ, на ошибке плашка. Ступень лестницы можно взять в любимые, пока она выполнена.
- **Престиж.** В шапке витрины «Престиж: N». В профиле: престиж и три любимых (из `GET /api/v1/achievements/summary`). В рейтинге рядом с именем игрока — `★ N`, если `N > 0`; у старого сервера поля нет — значок не рисуется.
- **Престиж в строках рейтинга добавляет серверная часть этой же задачи** (одно поле): модуль забегов не знает о достижениях, поэтому источник подключается так же, как сверка снаряжения (`RunLoadouts.provide`, `runs/run-loadouts.ts`) — порт `RunPrestige` в `runs/run-prestige.ts`, регистрация из `achievements.module.ts` через `AchievementsService.prestigeOf(ids)` (T-0106). Запрос престижа на всю таблицу один.
- **Цвета и значки только из токенов и набора значков проекта;** новых цветов нет. Ступени редкости различаются подписью и насыщенностью существующих токенов, не новыми оттенками.
- **«Настройки не отстают от игры»:** анимации витрины (появление карточек, заполнение полосы) — только `transform` и `opacity` и под тем же переключателем анимаций интерфейса, что лесенка появления строк в `task-row.tsx`; обязательного для чтения в них нет.

## Шаги по порядку

1. **Тесты первым коммитом.**
2. **`achievements-rules.ts`** (чистые функции):
   - `CATEGORY_ORDER = ["combat","collection","mastery","friends"]`;
   - `groupByCategory(items)`: категории в этом порядке, пустые опускаются, порядок внутри — как отдал сервер;
   - `cards(items)`: строки одной лестницы склеиваются в карточку `{ kind: "ladder", rungs, current }`, одиночные и скрытые — `{ kind: "single" }`; `currentRung(rungs)` по правилу из «Решений»;
   - `rarityTier(percent | null)` → `"common" | "uncommon" | "rare" | "epic" | null` (границы 40 / 15 / 5, включительно снизу);
   - `percentText(percent)`: `Intl.NumberFormat("ru-RU", { maximumFractionDigits: 1 })`, без хвостового нуля: `12.3` → «12,3», `100` → «100»;
   - `nextFavorites(current, id, unlocked): { ok: true; ids: string[] } | { ok: false; reason: "full" | "locked" }` (снять — всегда можно; не больше трёх; без повторов; порядок сохраняется);
   - `openedCount(items)`.
3. **`state/achievements-api.ts`:** Zod-схемы (`z/mini`, как в `tasks-api.ts`); вариант закрытого скрытого — отдельная ветка (`hidden: true, done: false` без остальных полей); поля, которых сервер мог не отдать (`percent`, `hint`, `filter`), необязательны; функции `load()`, `summary()`, `setFavorites(ids)`; код ошибки `achievement_not_unlocked`.
4. **`achievement-card.tsx`:** карточка по `cards(...)`: значок категории, название (`title`), строка цели (текст по виду цели — тот же сборщик, что в `task-row.tsx`, вынести в общую функцию без копирования; для `friends` и `account_level` — тексты ниже), полоса прогресса `value / target`, чип «+N престижа», редкость, состояние: «Забрать» (готово к забору), «Получено», либо прогресс; звёздочка «любимое» у открытых; ряд точек у лестницы.
5. **`achievements.tsx`:** шапка («Престиж: N», «Открыто X из Y»), полоса любимых (до трёх ячеек, пустая подсказка), секции по категориям; загрузка, ошибка с «Повторить», гость (`tasksAvailable()` ложно → плашка `tasks.guest`); `claim` через `api.claim(id)` с блокировкой двойного нажатия, плашкой ошибки, `loadWallet()`/`loadBadges()` и вызовом `onChanged()` (перечитывание заданий для знака вкладки); при забере — `track("achievement_unlocked", { achievement, kind, category, prestige })`.

## Чего не трогаем

- Серверные определения, редкость, избранное, престиж — готовы в T-0106; здесь только чтение и порт для строки рейтинга.
- Сезон рейтинга, награды за места, сравнение с друзьями: их задачи, таблицу рейтинга не перестраиваем.
- Вкладки «День», «Неделя», «Партнёры», очки заданий (T-0105), выбор вкладки (T-0098).
- Названия девяти старых достижений в `ru-tasks.json` (`achievement.<id>.name`) не удаляем: страховка для клиента, пока название не пришло с сервера.
- Достижения про сундуки и эволюции.

## Сценарий и интерфейс

Макета нет: собираем из существующих компонентов дизайн-системы и токенов.

- **Загрузка:** «Загружаем достижения…».
- **Пусто:** витрина пуста не бывает (определения в каталоге); если сервер отдал `items: []`, строка «Здесь пока пусто — новые цели появятся с обновлением каталога.» (существующий `tasks.empty`).
- **Ошибка / нет сети:** «Не удалось загрузить достижения — проверьте связь», «Повторить».
- **Ошибка избранного:** плашка «Не удалось сохранить любимые — попробуйте ещё раз», список прежний.
- **Любимых три, добавляем четвёртое:** подсказка «Любимых уже три — уберите одно, чтобы добавить другое».
- **Процент недоступен** (население ниже порога): карточка без строки редкости.
- **Гость (вход не настроен):** плашка `tasks.guest`, витрины нет.
- **Ограничение аккаунта:** на достижения не распространяется.

## Тесты

Первым коммитом.

- `packages/app-shell/test/achievements-rules.test.ts`:
  - `groupByCategory`: порядок категорий боевая → коллекция → мастерство → друзья; пустая категория опущена;

  - `nextFavorites`: добавить открытое к двум → три; добавить четвёртое → `full`; добавить закрытое → `locked`; снять → без него, порядок прочих сохранён; повторное добавление не дублирует;

## Критерии приёмки

- [ ] Тесты из раздела «Тесты» зелёные.
- [ ] Вкладка «Достижения»: секции по четырём категориям, лестница — одна карточка с текущей ступенью, скрытые закрыты подсказкой, редкость видна только при `percent`.
