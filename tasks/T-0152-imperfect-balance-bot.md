# T-0152. Бот калибровки с задержкой реакции и ограниченным вниманием

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0152.json)](README.md#значки-статуса)

## Зачем

Уклоняющийся бот калибровки видит всех врагов в радиусе 460 и пересчитывает
путь каждый тик. Пеших врагов медленнее игрока (190) он поэтому обходит без
единого попадания: в PR #379 (T-0117) без стрелка он дожил до потолка прогона
900 с, и кольца из 40 костяных ходоков этого не изменили. Коридор калибровки
держался только на снарядах огонька, а их по Р69 больше не будет. После задачи
бот реагирует с задержкой и следит только за несколькими ближайшими врагами,
как живой новичок, и толпа его догоняет. Тогда числа врагов снова видны в
таблице `pnpm balance:sim`, и T-0117 можно откалибровать.

## Решения

- **Решение пользователя от 18.10.2026:** чинить прибор, а не игру —
  неидеальный бот. Коридор 150–480 с, порог пассивного 90 с и тесты
  `balance-properties` не меняются (`content/balance-targets.ts` — цели,
  зафиксированные до калибровки, `docs/32-balance.md` §3.1).
- **Два несовершенства, оба без случайности.** Генератор случайных чисел бот
  не берёт: ни свой, ни `world.rng`. Иначе прогоны одного seed разошлись бы, а
  чужой поток случайности сдвинул бы весь мир.
  - **Задержка реакции** — бот пересчитывает направление раз в
    `reactionTicks` тиков (тик — 1/60 с), а между пересчётами идёт прежним
    курсом. Человек на телефоне реагирует за 0,2–0,3 с, а не за 17 мс.
  - **Ограниченное внимание** — в вектор «прочь» идут только `attentionCount`
    ближайших врагов в радиусе опасности, а не все. Человек не взвешивает
    всю толпу сразу: он уходит от тех, кто рядом, и упирается в следующих.
- **Пассивный бот не меняется:** он отвечает на вопрос, есть ли
  гарантированная смерть, и не двигается вовсе.
- **Подход к врагу и поиск сундука не меняются** (`APPROACH_RADIUS_UNITS`,
  `seekChest`), они только пересчитываются с тем же шагом реакции.
- **Значения выбираются замером по сетке**, правило выбора — в шаге 5.
  Исполнитель числа «на глаз» не ставит. Если ни одна пара сетки не проходит,
  он останавливается и пишет замеры в PR.
- Бот — инструмент команды, до игрока не доходит, поэтому `feat(dev)` и
  `release: patch` (`docs/09-ci-cd.md` §8.1).

## Шаги по порядку

Пункт — коммит.

1. **Тесты** (раздел «Тесты») — первым коммитом.
2. **Параметры бота** (`bot.ts`):

   ```ts
   export interface DodgingBotOptions {
     /** раз во сколько тиков бот пересчитывает курс; 1 — каждый тик */
     reactionTicks: number;
     /** сколько ближайших врагов в радиусе опасности он учитывает */
     attentionCount: number;
   }

   export const DODGING_BOT_DEFAULTS: DodgingBotOptions = { reactionTicks: …, attentionCount: … };

   export function createBot(skill: BotSkill, options: Partial<DodgingBotOptions> = {}): Bot
   ```

   - недостающие поля берутся из `DODGING_BOT_DEFAULTS`;
   - целое число ≥ 1 в обоих полях, иначе `throw new Error("Бот калибровки:
     reactionTicks должен быть целым числом от 1")` (для `attentionCount` —
     то же со своим именем);
   - пассивный бот параметры принимает и игнорирует;
   - до шага 5 в `DODGING_BOT_DEFAULTS` стоит `{ reactionTicks: 15,
     attentionCount: 4 }`.
3. **Задержка и внимание** (`dodgingBot(options)`):
   - счётчик вызовов в замыкании. Пересчёт курса — на вызовах с номером
     `0, reactionTicks, 2·reactionTicks, …`; на остальных — сразу
     `{ moveX: lastX, moveY: lastY }`, без запроса к сетке;
   - на пересчёте враги ближе `danger` не суммируются сразу, а отбираются
     `attentionCount` ближайших: массивы фиксированной длины
     (`Float64Array(attentionCount)` для расстояния и двух компонент),
     созданные один раз при создании бота, и вставка по возрастанию
     расстояния. При равном расстоянии порядок — порядок выдачи сетки.
     Вектор «прочь» считается по отобранным с тем же весом
     `1 - distance / danger`;
   - ближайший враг для подхода (`nearest`) по-прежнему ищется среди всех в
     радиусе `reach`; ветки «сундук» и «к ближайшему» не меняются;
   - комментарий у `dodgingBot` и абзац про уклоняющегося в шапке файла —
     почему так: без задержки и при полном обзоре бот обходит любую толпу
     медленнее себя, и калибровка видит только стрелков.
4. **Параметры в прогоне** (`simulate.ts`): `BalanceRunOptions` + поле
   `bot?: Partial<DodgingBotOptions>` с комментарием «параметры уклоняющегося
   бота для замера по сетке; не заданы — `DODGING_BOT_DEFAULTS`». Строка 88 —
   `createBot(options.skill, options.bot)`. В `BalanceRunResult` ничего не
   добавлять.
5. **Замер по сетке и выбор значений.**
   - Сетка: `reactionTicks` ∈ {6, 12, 18, 24, 30} (0,1–0,5 с) ×
     `attentionCount` ∈ {8, 6, 4, 3, 2} — 25 пар.
   - Набор забегов на пару — как в `balance-properties`: стартовые оружия
     первого уровня аккаунта × seed 1–5, `skill: "dodging"`, `maxSec: 900`,
     сводка — `summarizeRuns`. Для замера — временный файл
     `packages/core-game/test/tmp-bot-grid.test.ts` с одним `it`, который
     печатает таблицу через `console.log`. **Не коммитить.**
   - **(а) контент `dev`:** медиана в 150–480 с, `deathsBeforeMinuteRatio`
     ≤ 0,2, в забегах дольше 240 с сундук выпал хотя бы в половине, хотя бы
     один сундук открыт — те же условия, что в `balance-properties`.
   - **(б) контент T-0117:** перед вторым прогоном
     `git checkout 63593e0902e1aa13867809deab7a4370c045326f -- packages/core-game/src/content/enemies.ts packages/core-game/src/content/waves.ts`,
     после него — `git checkout HEAD -- packages/core-game/src/content/enemies.ts packages/core-game/src/content/waves.ts`.
     Условие: медиана ≤ 600 с и в потолок 900 с упёрлось не больше 5 забегов
     из 15. Эти файлы контента в коммиты не попадают.
   - **Правило выбора:** среди пар, прошедших (а) и (б), — наименьший
     `reactionTicks`, при нём — наибольший `attentionCount`. Нужен наименее
     несовершенный бот, который уже чувствует толпу. Выбранную пару вписать в
     `DODGING_BOT_DEFAULTS` с комментарием, откуда числа (замер по сетке,
     `docs/32-balance.md` §3.2).
   - **Ни одна пара не прошла** — остановиться: PR черновиком, в «Вопросах» —
     обе таблицы целиком. Сетку не расширять, условия не ослаблять.

## Тесты

Первым коммитом, `packages/core-game/test/balance-bot.test.ts`. Мир — фикстура,
как в `boss-hud.test.ts`: `createWorld({ seed: 1, enemies: [RAT], config: {
progressionEnabled: false } })`, `RAT = { id: "rat", hp: 10, speed: 1,
damage: 1, xp: 1, pattern: "swarm" }`, оружия нет, поэтому радиус опасности
— `DANGER_RADIUS_UNITS` (200). Игрок в (0, 0), координаты умножать на
`w.config.unitScale`. После расстановки или сдвига врагов — перестроить сетку:
`w.enemyGrid.rebuild(w.player.x, w.player.y, w.enemies.x, w.enemies.y,
w.enemies.alive, w.enemies.count)`.

- **Задержка реакции:** бот `{ reactionTicks: 5, attentionCount: 8 }`, враг в
  (100, 0). Первый вызов → `moveX < 0` (уходит влево). Враг переставлен в
  (−100, 0), сетка перестроена: вызовы 2–5 → `moveX < 0` (курс прежний), вызов
  6 → `moveX > 0`.
- **Задержка 1 — каждый тик:** то же с `reactionTicks: 1` → уже второй вызов
  даёт `moveX > 0`.
- **Внимание:** два врага слева в (−60, −5) и (−60, 5), шесть справа в
  (120, −30), (120, −15), (120, 0), (120, 15), (120, 30), (125, 0).
  - `{ reactionTicks: 1, attentionCount: 8 }` → `moveX < 0`: правая толпа
    перевешивает (6 × 0,4 против 2 × 0,7);
  - `{ reactionTicks: 1, attentionCount: 2 }` → `moveX > 0`: в счёт идут только
    два ближайших слева.
- **Повтор:** `simulateBalanceRun({ seed: 5, skill: "dodging", maxSec: 120,
  bot: { reactionTicks: 12, attentionCount: 3 } })` дважды → результаты
  `toEqual`.
- **Параметры проверяются:** `createBot("dodging", { reactionTicks: 0 })`,
  `{ reactionTicks: 2.5 }`, `{ attentionCount: 0 }` → бросают ошибку.
- **Пассивный не меняется:** `createBot("passive", { reactionTicks: 30 })` — три
  вызова `input` → `{ moveX: 0, moveY: 0 }`.
- **Умолчания из сетки:** `DODGING_BOT_DEFAULTS.reactionTicks` ∈
  {6, 12, 18, 24, 30}, `attentionCount` ∈ {8, 6, 4, 3, 2}.
- `balance-properties.test.ts` не правится и остаётся зелёным с новыми
  умолчаниями — это и есть условие (а).

## Вопросы к тимлиду

- Ответ claude-lead-1 на вопросы PR #382, 18.10.2026:
  - **Условие (б) снято.** Его не проходит ни одна пара, и дело не в боте.
    Бота убивают только снаряды: без огонька он гибнет на приходе
    босса-кастера (~750 с), без кастера 24 забега из 30 доходят до потолка

    WP36, T-0117 только добавляет врагов (`docs/35-stage4-plan.md`, WP36).

    правилу шага 5, а по смыслу: 0,3 с — обычная реакция человека на
    телефоне, четыре ближайших врага — сколько удерживает взгляд в толпе. На
    контенте `dev` пара проходит (а): медиана 387 с, смертей до минуты нет,
    сундуки на месте. Таблица шумная (соседние пары расходятся на сотню
    секунд при пяти seed), поэтому выбирать «по лучшей строке» нельзя.
  - Тест «умолчания из сетки» остаётся: 18 и 4 в ней есть.
