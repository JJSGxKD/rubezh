# T-0413. Флаги стран для панели — сжатые SVG владельца статическими файлами

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0413.json)](README.md#значки-статуса)

## Зачем

В панели страна узла Xray и ручного прокси — код текстом («NL»). Владелец
хочет флаги. Готовые SVG-флаги есть в его проекте VPNsib, но они тяжёлые:
252 файла, 6,4 МБ, отдельные — по 300–600 КБ. Задача сжимает их и кладёт
в панель статическими файлами. Подключает флаги к экранам T-0414.

## Решения

- **Р201** (`docs/35-stage4-plan.md`), решение владельца по флагам:
  - флаги — SVG владельца из VPNsib, переиспользовать разрешено,
    адаптировать можно;
  - сжатые svgo, статическими файлами панели;
  - грузятся по одному и лениво, код панели от них не тяжелеет.

Решения `claude-lead-1` по коду:

1. **`runner: owner`.** Источник флагов есть только на машине владельца —
   в рабочей копии `vpnsibcom_web`, папка `public/flags`. Обычно она лежит
   рядом с клоном этого репозитория: `../vpnsibcom_web/public/flags`. Путь
   передаётся скрипту аргументом и в репозиторий не пишется. Ни в
   скрипте, ни в документах нет путей машины владельца.
2. **Импорт — повторяемый скрипт**, а не ручное сжатие: флаги могут
   обновиться, и их перегоняют той же командой.
3. **Подключение к экранам — отдельной задачей** (T-0414, `runner: any`).
   Только эту часть нельзя сделать без машины владельца, и она должна быть
   маленькой.
4. **Берутся файлы с именем из трёх заглавных латинских букв**
   (`NLD.svg`). `GLOBAL.svg` и прочие пропускаются, и отчёт их называет.
   Файлы не из ISO 3166 (`ABH.svg`, `OST.svg`) тоже копируются: их просто
   не найдёт таблица кодов в T-0414.
5. **Имена в панели — строчными** (`nld.svg`): на Linux регистр различается
   (`CLAUDE.md`, «Окружение команды», имена ассетов — строчными).
6. **Сжатие** — svgo с `multipass: true`, `floatPrecision: 2` и
   `preset-default`. Рамка флага 52×40 единиц, в панели он ~21×16 px:
   сотая доля единицы невидима. `viewBox`, `width`, `height` и `xmlns`
   остаются: без них `<img>` не знает пропорций.
7. **svgo — точной версией в `devDependencies` корня.** Это последняя
   стабильная 4.x не моложе двух недель (`CLAUDE.md`, «Версии зависимостей —
   только точные»). У svgo нет postinstall-скрипта, `onlyBuiltDependencies`
   не трогаем.
8. **Безопасность файла** (их отдаёт свой домен панели). Скрипт и тест
   отвергают SVG, в котором есть:
   - `<script`, `<foreignObject`;
   - обработчики `on…=`;
   - внешние ссылки `href="http…"` / `xlink:href="http…"`.

## Как сейчас

- В `apps/admin` нет папки `public`. Vite (`apps/admin/vite.config.ts`,
  `base: "./"`) копирует `public/` в сборку как есть. Файл
  `public/flags/nld.svg` доступен по `./flags/nld.svg` от `index.html`:
  адреса панели — в хэше, страница всегда одна.
- Политика источников панели (`apps/admin/src/csp.ts:41`) — `img-src 'self'`
  и `data:`: свои файлы грузятся без правки политики.
- Источник — 252 файла `*.svg`, 6,4 МБ, рамка `viewBox="0 0 52 40"` с
  маской скруглённого прямоугольника. Самые тяжёлые — гербы: `MNP.svg`
  ~630 КБ, `ECU.svg` ~430 КБ.
- Корневые скрипты — `.mjs` в `scripts/<тема>/` (`scripts/fx/frames.mjs`,
  `scripts/content/run-export.mjs`). ESLint смотрит только `*.ts`/`*.tsx`
  (`eslint.config.js:12`).

## Шаги по порядку

1. **Тест первым коммитом** — `apps/admin/test/flag-files.test.ts` (раздел
   «Тесты»). До импорта он красный: папки нет.
2. **svgo** — `pnpm add -D -w svgo@<точная версия>` (решение 7). В
   `package.json` версия без `^` и `~`. В коммит идёт тот
   `pnpm-lock.yaml`, что записал pnpm.
3. **`scripts/admin/import-flags.mjs`**. Комментарий в шапке: откуда флаги
   (проект VPNsib владельца, Р201), запуск, что делает.
   Запуск: `node scripts/admin/import-flags.mjs <папка источника>`.
   - **Без аргумента или с несуществующей папкой** — сообщение «Укажите
     папку с флагами: node scripts/admin/import-flags.mjs
     ../vpnsibcom_web/public/flags» и код выхода 1.
   - **Выходная папка** — `apps/admin/public/flags/` от корня репозитория,
     через `node:path` и `import.meta.url`, без `\`. Создать, если нет.
     Удалить в ней прежние `*.svg`: только файлы этой папки, без рекурсии,
     через `fs.rm` каждого. Так папка повторяет источник.
   - **Для каждого файла `^[A-Z]{3}\.svg$`:**
     - прочитать;
     - `optimize(text, { multipass: true, floatPrecision: 2, plugins: ["preset-default"] })`;
     - проверить по решению 8, нарушение — выход 1 с именем файла;
     - проверить, что результат начинается с `<svg` и в нём есть
       `viewBox`;
     - записать `<имя строчными>.svg`.
   - **Отчёт в консоль:** сколько взято, какие пропущены, размер до и
     после (КБ, всего), пять самых тяжёлых после сжатия.
   - **Проверки решения 8** — одной функцией `svgProblem(text): string | null`
     внутри скрипта. Тест её не импортирует (TS-тест и `.mjs` без типов), а
     проверяет файлы своими выражениями — это вторая, независимая проверка.
4. **Запуск** на машине владельца с папкой из решения 1. Отчёт скрипта —
   в описание PR.
5. **Коммиты** (`CLAUDE.md`, «Коммиты»):
   - скрипт и svgo — одним;
   - файлы флагов — отдельным, `chore(admin): Добавь сжатые флаги стран`:
     в нём только `apps/admin/public/flags/*.svg`.
6. **Документы** — раздел «Документы».

## Тесты

Первым коммитом.

- `apps/admin/test/flag-files.test.ts` — читает
  `apps/admin/public/flags/` через `node:fs` и `node:path` от
  `import.meta.url`:
  - файлов не меньше 240;
  - каждое имя подходит под `/^[a-z]{3}\.svg$/`;
  - каждый файл начинается с `<svg`, в нём есть `viewBox` и нет ни одного
    совпадения с `/<script|<foreignObject|\son[a-z]+\s*=|href\s*=\s*["']https?:/i`;
  - каждый файл не больше 400 КБ, все вместе — не больше 5 МБ. Это
    проверка, что сжатие было: источник — 6,4 МБ. Не проходит — стоп,
    вопрос тимлиду с отчётом скрипта; пороги сам не поднимать;
  - есть `nld.svg`, `deu.svg`, `usa.svg`, `rus.svg`, `gbr.svg`.
- Там же — само выражение проверки на строках, чтобы оно не было пустым:
  - `<svg viewBox="0 0 1 1"><script>…</script></svg>` → совпадение;
  - `<svg onload="x()">` → совпадение;
  - `<svg><image href="https://example.com/a.png"/></svg>` → совпадение;
  - `<svg viewBox="0 0 52 40"><path d="M0 0h52v40H0z"/></svg>` → нет.
