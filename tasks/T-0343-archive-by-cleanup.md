# T-0343. PR задачи не правит epics.md и чужие задачи — перенос в архив уборкой тимлида

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0343.json)](README.md#значки-статуса) [![T-0208](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0208.json&label=T-0208)](archive/T-0208-board-contribution-periods.md)

## Зачем

Сейчас исполнитель закрывает задачу в своём PR: `status: done`, затем
`pnpm task fix` переносит файл в `tasks/archive/` и переписывает все ссылки
на него. Ссылки стоят в ячейке «Задачи» эпика — одной длинной строке таблицы
на эпик — и в строках значков задач, которые от неё зависят. Поэтому любые
два PR задач одного эпика конфликтуют в `tasks/epics.md`, а закрытие
задачи с зависимыми выходит за её зоны. После каждого мерджа тимлид вливает
`dev` в остальные ветки, перегенерирует `epics.md` и ждёт CI заново.

После задачи PR задачи меняет из `tasks/` только шапку своего файла, и файл
остаётся на месте. Переносит закрытые задачи в архив и правит ссылки на них
отдельная команда `pnpm task archive`. Её запускает тимлид в своём PR уборки,
не реже раза в пачку. PR задач друг с другом в `tasks/` больше не
конфликтуют.

## Решения

Решение владельца от 27.10.2026 (PR #517, ответы на три вопроса). Оно
меняет часть его же решения В1 от 24.10.2026
([T-0204](archive/T-0204-tasks-archive-folder.md), «Решения»): вместо
«переезд файла едет вместе с задачей» — «переезд делает уборка тимлида».
Остальное из В1 остаётся: две папки, переносит скрипт, а не человек, все
читатели видят обе папки. Ещё два ответа владельца — когда уборка и кто
приводит к новому виду открытые PR — ниже, в пунктах «Когда уборка» и «PR,
открытые до этой задачи».

**Корень проблемы — путь файла меняется внутри PR задачи.** От пути зависят
три вещи в чужих файлах:
- ячейка эпика — `epicTasksCell` строит ссылку от `task.path`;
- строка значков зависимых задач — `badgeLine`;
- ссылки в тексте других спецификаций — `withTaskLinks`.

Примеры: #506 (T-0209) поменял `epics.md` и строку значков T-0208, #504
(T-0144) — `epics.md`, T-0145 и T-0216. В T-0209 тимлиду пришлось вписать
T-0208 в `shared`, иначе `diff-check` был красным. Если путь в PR задачи не
меняется, не меняется и всё остальное.

**Варианты, которые рассмотрены и отклонены:**

| Вариант | Что убирает | Почему нет |
|---|---|---|
| (а) значок в ячейке ведёт на якорь доски или на путь, не зависящий от архива | конфликт в ячейке при закрытии | строки значков зависимых и ссылки в тексте спецификаций (их сотни, у T-0199 — 33) по-прежнему переписываются в PR задачи. Чтобы убрать и их, все ссылки между задачами пришлось бы вести через ветку `task-board`: два клика вместо одного, и у исполнителя-ИИ нет локального пути к файлу |
| (б) задачи эпика списком, по строке на задачу | часть конфликтов | git конфликтует и на соседних строках, и на двух вставках в одно место (проверено на песочнице 27.10.2026). Закрытие T-0119 и T-0120 или две новые задачи в конце списка всё равно спорят. Чужие строки значков переписываются, как и раньше, а таблицу эпиков пришлось бы ломать |
| (в) `epics.md` и перенос делает CI после мерджа в `dev` | все конфликты, в том числе между PR спецификаций | коммит бота в `dev` идёт без PR, а расчёт версии на таком коммите падает намеренно (`scripts/release/next-version.mjs:91–102`, «прямой push?»). Коммит токеном Actions не запускает CI, то есть в `dev` ляжет непроверенное. `task-board.yml` прямо обещает не пушить в `dev` (строки 1–6). Открыть PR сам workflow не может: PR от токена Actions не запускает проверки |
| (г) ссылки `tasks/T-NNNN` без слага и папки, с перенаправлением | — | перенаправлений файлов на GitHub нет. Остаются заглушки в `task-board` — тот же вариант (а) — или символьные ссылки, а на Windows они выезжают текстовыми файлами и тоже правятся при переносе |

**Выбрано: (в) без пуша ботом.** Перестройку делает не CI, а тимлид отдельным
PR. Что из этого следует:

- **`pnpm task fix` файлы не переносит.** Он ставит строки значков, ссылки и
  ячейки эпиков по тому, где файлы лежат сейчас. Пока файл не переехал, ни
  ячейка, ни чужие ссылки не меняются: статуса в них нет, он живой — в
  картинке значка.
- **Новая команда `pnpm task archive`** — то же, что `fix`, плюс перенос по
  статусу в обе стороны: закрытые (`done`, `cancelled`) уходят в
  `tasks/archive/`, открытые из архива возвращаются наверх. Запускает её
  только тимлид в отдельном PR уборки. В PR спецификаций её не запускают:
  два PR, перенёсшие разные наборы задач, спорили бы за те же строки.
- **Закрытая задача наверху — не ошибка, а «ждёт уборки».** `pnpm task check`
  её пропускает и печатает, сколько таких. Открытая задача в архиве
  по-прежнему ошибка, её чинит `pnpm task archive`.
- **PR задачи меняет из `tasks/` только `tasks/<свой файл>`.**
  `tasks/archive/<свой файл>` и `tasks/epics.md` из разрешённых в
  `outOfZone` убираются. Если они всё же в диффе, `diff-check` подсказывает,
  как вернуть файл.
- **Первая строка описания PR** — `Задача: tasks/T-NNNN-<slug>.md`. Путь в
  архив `pr-check` по-прежнему принимает: файл ищется в обеих папках ветки.
- **Когда уборка.** Не реже раза в пачку — перед релизным PR
  (`docs/38-release-plan.md` §2, шаг 1). Ещё — когда закрытых наверху
  набралось много. Ветка не `task/*`, заголовок
  `chore(tasks): Перенести закрытые задачи в архив`, метка `release: none`.
- **PR, открытые до этой задачи**, которые уже перенесли свой файл (#484,
  #486), приводит к новому виду тимлид при мердже — по подсказке
  `diff-check`. В коде переходного режима нет.

## Шаги по порядку

1. **Рефакторинг, отдельным коммитом, поведение не меняется.**
   - Новый файл `scripts/tasks/fix.mjs`. Это чистая функция без диска и git,
     как соседние модули, с комментарием-шапкой по их образцу:

     ```js
     /**
      * План `pnpm task fix` и `pnpm task archive` над файлами `tasks/`:
      * `files` — `[{ name, text }]`, имя — путь от `tasks/` (`T-0001-x.md`,
      * `archive/T-0001-x.md`, `epics.md`). Результат — `{ moves, files }`:
      * переносы `{ from, to }` и файлы с новым текстом по именам после
      * переносов. Перенесённый файл без правки текста в `files` не входит.
      */
     export function planFix(files, { archive })
     ```

   - Внутри — шаги (а)–(г) нынешнего `runFix`, но над списком в памяти:
     1. `archive: true` — переносы по `placementPath`: имя файла в списке
        меняется на новое;
     2. затем `readTasks` по новому списку;
     3. строки значков, `withTaskLinks`, `fixEpicCells` для `epics.md`;
     4. в `files` попадают тексты, которые изменились.

     Импорты — из `registry.mjs`, `task-file.mjs`, `epics.mjs`. Шаг (а)
     выполняется только при `archive: true`.
   - `runFix` в `task.mjs` получает параметр `{ archive }`:
     1. читает `readWorkingTasks()` и зовёт `planFix`;
     2. применяет план: `mkdirSync` папки архива, если есть переносы, затем
        `renameSync` по `moves`, затем `writeFileSync` по `files`;
     3. печатает те же строки, что сейчас.

     В этом коммите `case "fix"` зовёт `runFix({ archive: true })` —
     поведение прежнее.
2. **`pnpm task fix` без переноса, новая `pnpm task archive`.**
   - `task.mjs`:
     - `case "fix": return runFix({ archive: false });`
     - `case "archive": return runFix({ archive: true });`
   - Справка `USAGE` — вместо строки `fix` две, выровненные, как соседние:

     ```
     pnpm task fix                            поставить строки значков, ссылки и ячейки эпиков; файлы не переносит
     pnpm task archive                        уборка тимлида: закрытые задачи — в tasks/archive/, открытые — обратно, ссылки на них — заново
     ```

   - После вывода `runFix` (в обоих режимах) печатается
     `awaitingArchiveLine(tasks)` из шага 3, если она не `null`. Задачи для
     неё — реестр после применения плана.
3. **`registry.mjs` — закрытая задача наверху ждёт уборки.**
   - `checkPlacement(tasks)` — ошибка только для открытой задачи
     (`draft`, `ready`, `in-progress`) в архиве:
     `<path>: задача в статусе <status> лежит в архиве — вернёт наверх pnpm task archive`.
     `done` и `cancelled` наверху — без ошибки.
   - Новый экспорт `awaitingArchive(tasks)` — задачи в `done` и `cancelled`,
     у которых `path !== placementPath(task)`, по возрастанию `id`.
   - Новый экспорт `awaitingArchiveLine(tasks)` → `null`, если таких нет,
     иначе строка:
     `Ждут уборки в архив: <N> — <id через «, »>. Перенесёт pnpm task archive — уборка тимлида (tasks/README.md, «Уборка архива»).`
   - Новый экспорт `registrySummary(tasks)`. Строка:
     `Реестр задач в порядке: <всего> задач (открытых <O>, в архиве <A>, ждут уборки <W>).`
     - `O` — задачи в `draft`, `ready`, `in-progress`;
     - `A` — путь начинается с `archive/`;
     - `W` — `awaitingArchive(tasks).length`;
     - часть `, ждут уборки <W>` печатается только при `W > 0`.
   - Комментарии к `placementPath` и `checkPlacement` переписать: место по
     статусу — то, куда переносит `pnpm task archive`; закрытая задача
     наверху ждёт уборки.
4. **`task.mjs` — `runCheck`.** После зелёного `checkRegistry` печатает
   `registrySummary(readTasks(files).tasks)` вместо нынешнего подсчёта по
   папкам, а затем `awaitingArchiveLine`, если она не `null`.
5. **`zones.mjs` — зоны PR задачи.**
   - `outOfZone` разрешает `zones`, `shared` и только `tasks/<fileName>`.
     `tasks/archive/<fileName>` и `tasks/epics.md` из списка убираются.
     Комментарий: задача закрывается в своём PR на месте; в архив её и
     ссылки на неё переносит уборка тимлида (`pnpm task archive`), поэтому
     `tasks/archive/` и `tasks/epics.md` PR задачи не меняет.
   - Новый экспорт `outOfZoneHint(outside, fileName)`:
     - `null`, если ни один путь из `outside` не начинается с `tasks/`;
     - иначе строка:
       `В PR задачи из tasks/ меняется только её файл, и он остаётся в tasks/: перенос в архив и ссылки на него — уборка тимлида (tasks/README.md, «Уборка архива»). Если файл задачи уже в архиве — верни его: git mv tasks/archive/<fileName> tasks/<fileName>, затем pnpm task fix — ссылки в tasks/epics.md и других задачах вернутся к виду dev.`
6. **`task.mjs` — `runDiffCheck`.** После списка путей вне зон, перед
   строкой «Понадобился файл вне зон…», печатается
   `outOfZoneHint(outside, fileName)`, если она не `null`.
7. **`pr-check.mjs` — `checkTaskLine`.**
   - Текст ошибки:
     `задача: первая строка описания должна быть «Задача: tasks/${branch[1]}-….md»`.
   - Комментарий над регуляркой: задача закрывается в PR на месте, в
     `tasks/`; путь в архив тоже принимается — файл ищется в обеих папках
     ветки.
   - Регулярка и `taskFilesAt` не меняются.
8. **Документы** — раздел «Документы» ниже, тем же коммитом, что поведение
   (шаги 2–7).
9. **Закрыть задачу** по новому правилу: `status: done` в
   `tasks/T-0343-archive-by-cleanup.md`, файл остаётся в `tasks/`. `pnpm task check`
   зелёный и печатает «ждут уборки 1». `tasks/epics.md` в диффе PR нет.

## Чего не трогаем

- `scripts/tasks/epics.mjs`, `scripts/tasks/task-file.mjs`,
  `scripts/tasks/board*.mjs`, `scripts/tasks/git-io.mjs`. Ячейки, строки
  значков и доска уже строятся по фактическому `path` и читают обе папки.
  Менять их нечем.
- Вид `tasks/epics.md` и ячейки «Задачи». Как убрать конфликты между PR
  спецификаций в одной строке эпика — отдельный вопрос, не эта задача.
- `.github/workflows/*`. Уборку не автоматизируем: коммит без PR ломает
  расчёт версии (раздел «Решения», вариант (в)).
- Перенос нынешних задач. Сейчас в `tasks/` нет закрытых, уборка не нужна.
- Файлы чужих PR (#484, #486). Их приводит к новому виду тимлид при мердже.
- Скилл `task-spec` и `tasks/_template.md`. Фраза «строку значков и ячейку
  эпика ставит `pnpm task fix`» остаётся верной.

## Критерии приёмки

- [ ] `pnpm task fix` на рабочей копии с задачей в `done` наверху ничего не
      переносит и не меняет `epics.md` и чужие файлы задач. Он печатает
      «Ждут уборки в архив: …».
- [ ] `pnpm task archive` переносит закрытые задачи в `tasks/archive/`, а
      открытые из архива — наверх. Ссылки на них он правит в `epics.md`, в
      строках значков и в тексте задач. Повторный запуск — «Править нечего.».
- [ ] `pnpm task check` зелёный при закрытой задаче наверху и печатает
      «…, ждут уборки N».
- [ ] `pnpm task check` красный при открытой задаче в архиве, с подсказкой
      `pnpm task archive`.
- [ ] `outOfZone` разрешает из `tasks/` только `tasks/<fileName>`.
      `diff-check` с файлом задачи в архиве или с `tasks/epics.md` в диффе
      красный и печатает подсказку `git mv … && pnpm task fix`.
- [ ] Текст ошибки `checkTaskLine` называет `tasks/T-NNNN-….md`. Путь в
      архив по-прежнему принимается.
- [ ] Рефакторинг `planFix` — отдельным коммитом, до смены поведения.
      Тесты — первым коммитом.
- [ ] Документы из раздела «Документы» обновлены тем же коммитом, что
      поведение.
- [ ] Файл `tasks/T-0343-archive-by-cleanup.md` закрыт по новому правилу и
      остаётся в `tasks/`. В диффе PR нет ни `tasks/epics.md`, ни
      `tasks/archive/`.
- [ ] Гейт (`CLAUDE.md`) и `pnpm docs:check` зелёные.
