# T-0016. Пересчёт значков не отменяется пустыми прогонами

[![статус](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/JJSGxKD/rubezh/task-board/status/T-0016.json)](README.md#значки-статуса)

## Зачем

После мерджа PR не из ветки задачи значки статуса не пересчитываются. Мердж
даёт два прогона `task-board.yml` почти одновременно: `push` в `dev` и
`pull_request` с типом `closed`. У второго джоб пропускается, потому что ветка
PR — не `task/*`. Но `concurrency` объявлен на уровне всего workflow, и этот
пустой прогон отменяет настоящий пересчёт от `push`.

6.10.2026 так было при мердже #212: прогон 37452243327 (`push`, `dev`) отменён
прогоном 37452243929 (`pull_request`, `docs/home-mock-connection`, джоб
пропущен). Значки вернул ручной перезапуск.

## Решения

- `concurrency` переносится с уровня workflow на уровень джоба `board`. Ключи
  те же: `group: task-board`, `cancel-in-progress: true`. Группа джоба
  занимается, только когда джоб действительно запускается: пропущенный по `if`
  джоб никого не отменяет.
- Условие `if` у джоба, триггеры и шаги не меняются.

## Как сейчас

`.github/workflows/task-board.yml`:

- строки 44–48 — комментарий и `concurrency` на верхнем уровне:

  ```yaml
  # Пересчёт идемпотентен: нужен только последний. Параллельные прогоны спорили
  # бы за один force-push.
  concurrency:
    group: task-board
    cancel-in-progress: true
  ```

- строка 51 — джоб `board:`, строка 52 — `runs-on: ubuntu-latest`, строка
  57 — `if: >-` с фильтром веток задач.

## Шаги по порядку

1. Тест первым коммитом (раздел «Тесты»). Он должен упасть на нынешнем файле.
2. В `task-board.yml` убрать блок `concurrency` с верхнего уровня вместе с его
   комментарием.
3. В джоб `board` сразу после `runs-on: ubuntu-latest` вставить:

   ```yaml
       # Пересчёт идемпотентен: нужен только последний. Параллельные прогоны
       # спорили бы за один force-push. Группа — у джоба, а не у workflow:
       # пропущенный по `if` джоб (PR не из ветки задачи) её не занимает и не
       # отменяет пересчёт после мерджа в dev.
       concurrency:
         group: task-board
         cancel-in-progress: true
   ```

   Отступ — четыре пробела, как у `runs-on`.
4. `docs/09-ci-cd.md`, таблица workflow, строка `task-board.yml`. В конец
   описания, после «в `dev` и `main` не пушит», дописать: «. Прогоны с
   пропущенным джобом пересчёт не отменяют: `concurrency` — у джоба».

## Чего не трогаем

- Триггеры, условие `if`, шаги и права workflow.
- `scripts/tasks/**`: скрипты пересчёта в порядке.
- `pr-checks.yml` и `claim-check`.

## Тесты

Первым коммитом, новый `scripts/test/task-board-workflow.test.ts`. YAML-парсера
в зависимостях нет и не добавляем: файл читается текстом (`node:fs`), путь —
от корня репозитория через `fileURLToPath(new URL("../..", import.meta.url))`,
как в `scripts/test/action-pins.test.ts`.

- «у workflow нет concurrency верхнего уровня» — ни одна строка файла не
  совпадает с `/^concurrency:/m` (ключ с нулевым отступом) → совпадений нет;
- «concurrency объявлен у джоба board» — участок файла от строки
  `  board:` до конца содержит `/^    concurrency:\n      group: task-board\n      cancel-in-progress: true$/m` → есть совпадение;
- «группа объявлена один раз» — `group: task-board` встречается в файле ровно
  один раз.

Перед поиском перевести строки файла в LF: на Windows рабочая копия может быть
с CRLF.
