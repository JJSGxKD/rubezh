# Bullet-heaven / dungeon-runner мини-игра — проектная документация

Кроссплатформенная HTML5-игра в жанре bullet heaven / arcade dungeon-runner
(постоянная автоатака, вид которой задают оружие и улучшения, + перемещение
по бесконечному миру, прокачка за опыт внутри забега, roguelite-улучшения) для Telegram, MAX и VK.

## Ключевые решения (коротко)

- **Платформы**: **Telegram (первая цель)** → MAX (порт) → VK (опционально, есть нативная реклама). Приоритет пересмотрен: у команды уже есть продакшен-опыт и переносимый код под Telegram Mini Apps, цикл тестирования там короче, а схема валидации initData в MAX ещё не сверена с документацией. Обоснование — `02-roadmap.md` §«Приоритет платформ»
- **Движок и интерфейс**: Phaser 3 рисует только мир забега, меню и оверлеи — React-оболочка (решение этапа 2); сборка Vite, игровой цикл платформонезависим (`27-design-system-and-app-shell.md`)
- **Планирование**: этапы с оценкой в днях вместо календарных недель (`02-roadmap.md`); с этапа 2 версия назначается автоматически при мердже в `main` (`09-ci-cd.md` §8.1)
- **Бэкенд**: NestJS + PostgreSQL + Prisma + Redis (переиспользование текущего стека)
- **Монетизация**: только прямые IAP фиксированной стоимости (без рандома/лутбоксов) — скины, континью, сезонный контент
- **Архитектура**: `core-game` (общее) + `adapter-{telegram,max,vk}` (тонкий платформенный слой) + общий бэкенд
- **Команда**: 3 человека — техническая реализация (движок, бэкенд, платформенные адаптеры), геймдизайн/баланс/экономика (выделенная роль, профильное образование и опыт) и техническая адаптация ассетов/монетизация/QA (Unity/Gmod/Яндекс Игры опыт). Контент вынесен в данные специально под такое разделение, см. `01-tech-stack.md` §9 и `06-team-and-workflow.md`
- **Фазирование**: MVP (6-8 недель, `02-roadmap.md`) — один режим забега, простая мета-валюта, лидерборд в Telegram. Веб-версия, снаряжение с редкостью, рейтинговая лига, уровень аккаунта — сознательно вынесены в Фазу 2 (`10-progression-and-ladder.md`, `08-web-and-identity.md`), не блокируют публичный лонч
- **Юрлицо и деньги**: вся регистрация (ИП/самозанятость), налоги, договоры с партнёрами — на участнике 1. Доход делится ежемесячно после расходов/налога/погашения займа: 45% / 27.5% / 27.5%, формулы — `11-revenue-split.md`. Доля действует, только пока участник ведёт проект — правило жёсткое, без частичного вестинга
- **Аналитика — сквозное требование**: каждый модуль порождает события, продуктовая аналитика читается в своей админ-панели с правами по ролям и конструктором графиков, Grafana — только техническая. Данные, не записанные сегодня, задним числом не восстановятся — `22-analytics-and-metrics.md`, `29-admin-panel.md`
- **Админ-панель — одна на команду**: контент и баланс, аналитика, бухгалтерия проекта, игроки, рассылки в бота и посты в каналы, роли owner / admin / геймдизайнер / модератор / маркетолог / финансы — `29-admin-panel.md`
- **Рост**: виральность (реферальная программа + шеринг результатов и карточки профиля) и закупка трафика (партнёрская программа с RevShare и FTD) — `23-referral-and-partner-program.md`, `24-attribution-and-sharing.md`
- **Инженерная планка**: перенос кода из наших прошлых проектов — это адаптация с рефакторингом, а не копирование; каждый перенесённый блок проходит чек-листы безопасности и нагрузки и покрывается тестами. Правила — `13-reuse-from-vpnsibcom.md` §1, стандарты — `15-engineering-standards.md`
- **IP**: репозиторий публичный под source-available лицензией (не MIT/Apache) — посторонним нельзя монетизировать, участникам разработки можно переиспользовать код под другим брендом. Антифрод-логика и бэкенд — отдельно, не публикуются. Детали — `12-ip-and-licensing.md`
