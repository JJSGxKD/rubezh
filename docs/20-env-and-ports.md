# Окружения, переменные и порты

Справочник, к которому обращаются, когда нужно поднять проект, добавить
переменную или понять, кто занял порт. Шаблон со всеми переменными —
`.env.example` в корне; здесь — смысл, правила и различия между режимами.

Смежное: `09-ci-cd.md` §3 (секреты в CI) и §9 (окружения),
`15-engineering-standards.md` §9 (правила конфигурации),
`19-content-admin.md` (переменные админки).

---

## 1. Правила

1. **Один `.env` на весь монорепо, в корне.** Vite-приложения читают его
   через `envDir`, бэкенд — напрямую. Отдельные `.env` в пакетах не заводим:
   рассинхронизация между ними — источник багов, которые ищут часами.
2. **`.env` не коммитится.** В git только `.env.example` с пустыми
   значениями. Проверяется `gitleaks` в CI.
3. **Конфигурация валидируется при старте**, единой Zod-схемой. Невалидная
   конфигурация = процесс не поднимается. Это осознанное поведение: ошибка
   при старте дешевле неверного поведения в рантайме.
4. **У секретов не бывает значений по умолчанию.** Конструкция вида
   `process.env.SECRET || 'default'` запрещена — именно так в источнике
   переноса приложение могло стартовать с публично известным секретом
   (`13-reuse-from-vpnsibcom.md` §2.1 C).
5. **`process.env` в коде за пределами модуля конфигурации запрещён.**
   Доступ — через типизированный конфиг.
6. **Всё с префиксом `VITE_` попадает в клиентский бандл и является
   публичным** — независимо от названия. Секрет, оказавшийся там, считается
   скомпрометированным.
7. **У staging и production — отдельные наборы значений и отдельный бот.**
   Общий бот означает, что тестовая рассылка уходит реальным игрокам.

## 2. Карта портов

Порт **не выбирается на месте** — берётся отсюда. Все значения задаются
переменными, дефолты в коде совпадают с этой таблицей.

| Сервис | Переменная | dev | staging | production |
|---|---|---|---|---|
| Бэкенд API | `API_PORT` | `4000` | `127.0.0.1:4100` | не публикуется, только через Caddy |
| Dev-сервер Telegram | `WEB_TELEGRAM_PORT` | `5173` | — | — |
| Dev-сервер MAX | `WEB_MAX_PORT` | `5174` | — | — |
| Dev-сервер VK | `WEB_VK_PORT` | `5175` | — | — |
| Админка геймдизайнера | `ADMIN_PORT` | `5176` | через Caddy | через Caddy, отдельный поддомен |
| Кабинет партнёра | `PARTNER_CABINET_PORT` | `5177` | через Caddy | через Caddy, отдельный поддомен |
| PostgreSQL | `POSTGRES_PORT` | `127.0.0.1:5432` | `127.0.0.1:5532` | **не публикуется** |
| Redis | `REDIS_PORT` | `127.0.0.1:6379` | `127.0.0.1:6479` | **не публикуется** |
| Prometheus | `PROMETHEUS_PORT` | `9090` | `9190` | не публикуется |
| Grafana | `GRAFANA_PORT` | `3001` | `3101` | через Caddy, поддомен |
| Caddy | `HTTP_PORT` / `HTTPS_PORT` | — | `80` / `443` | `80` / `443` |

Три правила, которые из таблицы не видны:

- **Смещение staging = dev + 100** для инфраструктурных сервисов. Оба
  окружения живут на одном VPS (`09-ci-cd.md` §9), и без смещения они
  подрались бы за порты.
- **В production наружу смотрит только Caddy.** Порты БД, Redis и Prometheus
  не публикуются вовсе — это пункт чек-листа безопасности
  (`15-engineering-standards.md` §7). В источнике переноса прод-compose
  публиковал `5432` и `6379` на хост; мы так не делаем.
- **В dev БД и Redis публикуются на `127.0.0.1`, а не на `0.0.0.0`.** Иначе
  Postgres с паролем `postgres` доступен всей локальной сети — включая
  публичный Wi-Fi в кафе.

**Dev-серверы Vite запускаются со `strictPort: true`.** Занятый порт должен
падать с явной ошибкой, а не молча уезжать на соседний: иначе Telegram-сборка
внезапно оказывается на `5174`, а вы полчаса отлаживаете «неправильный
адаптер».

Фронтенда как сервиса в staging и production не существует — там статика,
собранная Vite и разложенная на CDN с хэшами в именах файлов
(`09-ci-cd.md` §5).

## 3. Группы переменных

Полный список с комментариями — в `.env.example`. Здесь — назначение групп и
где брать значения.

| Группа | Что внутри | Где брать значения |
|---|---|---|
| 1. Окружение | `NODE_ENV`, `APP_PLATFORM`, `APP_VERSION` | задаётся сборкой; `APP_VERSION` — из тега релиза |
| 2. Порты | см. §2 | из таблицы выше |
| 3. База данных | `POSTGRES_*`, `DATABASE_URL` | dev — из compose; прод — секреты окружения |
| 4. Redis | `REDIS_*` | там же |
| 5. Авторизация | `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, сроки жизни, `INIT_DATA_EXPIRES_IN`, cookie | генерируется: `openssl rand -hex 32`, разные значения для access и refresh |
| 6. CORS и адреса | `ALLOWED_ORIGINS`, `PUBLIC_*` | реальные домены мини-приложений; `*` в проде запрещён |
| 7. Платформы | токены ботов, ключи Bridge, OAuth | из кабинетов площадок; для staging — **отдельный** бот |
| 8. Платежи | webhook-секрет, RU-эквайринг | из кабинета провайдера |
| 9. Реклама | `ADS_SESSION_SECRET`, ключи сетей | из кабинетов сетей; порядок и активность сетей — данные в БД, не переменные |
| 10. Наблюдаемость | `LOG_LEVEL`, треды Telegram, Sentry, Grafana | id тредов — из супергруппы алертов |
| 11. Админка | `ADMIN_TELEGRAM_IDS`, `ADMIN_SESSION_SECRET`, `CONTENT_PUBLISH_REQUIRE_SIMULATION` | см. `19-content-admin.md` |
| 12. Программы роста и аналитика | домен редиректа, TTL клика, секрет подписи шеринга, кеш карточек, read-only пользователь Grafana, срок хранения сырых персональных данных | `22-analytics-and-metrics.md`, `23-referral-and-partner-program.md`, `24-attribution-and-sharing.md` |
| 13. Публичные для клиента | `VITE_*` | только не-секреты |

## 4. Работа в dev

Один раз на машину:

```bash
corepack enable pnpm
```

В корне репозитория:

```bash
cp .env.example .env
pnpm install
docker compose up -d
```

Проверить, что инфраструктура поднялась:

```bash
docker compose ps
```

Запуск (каждая команда — свой терминал, порты не конфликтуют):

```bash
pnpm dev:backend     # API на http://localhost:4000
pnpm dev:telegram    # http://localhost:5173
pnpm dev:max         # http://localhost:5174
pnpm dev:vk          # http://localhost:5175
```

Миграции и Prisma:

```bash
pnpm --filter backend-api prisma:migrate    # создать миграцию в dev
pnpm --filter backend-api prisma:generate   # перегенерировать клиент
```

Остановить инфраструктуру: `docker compose down` (данные останутся в томах),
`docker compose down -v` — вместе с данными.

**Тестирование Mini App локально.** Telegram не откроет `http://localhost` как
Mini App — нужен публичный HTTPS-адрес. Варианты: туннель (cloudflared,
`ngrok`) на порт `5173` и адрес туннеля в настройках тестового бота, либо
`vite --host` плюс проброс. Адрес туннеля добавляется в `ALLOWED_ORIGINS`,
иначе CORS отклонит запросы к API.

**Заполнять `.env` реальными ключами не обязательно, чтобы начать.** Игровой
цикл (недели 1-2 роадмапа) работает без бэкенда вообще. Ключи нужны с недели 3.

## 5. Работа в production

Схема — Docker Compose на VPS (`01-tech-stack.md` §10), развёртывание из
образа, собранного в CI (`09-ci-cd.md` §10). Прод-compose лежит **не в этом
файле**: `docker-compose.yml` в корне — только dev.

Отличия прода от dev, все существенные:

| Аспект | dev | production |
|---|---|---|
| Источник образа | локальная сборка | образ из GHCR по тегу, собранный CI |
| Порты БД/Redis | `127.0.0.1` | не публикуются вовсе |
| Вход снаружи | напрямую в Vite/API | только Caddy на `80`/`443`, автоматический TLS |
| Секреты | `.env` в корне | секреты окружения на хосте, права `600`, владелец — сервисный пользователь |
| Фронтенд | dev-сервер Vite | статика на CDN с хэшами в именах |
| Миграции | `prisma migrate dev` вручную | `prisma migrate deploy` в `entrypoint` до старта приложения |
| `NODE_ENV` | `development` | `production` |
| `LOG_LEVEL` | `debug` | `info` |
| `COOKIE_SECURE` | `false` | `true` |
| CORS | localhost-адреса | только реальные домены мини-приложений |

Порядок выката (подробно — `09-ci-cd.md` §10):

1. CI собирает образ, тегирует и пушит в GHCR.
2. На VPS: `docker compose pull && docker compose up -d` для нужного
   compose-проекта.
3. `entrypoint` применяет `prisma migrate deploy` **до** старта приложения.
4. Healthcheck подтверждает готовность; при провале — откат к предыдущему
   тегу образа.

**Перед миграцией в проде — свежий бэкап и проверка, что он читается.**
Бэкап, из которого ни разу не восстанавливались, бэкапом не является.

**Схема миграций expand → migrate → contract** обязательна: из-за модерации
площадок старые клиенты живут днями и продолжают дёргать API
(`09-ci-cd.md` §4). Удаление колонки в том же релизе, где прекратилась
запись, запрещено.

## 6. Staging

Отдельный compose-проект на том же VPS: свои тома, своя БД, свой бот, свои
тестовые ключи провайдеров, порты со смещением +100 (§2).

Компромисс осознанный: отдельный сервер удваивает расходы, а изоляции на
уровне compose-проекта достаточно. Ограничение честное — нагрузочные прогоны
на staging искажают картину прода, их делаем в окно низкой нагрузки или на
временном хосте (`17-testing-strategy.md` §7).

## 7. Как добавить новую переменную

1. Добавить в `.env.example` — в нужную группу, с комментарием «зачем» и с
   пустым значением, если это секрет.
2. Добавить в Zod-схему конфигурации: тип, обязательность, значение по
   умолчанию (для не-секретов).
3. Добавить в секреты CI для тех пар `platform × env`, где она нужна
   (`09-ci-cd.md` §3).
4. Задать значение на staging и production **до** выката кода, который её
   читает. Иначе приложение не поднимется — и это правильное поведение, но
   узнать о нём лучше не в момент релиза.
5. Если это порт — внести в таблицу §2, включая staging-смещение.
6. Предупредить команду: у остальных `.env` не обновится сам.

## 8. Диагностика

| Симптом | Причина и что делать |
|---|---|
| Приложение падает при старте с текстом про переменную | Так и задумано: не задана обязательная переменная. Сверить с `.env.example` |
| `EADDRINUSE` на dev-сервере | Порт занят — из-за `strictPort` он падает явно. Посмотреть, что висит, или сменить порт в `.env` |
| Vite не видит переменные | Читаются только `VITE_*`; остальное в бандл не попадает намеренно |
| CORS-ошибка в браузере | Адрес не в `ALLOWED_ORIGINS`. При работе через туннель добавить адрес туннеля |
| Prisma не подключается | `DATABASE_URL` указывает на `localhost`, а приложение в контейнере: там нужен host = имя сервиса compose |
| Telegram не открывает Mini App | `http://localhost` не подходит, нужен публичный HTTPS — см. §4 |
| Всё поднялось, но API отвечает 401 | Не заданы `JWT_*` или `TELEGRAM_BOT_TOKEN`, либо истекло окно `INIT_DATA_EXPIRES_IN` |
