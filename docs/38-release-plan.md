# План выпусков

Решение участника 1 от 13.10.2026: **выпуск в `main` — поездом раз в
неделю**. Готовое уходит игрокам каждую неделю, а не копится в `dev`
месяцами. Как устроены ветки, метки и номера версий —
`09-ci-cd.md` §8.1, `CLAUDE.md`, «Версии и заголовки PR».

## 1. Поезд

- **Когда.** Раз в неделю, по четвергам. Срочное исправление — в любой
  день, PR прямо в `main` (`CLAUDE.md`, «Ветки»).
- **Что едет.** Всё, что влито в `dev` к отсечке и прошло CI. Поезд не ждёт
  задачу: не успела — едет следующим. Недоделанное в `dev` не вливается
  или спрятано за флагом (`09-ci-cd.md` §11).
- **Версия — цель, а не условие.** У задачи поле `version` — в какой поезд
  она целит. Потоки исполнителей берут задачи ближней версии первыми
  (`pnpm task next`). Номер выпуска считает CI по меткам PR: `feat` —
  следующая минорная, только `fix` — патч.

## 2. Отсечка — порядок тимлида

1. **`dev` зелёный.** CI вершины `dev` прошёл, открытых красных вопросов по
   влитому нет.
2. **Миграции** с прошлого выпуска — только добавляют (expand,
   `09-ci-cd.md` §4). Ломающая — не в этот поезд.
3. **Релизный PR** `dev` → `main`, заголовок
   `chore(release): Выпустить vX.Y.Z`, без метки:
   - что едет, коротко по темам;
   - что сделать до и после выката руками (настройки панели, ключи);
   - чего нет и почему.
4. **Мердж** merge-коммитом → CI выпускает тег и выкатывает на прод.
5. **Проверка прода** — раздел 3, отметками в комментарии к релизному PR.
6. **Сводка команде** — в чат, как после любого мерджа.

## 3. Проверка прода после выката

- `https://api.<домен>/health/ready` — `200`.
- Игра открывается в Telegram, через CDN (`docs/20-env-and-ports.md` §2.2):
  - у страницы `Cache-Control: no-cache`;
  - у файлов с хэшем — `immutable`.
- Забег проходит до конца, награда начислена.
- Магазин открывается; оплата — по состоянию `payments.stars` в панели.
- Панель: вход через бота, «Сводка» без ошибок.
- Бот: `/start` отвечает карточкой.
- `docker compose ps` на сервере — все сервисы `healthy`.
- В логах API (`docker compose logs api`) и потоке «Сбои сервера» — нет
  всплеска ошибок за первый час.

Не прошло — откат на прежний тег (`09-ci-cd.md` §11): `deploy.yml` вручную
с версией прошлого выпуска.

## 5. Как задача получает версию

- Тимлид ставит `version` при заведении задачи — ближнюю, если задача
  нужна игрокам скоро, и дальнюю, если зависит от несделанного.
- Задача не успела к поезду — версия сдвигается на следующую одной
  правкой шапки. Это видно в диффе.
- Срочное исправление в `main` — без версии: оно едет сразу.
