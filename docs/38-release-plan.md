# План выпусков

Решение владельца от 13.10.2026 (Р103, `35-stage4-plan.md`): **выпуск в
`main` — пачками очереди, а не по календарю**. Пачка уходит, когда собрана и
`dev` зелёный; ждать четверга или другой даты не надо. Приоритет этапа —
удержание игроков и интерес к самим забегам (Р102): то, что сделало забег
интереснее, должно доходить до игроков сразу, как готово. Как устроены
ветки, метки и номера версий — `09-ci-cd.md` §8.1, `CLAUDE.md`, «Версии и
заголовки PR».

До перехода на пачки вышли v0.7.0 и v0.8.0/v0.8.1: у их задач поля `batch`
нет, а старое поле `version` из шапок убрано.

## 1. Пачки

- **Что это.** Пачка — номер очереди: 1, 2, 3 и так далее. Это набор задач,
  которые уходят в `main` одним релизным PR. Номер задачи — поле `batch` в
  шапке (`tasks/README.md`, «Поля задачи»).
- **Номера абсолютные и только растут.** Выпущенная пачка больше не
  используется: новая задача получает номер ещё не выпущенной пачки, а если
  такой нет — следующий по счёту.
- **Когда пачка уходит в `main`.** Когда все её задачи влиты в `dev`
  (`done`) и `dev` зелёный. Не влитое переносится в следующую пачку правкой
  одной строки в шапке (раздел 5), а не держит остальных. Тимлид выпускает
  пачку релизным PR (раздел 2).
- **Что едет.** Вся ветка `dev` на момент отсечки: выборочно задачи из неё не
  вынуть. Потоки берут задачи по порядку пачек (`pnpm task next`), поэтому в
  `dev` лежит пачка и то, что успело из следующей, — оно едет вместе с ней.
  Недоделанное в `dev` не вливается или спрятано за флагом
  (`09-ci-cd.md` §11).
- **Срочное исправление — в любой день**, PR прямо в `main`, мимо пачек
  (`CLAUDE.md`, «Ветки»). Такому PR пачка не нужна.
- **Версия — результат, а не заголовок пачки.** Номер выпуска (`vX.Y.Z`)
  считает CI по меткам PR: есть `feat` — следующая минорная, только `fix` —
  патч. Пачка с версией не связана.

## 2. Отсечка — порядок тимлида

1. **Пачка собрана.** Её задачи влиты в `dev`; не влитые перенесены в
   следующую пачку (раздел 5). `pnpm task check` проходит.
2. **`dev` зелёный.** CI вершины `dev` прошёл, открытых красных вопросов по
   влитому нет.
3. **Миграции** с прошлого выпуска — только добавляют (expand,
   `09-ci-cd.md` §4). Ломающая — не в эту пачку.
4. **Релизный PR** `dev` → `main`, заголовок
   `chore(release): Выпустить vX.Y.Z`, без метки:
   - что едет, коротко по темам, и номер пачки;
   - что сделать до и после выката руками (настройки панели, ключи);
   - чего нет и почему.
5. **Мердж** merge-коммитом → CI выпускает тег и выкатывает на прод.
6. **Проверка прода** — раздел 3, отметками в комментарии к релизному PR.
7. **Сводка команде** — в чат, как после любого мерджа.

## 3. Проверка прода после выката

- `https://api.<домен>/health/ready` — `200`.
- Игра открывается в Telegram, через CDN (`docs/20-env-and-ports.md` §2.2):
  - у страницы `Cache-Control: no-cache`;
  - у файлов с хэшем — `immutable`.
- Забег проходит до конца, награда начислена.
- Магазин открывается; оплата — по состоянию `payments.stars` в панели.
- Панель: вход через бота, «Сводка» без ошибок.
- Бот: `/start` отвечает карточкой.
- `docker compose ps` на сервере — все сервисы `healthy`.
- В логах API (`docker compose logs api`) и потоке «Сбои сервера» — нет
  всплеска ошибок за первый час.

Не прошло — откат на прежний тег (`09-ci-cd.md` §11): `deploy.yml` вручную
с версией прошлого выпуска.

## 5. Как задача получает пачку

- **Тимлид ставит `batch` при заведении задачи.** Ближняя невыпущенная
  пачка — если задача нужна игрокам скоро и не зависит от несделанного;
  более дальняя — если зависит от задачи, которая едет позже.
- **Порядок зависимостей проверяется.** `pnpm task check` падает, если
  задача зависит (`depends_on`) от задачи более поздней пачки или если задача
  с пачкой зависит от задачи без пачки. Сделанные и отменённые зависимости
  не в счёт. Ошибка называет обе задачи и обе пачки: исправляется переносом
  одной из них.
- **Не успела к выпуску — переносится.** Тимлид одной правкой строки
  `batch` в шапке отправляет задачу в следующую пачку; это видно в диффе.
  Зависящие от неё задачи переносятся вместе с ней — иначе проверка не даст
  влить правку.
- **Задача без `batch` не в очереди.** Ни одна пачка её не ждёт, потоки
  берут такую после всех задач с пачкой. Годится для задач в `draft`.
- **После выхода пачки её номер не используется.** У `done` и `cancelled`
  поле можно оставить как память о пачке или убрать: ни проверки, ни доска
  его у таких задач не читают.
- **Срочное исправление в `main`** — вне пачек: оно едет сразу.
