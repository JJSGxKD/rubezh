# Атрибуция, редирект-страница и виральный шеринг

Документ описывает путь от клика по ссылке до атрибутированного игрока и
обратный виток: как игрок сам порождает новые ссылки.

Смежное: `23-referral-and-partner-program.md` (кому и за что платим),
`22-analytics-and-metrics.md` (что считаем), `08-web-and-identity.md`
(веб-версия и идентичность), `10-progression-and-ladder.md` (что показываем
в карточке профиля).

---

## 1. Общая схема

```
Ссылка (реф / партнёрская / из шеринга)
        │
        ▼
Редирект-страница на нашем домене  ──►  запись клика в БД, короткий click_id
        │
        ├── прямой переход на платформу (deep link с click_id)
        └── хаб-страница с кнопками платформ (каждая кнопка несёт тот же click_id)
        │
        ▼
Первый запуск Mini App: startParam = click_id
        │
        ▼
Сервер связывает клик с пользователем → атрибуция → награды
```

---

## 2. Почему своя редирект-страница, а не прямая ссылка на платформу

Соблазн — давать сразу `t.me/bot/app?startapp=...`. Так делать нельзя, и
причин четыре.

1. **Параметр запуска слишком мал.** У Telegram `startapp` ограничен по
   длине и алфавиту; упаковать в него UTM-метки, кампанию, идентификатор
   партнёра и тип креатива невозможно. Короткий `click_id` — единственная
   схема, которая масштабируется: сам параметр остаётся коротким, а данные
   лежат в строке БД.
2. **Данные видны только до перехода.** `Referer`, User-Agent, IP, язык,
   часовой пояс доступны на нашей странице. После перехода в мессенджер их
   уже нет. Это же — исходные данные для антифрода (§5).
3. **Без страницы неизвестен знаменатель.** Сколько было кликов — база всех
   конверсий. Без неё «100 регистраций» ничего не значит: из тысячи кликов
   это провал, из ста двадцати — отличный результат.
4. **Цель можно менять без смены ссылки.** Партнёр разместил ссылку в
   закреплённом посте полгода назад; мы добавили VK — ссылка продолжает
   работать и ведёт куда нужно.

## 3. Устройство редирект-страницы

### 3.1 Адрес

```
https://<домен>/r/<code>
```

`code` — короткий (8-10 символов) **непредсказуемый** идентификатор. Два
требования, оба существенные:

- **не инкрементальный** — иначе перебором можно просканировать чужие
  ссылки и накрутить чужие клики;
- **сам по себе не содержит данных** — это ключ к строке в БД, а не
  упаковка. Идентификатор партнёра, зашитый в код ссылки, читается любым
  желающим и провоцирует подмену.

### 3.2 Что собираем при клике

| Данные | Источник | Зачем |
|---|---|---|
| `code` | путь | какая ссылка сработала |
| UTM: source, medium, campaign, content, term | query | разрезы в аналитике |
| `Referer` | заголовок | откуда пришли, если браузер отдал |
| User-Agent | заголовок | устройство, ОС, платформа |
| IP | соединение | гео, антифрод (хранение — §6) |
| `Accept-Language` | заголовок | язык интерфейса при первом запуске |
| Часовой пояс, разрешение экрана | JS, если исполнился | точность гео и антифрод-отпечаток |
| Метка времени | сервер | скорость конверсии клик → запуск |

Всё это пишется одной строкой `click` с уникальным `click_id`. Запись —
асинхронная, редирект не ждёт её завершения: страница должна отдаваться
мгновенно, иначе часть переходов теряется на медленной сети.

### 3.3 Превью ссылки — отдельная задача

Мессенджер, получив ссылку, сам запрашивает страницу, чтобы построить
превью. Отсюда два требования:

- страница отдаёт корректные OG-теги: заголовок, описание, картинку.
  Ссылка без превью в чате конвертит заметно хуже — а для шеринга (§7) это
  основной канал;
- **запросы краулеров не считаются кликами.** Иначе одна отправка ссылки в
  чат порождает фантомный клик, и конверсия оказывается заниженной, а
  метрика «клики без запусков» ложно сигналит о накрутке.

### 3.4 Куда ведём

Два режима, выбор — свойство самой ссылки:

- **Прямой** — сразу на конкретную платформу, deep link с `click_id` в
  параметре запуска. Годится, когда точно известно, где аудитория: ссылка в
  Telegram-канале ведёт в Telegram.
- **Через хаб** (§4) — когда площадка размещения не совпадает с целевой
  платформой или неизвестна: сайт, видео, подкаст, офлайн.

## 4. Хаб-страница

Страница на сайте с кнопками «Играть в Telegram», «в MAX», «в VK» и
«в браузере».

**Главное свойство: атрибуция не теряется при выборе платформы.** Каждая
кнопка уже несёт тот же самый `click_id`, полученный на редиректе. Игрок
может открыть VK вместо Telegram — источник, кампания и партнёр останутся
теми же.

Дополнительно:

- порядок и подсветка кнопок подстраиваются под устройство: на iOS сначала
  то, что там реально работает;
- выбор платформы пишется событием `hub_platform_chosen` — это данные о
  том, какая площадка нужна аудитории конкретного канала, и они влияют на
  приоритет портирования;
- хаб — часть веб-версии (`08-web-and-identity.md`), не отдельный продукт;
- кнопка «в браузере» ведёт в гостевую игру без входа
  (`08-web-and-identity.md` §7): код клика приходит туда параметром адреса,
  и атрибуция не теряется даже у того, кто не стал ставить мини-приложение.

## 5. Связывание клика с игроком

1. Клиент при первом запуске читает параметр запуска платформы и передаёт
   его на бэкенд вместе с данными авторизации. В Telegram параметр уже
   лежит в подписанном `initData` (`start_param`), и сервер берёт его
   оттуда, а не из тела запроса. Клик в параметре — `c-<код>`, код из 6–32
   латинских букв и цифр: формат занят заранее, чтобы запуски по будущим
   редирект-ссылкам узнавались с первого дня
   (`backend/api/src/modules/attribution/start-param.ts`).
2. Сервер находит строку клика по `click_id`, проверяет срок жизни
   (гипотеза — 30 суток: дольше связь между кликом и запуском
   недостоверна).
3. Применяет правила приоритета атрибуции
   (`23-referral-and-partner-program.md` §5).
4. Пишет `Session` и `Acquisition` — модели уже описаны в
   `13-reuse-from-vpnsibcom.md` §6, здесь они получают ещё и `click_id`.
5. Порождает события `app_first_open` и `user_registered` с приложенным
   снимком атрибуции (`22-analytics-and-metrics.md` §3.1).

**Устойчивость.** Параметр запуска теряется чаще, чем кажется: игрок открыл
ссылку, отвлёкся, вернулся в приложение из истории. Поэтому: клик живёт 30
суток, а промокод (`23-...` §3) — способ восстановить атрибуцию вручную,
когда параметр не дошёл.

## 6. Антифрод и приватность

**Сигналы, ради которых всё и собирается:**

- клики без последующих запусков — доля и её всплески;
- много кликов с одного IP или подсети за короткое время;
- одинаковый отпечаток устройства у «разных» игроков;
- аномально быстрая цепочка клик → регистрация → платёж;
- `Referer` с ферм и агрегаторов;
- расхождение между заявленным клиентом временем и серверным.

Сырые данные хранятся ограниченный срок, затем усечённый IP и хэш
(`22-analytics-and-metrics.md` §7).

**Приватность.** IP и User-Agent — персональные данные; юридическая сторона
отмечена как требующая проверки юристом (`03-notes-and-risks.md`). Правила:
собираем только то, что используется в конкретных проверках и отчётах;
партнёрам и игрокам сырые данные не показываем; данные клика не связываем с
профилем глубже, чем нужно для атрибуции.

## 7. Виральный шеринг

Обратный виток: игрок сам порождает ссылки. Это дешевле любого закупленного
трафика и единственный масштабируемый источник роста при K ≥ 1
(`22-analytics-and-metrics.md` §5.6).

### 7.1 Чем делятся

**Результат забега.** Карточка со счётом, достигнутой волной, персонажем,
временем. Уместна сразу после забега.

**Карточка профиля («престиж»).** Уровень аккаунта, персонаж, снаряжение,
ключевая статистика, титулы и достижения — то, что описано в
`10-progression-and-ladder.md`. Это объект хвастовства, а не отчёт: игрок
делится им, потому что им приятно обладать.

**Оформление карточки зависит от статистики.** Рамка, фон, эффекты
меняются с уровнем, лигой, редкими достижениями. Смысл двойной: во-первых,
это награда, которую видно другим; во-вторых, разные карточки дают
естественный A/B — видно, какое оформление приводит больше переходов.

Варианты оформления — данные, а не код: набор, условия получения и тексты
настраиваются в админке (`19-content-admin.md`).

### 7.2 Куда делятся

Набор каналов определяется платформой и здравым смыслом — не все варианты
уместны везде.

| Платформа | Каналы |
|---|---|
| Telegram | Пересылка в чат, история (stories), inline-шеринг |
| MAX | По возможностям площадки — уточнить при портировании |
| VK | Стена, история, личное сообщение |
| Веб | Системное меню «Поделиться», копирование ссылки, скачивание картинки |

Правило: если площадка даёт нативный формат историй — используем его.
История видна широкому кругу без адресного выбора получателя, а это
единственный по-настоящему массовый канал из перечисленных.

### 7.3 Как устроена расшаренная ссылка

**Каждый шеринг порождает собственную ссылку** со своим `code` — не общую
реферальную ссылку игрока. Это даёт:

- измеримость: видно, что конвертит лучше — результат забега или карточка
  профиля, какой канал, какое оформление;
- защиту: скомпрометированную или накрученную ссылку можно погасить, не
  трогая остальные;
- контекст: по ссылке из результата забега приглашённого можно встретить
  соответствующим экраном.

При этом реферальная привязка остаётся привязкой к игроку: в строке ссылки
хранится и `ref_id`, и тип шеринга.

### 7.4 Картинка

Генерируем **на сервере**, кешируем по хэшу параметров, отдаём с CDN.

Причины: истории требуют конкретных пропорций и предсказуемого рендера;
OG-превью в мессенджерах в любом случае требует серверной картинки; на
слабых Android генерация на клиенте отнимает кадры у игрового цикла — а
производительность WebView и есть главный технический риск
(`01-tech-stack.md` §8).

Кеш обязателен: одна и та же карточка профиля запрашивается многократно, а
рендер — самая дорогая операция во всём потоке.

### 7.5 Текст

Маркетинговый текст — **данные, а не строка в коде**: варианты лежат в
конфигурации, локализуются, участвуют в A/B (`19-content-admin.md`).
Тексты пишутся под канал: то, что уместно в личном сообщении другу, плохо
работает в истории.

### 7.6 Когда предлагать

Момент важнее оформления.

- После **личного рекорда** — не после каждого забега.
- После получения редкого предмета или уровня, то есть в момент, когда есть
  чем хвастаться.
- Никогда не блокируя путь игрока: предложение поделиться, которое надо
  закрыть, чтобы продолжить, воспринимается как реклама.

Навязчивый шеринг стоит не только раздражения: площадки рассматривают
агрессивные механики распространения как повод для санкций при модерации
(`09-ci-cd.md` §4).

## 8. Что попадает в аналитику

События `link_clicked`, `redirect_served`, `hub_platform_chosen`,
`app_first_open`, `share_offered`, `share_completed`, `shared_link_opened`
(`22-analytics-and-metrics.md` §3.3).

Считаем: клики и их источники, конверсию клик → запуск → регистрация,
долю кликов без запусков, время до запуска, распределение по платформам с
хаба, принятие предложения поделиться, обратные переходы и их конверсию,
эффективность вариантов карточки и текста.
