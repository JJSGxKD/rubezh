# Прогрессия аккаунта, снаряжение, режимы и рейтинговая лига

Дополняет мета-прогрессию из `05-game-design.md` §3 (разблокировки за
забег-валюту). Здесь — то, что происходит **между** забегами на более
длинной дистанции: уровень аккаунта, снаряжение с редкостью, структура
уровней вместо только бесконечного забега, и рейтинговая лига.

**Важная оговорка сразу**: это большой пласт систем поверх и без того
плотного MVP-скоупа (`02-roadmap.md`). Ниже — полная проработка дизайна,
но по срокам всё это стоит явно вынести за пределы 6-8-недельного роадмапа
до MAX — см. итоговую сноску про фазирование.

## 1. Уровень аккаунта (XP)

- Начисляется за факт игры (за забег, за выполненное задание/условие), не
  привязан к конкретному прогону
- Даёт не игровую силу напрямую, а точки для системы снаряжения (§2) и
  косметические статусы (титул, рамка профиля) — держим тот же принцип,
  что и с скинами: видимый прогресс, но не покупаемое преимущество
- Не путать с рейтинговой лигой (§4) — это два независимых трека: уровень
  аккаунта никогда не сбрасывается, лига — сбрасывается по сезонам

> Уровень аккаунта, снаряжение и достижения — это ещё и содержимое
> **карточки профиля**, которой игрок делится в соцсетях и историях:
> оформление карточки меняется вместе с прогрессией и работает как
> виральный канал (`24-attribution-and-sharing.md` §7.1).

## 2. Снаряжение и система редкости

Обычная для жанра шкала: **обычное → редкое (синее) → эпическое
(фиолетовое) → легендарное**. Здесь есть архитектурно важный момент,
напрямую завязанный на уже принятое решение об отказе от лутбоксов
(`03-notes-and-risks.md`):

- **Редкость и дроп через RNG — это нормально, если снаряжение выдаётся
  бесплатно за игру** (награда за уровень/забег/лигу). Регуляторный риск,
  из-за которого решили не делать лутбоксы, касался конкретно **платных**
  рандомных покупок за реальные деньги — бесплатный RNG-дроп в эту
  категорию не попадает
- **Но** это разделение легко случайно стереть на следующем шаге: если
  потом добавить "купить сундук с шансом на легендарку" — это снова
  ровно тот механизм, от которого решили отказаться, просто через другую
  дверь. Явное правило для экономики: снаряжение можно получить только
  через прогресс (уровень, забег, лигу) или купить **конкретный** предмет
  за фиксированную цену (как скины) — комбинации "заплати за шанс" не
  должно быть нигде в SKU-листе, включая будущие обновления
- Снаряжение даёт статовые бонусы (не только косметику, в отличие от
  скинов) — значит, важно определить потолок влияния на баланс:
  снаряжение должно расширять билды (разные подходы к прохождению), а не
  быть банальным "+% урона", иначе игрок без снаряжения объективно слабее
  на той же сложности — это уже мягкая форма pay-to-win, даже если само
  снаряжение бесплатное, если скорость его получения можно купить за
  донат напрямую (см. следующий пункт)
- Если решим продавать "ускорители получения снаряжения" за донатную
  валюту (частая механика) — делать это тоже стоит осторожно: продавать
  ускорение **темпа**, а не гарантированный результат конкретной редкости,
  чтобы не пересекаться с тем же риском лутбоксов по сути механики

## 3. Структура уровней вместо только бесконечного забега

Два режима вместо одного:

- **Кампания**: последовательность уровней с фиксированным составом волн,
  каждый следующий сложнее и вводит новых врагов — разблокируется по
  порядку (прошёл N → открылся N+1). Даёт предсказуемую кривую обучения и
  natural place для ввода нового контента (враг привязан к конкретному
  уровню, а не появляется без объяснения)
- **Бесконечный режим**: тот же core loop, но без фиксированного конца —
  волны продолжают эскалировать по формуле (уже заложенной в
  `05-game-design.md` §4) до тех пор, пока игрок не погибнет. Это отдельная
  точка входа, не "финал кампании перетекает в бесконечность" — иначе
  сложно однозначно считать результат для лидерборда (кампания меряется
  прохождением, бесконечный режим — очками/временем/волной)
- Открытый вопрос для проработки на этапе 2 (см. `02-roadmap.md`): делить
  ли лидерборд на "лучший результат в бесконечном режиме" и "быстрейшее
  прохождение кампании" как две отдельные метрики, или на MVP оставить
  только одну — начинать проще с одной метрики (бесконечный режим,
  проще для сравнения между игроками), кампанию вводить отдельным
  обновлением

## 4. Рейтинговая лига ("ладдер")

Отдельная прогрессия **вне** одного забега и даже вне уровня аккаунта —
соревновательный трек:

- Новый игрок стартует с нижнего дивизиона (условно "дерево"), поднимается
  по дивизионам по мере набора лиговых очков
- **Лиговые очки начисляются по результату забега** (лучший результат за
  забег в бесконечном режиме, либо прогресс по кампании — см. §3, финальное
  решение зависит от того, какую метрику оставляем основной)
- **У каждого дивизиона — свой отдельный лидерборд** (не общий список на
  всех) — это прямое продолжение идеи из `03-notes-and-risks.md` про то,
  что "обгони конкретного" мотивирует больше, чем абстрактный топ-100:
  соревнование с игроками своего уровня, а не с топ-1% с первого дня
- **Переход между дивизионами**: набор очков сверх порога → повышение.
  Не привязывать к "прохождению уровней кампании" напрямую (кампания
  конечна, а лига должна работать и для тех, кто в основном играет в
  бесконечный режим) — привязать к очкам, которые начисляются из любого
  режима одинаково
- **Сезонность**: лига имеет смысл только с сезонным сбросом (иначе топ
  дивизион зацементируется первыми активными игроками навсегда, и всем
  новым будет бессмысленно карабкаться) — сезон длиной 4-6 недель как
  рабочая гипотеза, награда за финальный дивизион сезона — косметика
  (скин/титул), не игровая сила
- Кросс-платформенность лиги — та же модель данных, что и в
  `08-web-and-identity.md` §5: один Redis ZSET на дивизион, с полем
  `platform` для бейджа, без связывания аккаунтов между площадками

## 5. Как это соотносится с MVP-роадмапом

Ничего из этого файла не входит в 6-8-недельный план до публичного лонча
на MAX (`02-roadmap.md`) — там сознательно минимальный core loop
(один режим забега + простая мета-валюта + один общий лидерборд), и это
осознанное решение, а не недосмотр. Рекомендация: держать этот документ
как дизайн для "Фазы 2" (после этапов 6–7, параллельно с портом на
Telegram/VK или сразу за ним) — вводить по одной системе за раз
(например: сначала уровень аккаунта → потом дивизионы → потом снаряжение
с редкостью), проверяя retention-эффект каждой перед следующей, а не
выкатывать всё разом. Выкатить все пять систем одновременно без данных о
том, какая из них реально держит игроков, — способ потратить много времени
разработки без понимания, что из этого сработало.
