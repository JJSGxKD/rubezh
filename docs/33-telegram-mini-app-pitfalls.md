# Типовые ошибки Telegram Mini App и как мы их избегаем

Свод граблей, на которые наступают при разработке Mini App, и сверка с тем,
что уже сделано у нас. Источник — разбор AdsGram
([«Ошибки разработки Telegram Mini App и как их избежать»](https://adsgram.ai/ru/blog/adsgram/telegram-mini-app-tma-development-mistakes-and-how-to-avoid-them));
здесь пересказ, привязанный к нашей архитектуре, а не копия.

Как читать: у каждого пункта — **суть ошибки**, **правило** и **у нас** —
где это уже закрыто или что осталось сделать. Пункт «у нас» обязан
обновляться вместе с кодом: устаревшая отметка «сделано» хуже её отсутствия.

Смежные документы: fullscreen, отступы и возможности клиента —
`27-design-system-and-app-shell.md` §5; атрибуция и параметр запуска —
`24-attribution-and-sharing.md`; реклама — `07-monetization-and-ads.md`;
перенос рекламного модуля — `13-reuse-from-vpnsibcom.md` §3.

## 1. Безопасность и `initData`

### 1.1 Доверие `initDataUnsafe`

**Суть.** `initDataUnsafe` — это разобранная на клиенте строка без проверки
подписи. Подменить в ней `user.id` может кто угодно.

**Правило.** На сервер уходит сырая строка `initData`, сервер проверяет
подпись: data-check-string из всех пар кроме `hash`, отсортированных по
ключу и склеенных `\n`; секрет — HMAC-SHA256 от токена бота с ключом
`"WebAppData"`; подпись — HMAC-SHA256 от data-check-string с этим секретом;
сравнение с `hash` —
за постоянное время. Токен бота на клиент не попадает никогда.

Есть и второй способ — подпись Ed25519 публичным ключом Telegram (не нужен
токен бота, удобно для сторонних сервисов). Подпись там в base64url без
выравнивания: в части языков `=` приходится дописывать вручную.

**У нас.** Сделано: `backend/api/src/modules/telegram/telegram-init-data.ts`
(HMAC, `timingSafeEqual`). Клиент идентификатор игрока из `initDataUnsafe`
как источник истины не использует.

### 1.2 Свежесть `auth_date`

**Суть.** Своего срока жизни у `initData` нет: строка, утёкшая в лог, отчёт
об ошибке или историю, работает сколько угодно.

**Правило.** Отклонять `initData` старше окна: обычно 24 часа, для операций с
деньгами и валютой — около часа. После проверки выдавать свой сессионный
токен и дальше авторизовать по нему, а не по `initData` на каждом запросе.

**У нас.** Окно проверяется (`maxAgeSec`, плюс отказ при дате из будущего
больше чем на 5 минут). Окно приёмников событий и отчётов —
`INGEST_INIT_DATA_MAX_AGE_SEC`, по умолчанию сутки (`20-env-and-ports.md`):
там подпись ничего не выдаёт в ответ. **Сделано на этапе 3:** вход в сессию —
отдельное окно `AUTH_INIT_DATA_MAX_AGE_SEC`, и потолок в час зашит в схему
конфигурации, а не в договорённость: процесс с большим значением не
стартует. Дальше игрок ходит по своему токену, а не по подписи запуска
(`34-stage3-plan.md`, Р2): забеги, рейтинг и плейтест — тоже, плейтестовой
проверки подписи на каждом запросе больше нет (WP4).

### 1.3 Сессия в `localStorage`

**Суть.** WebView Telegram чистит `localStorage` непредсказуемо — на iOS и
части десктопных сборок данные не переживают перезапуск. Ошибки при этом
нет: приложение просто открывается как для нового игрока.

**Правило.** Что где хранить:

| Хранилище | Где лежит | Для чего | Ограничения |
|---|---|---|---|
| `localStorage` | WebView | Временное состояние интерфейса | Может пропасть на iOS и десктопе |
| `CloudStorage` (Bot API 6.9) | Облако Telegram | Настройки, общие для устройств игрока | 1024 ключа на пользователя, ключ 1–128 символов, значение до 4096 |
| `DeviceStorage` (9.0) | Устройство | Локальный кэш, предпочтения | Не синхронизируется |
| `SecureStorage` (9.0) | Защищённая область устройства | Чувствительные локальные значения | Не синхронизируется, зависит от версии клиента |
| Наш бэкенд | Сервер | Сессии, балансы, права | Только после проверенного `initData` |

Права доступа и балансы — **только на сервере**.

**У нас.** Локальное хранилище спрятано за `KeyValueStorage` в адаптере
(`packages/adapter-telegram/src/storage.ts`) именно ради переезда на
`DeviceStorage` без правок выше. Сейчас там лежат только настройки и
локальные рекорды — потеря неприятна, но не ломает ни деньги, ни доступ.
**Открыто:** решение о переезде на `DeviceStorage` / `CloudStorage` — по
итогам закрытого теста на iOS (`27-design-system-and-app-shell.md` §7).

### 1.4 Вызовы API Mini App с чужого домена

**Суть.** С Bot API 10.2 (14 июля 2026) методы Mini App работают только со
своего домена приложения. Страница на другом домене, iframe, партнёрский
лендинг внутри приложения теряют `Telegram.WebApp`. Коварство в том, что
приложение при этом не падает, а на старых клиентах всё работает — тест на
старой сборке проблему не покажет.

**Правило.** Всё, что зовёт API Telegram, живёт на зарегистрированном домене
приложения; обмен со сторонними сервисами — через наш бэкенд. Проверять на
актуальной сборке клиента.

**Встраивание и политика источников.** Telegram Web открывает Mini App
**во фрейме** — в отличие от мобильных и десктопных клиентов. Поэтому
«закрыть встраивание всем» (`frame-ancestors 'none'`, `X-Frame-Options: DENY`)
ломает игру именно там, где её реже всего тестируют: на телефоне фрейма нет,
и проверка проходит. Встраивание разрешается ровно `https://web.telegram.org`.

**У нас.** Оболочка и забег — один origin. Политика источников клиента пускает
во фрейм только Telegram Web (`scripts/vite/content-security-policy.ts`,
`34-stage3-plan.md`, WP3). Редирект-страница и хаб
(`24-attribution-and-sharing.md` §3–4) работают **до** открытия Mini App и
API Telegram не вызывают — под ограничение не попадают. Встраивать чужие
страницы в iframe с вызовами API нельзя.

## 2. Вёрстка и viewport

### 2.1 `100vh` вместо высоты от Telegram

**Суть.** На мобильных Mini App открывается шторкой, а `100vh` считается от
окна браузера: низ интерфейса уезжает под панели Telegram.

**Правило.** `expand()` на старте. `viewportHeight` меняется непрерывно (шторку
тянут, клавиатура выезжает), `viewportStableHeight` — только в конце
движения: к нему привязывают всё, что не должно прыгать, и перерисовывают
раскладку по стабильному значению.

**У нас.** Сделано: адаптер отдаёт наружу высоту из `stableHeight`
(`packages/adapter-telegram/src/ui-telegram.ts`), раскладка оболочки
опирается на неё, а не на `vh`. Бот закрытого теста стартует в fullscreen, а
в компактном окне оболочка показывает плашку «разверните» с вызовом
`expand` (`27-design-system-and-app-shell.md` §5.2.0).

### 2.2 Безопасная зона — только половина

**Суть.** С Bot API 8.0 отступов два набора: `safeAreaInset` — системные
(вырез камеры, полоса «домой»), `contentSafeAreaInset` — занятое интерфейсом
Telegram. Учли один — закрыли половину проблемы. В fullscreen Telegram
перестаёт резервировать место под себя, и всё неучтённое оказывается под его
кнопками.

**У нас.** Сделано: оба набора складываются в `--app-inset-*`
(`27-design-system-and-app-shell.md` §5.1); отступы от выреза и кнопок
задаются только через них (правило из `CLAUDE.md`).

### 2.3 Вертикальные свайпы в игре

**Суть.** Вертикальный свайп сворачивает или закрывает Mini App. Если в
приложении свои жесты — джойстик, перетаскивание, — клиент перехватит жест
и закроет приложение посреди действия. Игрок видит это как вылет.

**Правило.** `disableVerticalSwipes()` (7.7) на экранах со своими жестами,
обратно включать на обычных прокручиваемых. Где можно потерять прогресс —
`enableClosingConfirmation()` (6.2).

**У нас.** Сделано: на время забега и стресс-теста свайпы выключены, а
подтверждение закрытия включено (`packages/app-shell/src/state/run.ts`,
`state/stress.ts`); в меню — наоборот.

### 2.4 Своя кнопка «Назад»

**Суть.** У Telegram есть системная «Назад» в шапке, на Android — ещё и
аппаратная. Своя кнопка в интерфейсе — третий элемент, и стеки у них разные:
системная живёт историей браузера, своя — логикой приложения. На ветвистых
сценариях они расходятся.

**Правило.** `BackButton` (6.1), привязанный к роутеру; видимость меняется
вместе с маршрутом; один стек навигации на всех.

**У нас.** Сделано: `BackButton` связан со стеком экранов, в корне скрыт
(`27-design-system-and-app-shell.md` §5.2, §7), а во время забега ставит
паузу (`packages/app-shell/src/app/App.tsx`). Своя кнопка «Назад» в верхней
панели — только вне Telegram (браузерная сборка адаптера).

## 3. Производительность

| Ошибка | Правило | У нас |
|---|---|---|
| Тяжёлый первый бандл | Делить код по маршрутам, всё, что не нужно первому экрану, — отложенно. Важен объём начальной загрузки, а не синтетика: основная аудитория — средние Android, пара секунд ожидания воспринимается как зависание | Phaser — отдельным чанком через `loadRunEngine()`, бюджет бандла в гейте (`pnpm budget`, `27-…` §3.4) |
| Расчёт на SSR | API Telegram есть только в `window`; всё, что от него зависит, — в клиентском коде, до готовности SDK — скелетон | SSR не используем: оболочка — клиентское SPA на Vite |
| Тяжёлые анимации | В WebView на слабом железе анимировать только `transform` и `opacity`, лишние эффекты выключать при просадке | Правило оболочки (`27-…` §3.3, §4.5) и переключатели эффектов в настройках (§7.1) |
| Белый экран при загрузке | Экран загрузки или скелетон вместо пустого фона — меньше уходов в первые секунды | Экран загрузки оболочки (`27-…` §3.4) |

## 4. Версии клиента и платформы

**Суть.** Метод, которого нет в клиенте игрока, либо молча ничего не делает,
либо бросает ошибку. Код правильный, а функция у части игроков не работает.

**Правило.** Зафиксировать минимальную поддерживаемую версию Bot API, а всё,
что выше неё, проверять перед вызовом (`isVersionAtLeast()`, 6.1) и иметь
запасной вариант:

| Возможность | Метод | Bot API | Запасной вариант |
|---|---|---|---|
| Назад | `BackButton` | 6.1 | Кнопка в своей шапке |
| Подтверждение закрытия | `enableClosingConfirmation()` | 6.2 | Автосохранение |
| Облачные настройки | `CloudStorage` | 6.9 | Настройки на сервере |
| Свайпы | `disableVerticalSwipes()` | 7.7 | Ограничить зоны перетаскивания |
| Полный экран | `requestFullscreen()` | 8.0 | Развёрнутый режим |
| Безопасная зона | `safeAreaInset`, `contentSafeAreaInset` | 8.0 | Фиксированные отступы |
| Хранилища устройства | `DeviceStorage`, `SecureStorage` | 9.0 | Сессия на сервере |
| Выбор чата | `requestChat()` | 9.6 | Обычная ссылка для шеринга |

**Тестирование.** Веб-клиент Telegram прячет большую часть проблем.
Релиз-кандидат проверяется на iOS (Safari Web Inspector), на Android (Chrome
DevTools по USB) и хотя бы на одном десктопном клиенте. Для ошибок, которые
воспроизводятся только у тестера, — встроенная консоль вроде Eruda.

**У нас.** Проверка поддержки — через `@tma.js/sdk`: вызовы идут через
`isAvailable()` / `ifAvailable()` в адаптере, а не напрямую; запасные
варианты — `27-…` §5.2. Матрица устройств — `27-…` §5.4. Вместо Eruda —
свой режим диагностики с отчётом на сервер (`28-diagnostics.md`).
**Сделано:** минимальная версия Bot API — **7.7**, проверяется при старте, ниже
неё игрок видит экран «обновите Telegram» (`27-…` §5.2,
`34-stage3-plan.md`, Р11). Граница проведена по `disableVerticalSwipes`: без
неё свайп закрывает приложение посреди забега.

## 5. `startapp` и диплинки

### 5.1 Несколько параметров в диплинке

**Суть.** В Mini App приходит ровно один параметр запуска — `startapp`.
Схемы с несколькими параметрами потом приходится переделывать.

**Правило.** Упаковать значения в одну строку со своим разделителем
(например, `ref__campaign__level`) и разбирать её.

**У нас.** В `startapp` уходит один `click_id`, всё остальное — реферер,
кампания, партнёр — лежит на сервере в строке клика
(`24-attribution-and-sharing.md` §1, §5). Так и лимит длины параметра не
мешает, и подделать состав нельзя.

### 5.2 Бонус по содержимому `startapp`

**Суть.** `startapp` пишет в ссылку кто угодно, в том числе чужой
реферальный ID. Начисление по нему напрямую — реферальный фрод.

**Правило.** Параметр читается на сервере из **проверенного** `initData`
(`start_param`) и сверяется с данными игрока. Для доступа и валюты параметрам
диплинка не доверять.

**У нас.** По схеме `24-…` §5–6 и `23-referral-and-partner-program.md`:
сервер находит клик по `click_id`, проверяет срок жизни и антифрод-сигналы,
награда — только после условий программы. При реализации — брать
`start_param` из проверенного `initData`, а не из тела запроса.

## 6. Реклама (на примере AdsGram)

Rewarded-реклама в Telegram у нас планируется (`07-monetization-and-ads.md`,
`02-roadmap.md`), провайдеры — AdsGram, Taddy, RichAds. Правила ниже общие для
любой сети; конкретика — по SDK AdsGram.

| Ошибка | Правило |
|---|---|
| Реклама на первом экране | Показ прерывает сессию до того, как игрок получил результат, и растит уходы трафика, за который уже заплатили. Показы — на границах действия: конец забега, выполненное задание, выдача награды. Rewarded — за то, что игрок уже понимает и хочет: вторая жизнь, ускорение, бонус |
| `debug: true` в проде | Реклама крутится, но показы не считаются, reward-колбэки не приходят, выплат нет. `debug` — из конфигурации окружения, в проде `false`; проверяется в гейте релиза |
| `init()` на каждый показ | `window.Adsgram.init({ blockId })` вызывается один раз на блок и возвращает `AdController`, дальше — только `show()` |
| Не обработан отказ `show()` | Промис отклоняется при неудачной загрузке и при раннем закрытии. Без обработки — либо награда без просмотра, либо интерфейс, навсегда застрявший в «загрузке». Отказ обрабатывается явно, ожидание — с таймаутом; события SDK: `onStart`, `onSkip`, `onReward`, `onComplete`, `onError`, `onBannerNotFound`, `onNonStopShow`, `onTooLongSession`. `onBannerNotFound` — обычно низкий филл для гео или блока, а не поломка интеграции. У награды должен быть путь и без рекламы |
| Награда начисляется клиентом | Запрос повторяется без показа — та же дыра, что доверие `initDataUnsafe`. Начисляет бэкенд, по проверенной сессии. У AdsGram есть серверный reward URL (доступен от ~50 000 DAU): GET на HTTPS-порт 443 с плейсхолдером `[userId]`; в `debug` не отправляется — проверять на боевом блоке |
| Блок вне видимости | Показ засчитывается после 2 секунд непрерывной видимости не меньше 50% блока. Блок за экраном, в свёрнутом контейнере или нулевой высоты «показан», но не засчитан. Не перекрывать блоки, не звать `show()` в свёрнутом приложении (у нас — `isActive`, `27-…` §5.2) |
| Один блок на всё | До 10 блоков на приложение: отдельный блок на каждое место (конец забега, второй шанс, ежедневный бонус, задания) — иначе не сравнить, какое размещение работает |

**Модерация и выплаты AdsGram** (справочно, условия площадки могут
меняться). Модерация — 4–6 часов в будни, 6–10 в выходные. Отказы обычно из-за
незавершённости: приложение закрыто авторизацией или белым списком (проверяющий
видит ошибку вместо игры), не работает на одной из платформ (клавиатура на
iOS, раскладка на десктопе). Выплаты — USDT в TON по умолчанию, также USDT
TRC20 и фиат; минимум к выводу — $100; обработка до суток в будни и до двух
в выходные.

**Для нас это значит:**

- в режиме закрытого теста (`26-stage2-plan.md`) доступ ограничен — на
  модерацию рекламной сети нужна сборка, открытая проверяющему;
- рекламная воронка (запрос → показ → просмотр → награда, отказы по причинам)
  — события по словарю `22-analytics-and-metrics.md` **до** подключения сети:
  иначе низкий филл не отличить от сломанного размещения;
- награда за рекламу — через бэкенд и идемпотентно, как и прочие начисления
  (`15-engineering-standards.md`); при переносе модуля `ads` из
  `vpnsibcom_api` — по правилам `13-reuse-from-vpnsibcom.md`.

## 7. Симптом → причина

| Симптом | Вероятная причина | Что смотреть |
|---|---|---|
| Пусто или «новый игрок» только на iOS | Очищен `localStorage`, сессия потеряна | Сессия на бэкенде, порядок инициализации |
| `Unable to retrieve launch parameters` | Открыто вне Telegram | Проверка окружения, мок для локальной разработки (у нас — браузерная сборка адаптера) |
| Кнопку перекрыл вырез или шапка | Не учтены отступы | `safeAreaInset` + `contentSafeAreaInset` → `--app-inset-*` |
| Раскладка прыгает при клавиатуре | Раскладка от `viewportHeight` | `viewportStableHeight` |
| Приложение закрывается при перетаскивании | Вертикальные свайпы включены | `disableVerticalSwipes()` |
| Метод не работает у части игроков | Старый клиент | Проверка версии и запасной вариант |
| Вызовы API перестали проходить | Вызов не со своего origin | Ограничение Bot API 10.2 |
| Реклама крутится, статистики нет | `debug` в проде | `debug: false` |
